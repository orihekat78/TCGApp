# デッキ編集画面刷新 設計仕様

## 目的

- デッキ内容を主役にし、右のカード一覧から迷わず編集できる作業画面にする。
- カード確認とカード追加を分離し、誤追加を防ぐ。
- HOME・SETUP・CARDSと同じヘッダー、密度、状態表現を使う。
- 保存、取消、検証、同一カードID上限、デッキコードの動作は変えない。

## 情報構造

- 上段: 共通 `PrimaryHeader`。
- 操作列: デッキ名、デッキ切替、新規、複製、削除、コード、テスト、未保存、取消、保存。
- 主作業面: 左から中央までをデッキ、右端をカード一覧にする。
- デッキ面: パートナー・事件、40枚カウント、コスト分布、カードグリッド、検証結果。
- カード一覧: 検索、フィルタ、並び順、カードグリッドを独立スクロールにする。
- カード詳細は常設しない。選択時だけ左端からドロワーとして開く。

## 操作契約

- カード一覧またはデッキ内カードのクリック / Enter / Space: 詳細を開く。枚数は変えない。
- カード一覧からデッキ面へドロップ: 既存 `addCard` で1枚追加する。
- 詳細の「1枚追加」「1枚除く」: ドラッグ操作のキーボード・タッチ代替。
- 同一ID上限、無制限カード、無効種別は既存 `addCard` だけで判定し、別実装を作らない。
- 追加成功、上限拒否、削除結果を `aria-live` で通知する。
- デッキ内カードの削除は、詳細のボタンと常時見える44px操作で可能にする。hover専用操作にしない。
- 右クリック拡大は既存互換として維持する。

## 詳細ドロワー

- 画像、印刷番号、共通ID、名前、種別、色、レアリティ、種別ごとの能力値、効果、キーワード、採用数を表示する。
- パートナーはC/AP、事件はC/AP/LP、イベントはAP/LPを表示しない。事件は先攻/後攻を表示する。
- `role="dialog"`、`aria-modal="true"`、明示的な閉じるボタン、Escape、backdrop、Tab trapを持つ。
- 閉じたら起点カードへフォーカスを戻す。
- ドロワーはデッキ面のみを覆い、カード一覧は見える状態を維持する。

## レスポンシブ

- 1440×900: header 72px、操作列約52px、デッキ約70%、カード一覧約30%。詳細幅320px。
- 851×393: header 42px、操作列44px、デッキ589px、カード一覧240pxを目安に維持。詳細幅280px。
- 横長コンパクトでも縦積みにしない。外側の横スクロール、重なり、切れをゼロにする。
- 検索、フィルタ、保存、閉じる、追加、削除は44px以上。カード画像と補助文字だけ縮小できる。
- デッキ面とカード一覧は各自で縦スクロールする。

## 視覚方針

- 深いnavy、cyanの状態色、細い境界、白い主要文字を既存Visual Foundationから継承する。
- 新しい粒子、装飾グロー、パターン背景、入れ子パネルを追加しない。
- signatureはドラッグ中の移動経路とドロップ面の状態変化。通常時は静かにする。
- `prefers-reduced-motion` ではドロワー移動を即時にし、情報は欠落させない。

## 非対象

- デッキ構築ルール、カードデータ、永続スキーマ、対戦エンジンは変更しない。
- 手動カード並べ替え、縦画面モバイル、カード固有演出は追加しない。
