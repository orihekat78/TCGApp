## engine gap（実在部分の確認、resolve-picks.ts / picks.ts 直読）
`atomDeckRevealUntil`(src/engine/effect/atom-handlers/picks.ts:9-93) は **filter の {dyn} を
handler 冒頭で dispatch-time 解決している**（L11-19, resolveFilterDynObj 呼出）。
**しかし `maxN`（=「指定名キャラ1枚につき」の枚数）には同種の処理が一切無い** — L93
`const maxN = a.maxN as number | undefined;` は生の型キャストのみ。
本カードのチェーンは `declareName{...}` → `deckRevealUntil{maxN:{dyn:'$declared.named.sceneNameCount'}}`
の形になるが、resolve-picks.ts の top-level `resolveDynArgs`（L74-95、chain 実行前の pre-walk）が
declareName 実行**前**に `{dyn}` を literal 化してしまい 0/NaN に固まる。仮に pre-walk 側が
修正されても、`atomDeckRevealUntil` 自体が `a.maxN` を dispatch 時に再解決する処理を持たない
限り依然として誤動作する。

## DSL 案
`atomDeckRevealUntil` L93 に、既存の filter 解決（L11-19）と同型の dispatch-time dyn 解決を追加：
`const maxN = resolveNumDyn(s, a.maxN, ctx);`（resolveFilterDynObj と対の新ヘルパー、
または resolveFilterDynObj を汎用化）。カード側 DSL:
`chain[declareName{...}, deckRevealUntil{maxN:{dyn:'$declared.named.sceneNameCount'}, bind:'seen', chooseMatch:'upTo', filter:{cardName:{dyn:'$declared.named'}}}]`。

## tier + 理由
T2。既存関数内の1箇所への additive 修正（filter で確立済みのパターンをmaxNにも適用するだけ）。
GameState 形状変更なし、既存消費者への影響なし（{dyn} 不在時は同一参照 no-op の既存規約踏襲）。
