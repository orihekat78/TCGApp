# B06042 ここで会うたが百年目 (イベント) grounding (2026-07-10, sonnet5)
> 状態: DEFER (T2)

## 印字 (要約)
自分の現場のキャラを1枚まで選び、ターン終了時までAP+1000し、「【宣言】【ターン1】相手の現場の
キャラを1枚まで選び、このキャラとのコンタクトを発生させる（このキャラがアクションした側）」を
与える。【ヒラメキ】カードを1枚引く。

## engine gap（実在、3点とも直読で確認）
1. **type 強制**: `atomCharGrantAbility`(atom-handlers/char.ts:163-189) は付与先 ability def の
   `type` を無条件 `'triggered'` に固定（L189）。本カードは `type:'declared'` を付与する必要が
   あるが、spec の type 指定は反映されない。
2. **findDeclaredAbility が未走査**: `findDeclaredAbility`(flow/main/declared-ability.ts:100-123) は
   `canDeclaredAbility`/`useDeclaredAbility`/`activateDeclaredAbility`/UI 列挙の**唯一共有 helper**
   （関数コメントで明記）。printed abilities と on-set-host faceUp rider のみ走査し、
   `turnEffects.grantedAbilities` を一切見ない。gap 1 を直しても付与された declared 能力は
   使用フローから発見不能。
3. **grantedId 衝突**: `grantedId = 'granted:${cardId}:${abilityId}'`（L183-185、付与元カードの
   cardId/abilityId のみで決定）。TSV 内公式Q&A「このイベントを2回使用して同じキャラを選んだ場合、
   それぞれターン中に1回、合わせて2回まで使用できる」を満たすには、同一ターゲットへの複数回付与が
   **独立した【ターン1】カウンタ**を持つ必要があるが、同一発生源からの付与は grantedId が
   衝突し1カウンタを共有してしまう。

## DSL 案（新規 primitive 不要、既存共有関数への3点 touch-up）
(1) `atomCharGrantAbility` で `type: (spec.type as string) ?? 'triggered'` に変更。
(2) `findDeclaredAbility` に `state.players[p].turnEffects.grantedAbilities` を uid+abilId で
    走査する第3経路を追加。
(3) grantedId に発生インスタンス識別子（例 `ax.id` または呼出ごとの連番）を混ぜて衝突回避。

## tier + 理由
T2。既存共有関数3箇所への additive 修正、GameState 形状変更なし。ただし
findDeclaredAbility は複数呼出点が依存する共有 helper のため、修正時は
canDeclaredAbility/useDeclaredAbility/UI 全経路の sync テストが要（2 lens 相当）。

## 罠

  gap の実在は2枚で相互裏付け**されている。B06042 単独の artifact ではない — 修正時は
  B07001 も同時解禁対象として横展開調査すること。

  3点セットでの一括修正が必須（部分修正は無意味）。
