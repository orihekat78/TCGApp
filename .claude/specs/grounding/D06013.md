## engine gap (2点セット必須 — 片方だけでは不可)

unstable-if conditional (if に '$revealed' を含む = conditionIfIsStable が default 分岐で unstable
判定) は pre-walk (resolve-picks.ts L710-716 付近) で then/else **両枝を無条件 walk** する
(BUG-161 で意図的維持)。then 内が **Pattern-A pick** (`uid:'$pick'` + target、sceneSetState stun の
D03004 idiom) だと `substituteAtomPick` が flag 無視で即 push → 色条件不成立でも human に
「スタン対象を選べ」modal が誤表示 (盤面は resolver 実行時 evalCond で守られる = UI 専害)。

- 修正① resolve-picks conditional case: unstable-if かつ枝に Pattern-A pick を含む場合、
  Pattern-B 同様に pre-walk push を抑止。
- 修正② atomSceneSetState (or runAtom 共通 preamble) に `uid==='$pick'` + target が pick-query の
  自己解決 fallback (tryRePickFromAtom) を追加 — sceneEnter `cardId:'$pick.cardId'` と対称化。
  ①のみ = silent-drop / ②のみ = over-fire のまま。
- shipped 全走査: 「bound-if + then/else 内 kind:'pick'」16 件は全て bound 値直代入 atom で
  Pattern-A pick は 0 件 = 未踏経路確定。
- 代替案却下: top-level chain 化 → over-fire が silent-drop に変わるだけ / PA 短縮形 →
  a.state が「新状態(string)」と「候補filter(array)」を兼務できず表現不能。

  deckRevealUntil{player:'self', maxN:4, bind:'$revealed'},           // bind-only (filter/bindMatch 省略)
