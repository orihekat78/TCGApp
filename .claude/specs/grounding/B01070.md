# B01070 アンドレ・キャメル grounding (2026-07-10, sonnet5)
> 状態: DEFER (T2 候補、SMALL_GAP)

## engine gap
- a1「相手の現場にいるキャラがこのキャラを指定してアクションしたとき、そのコンタクト中、この
  キャラをAP＋1000する。」= trigger `{hook:'action:declare'}` で targetUid を判定する必要が
  あるが、現行 `triggerCharMatches` (src/engine/cond/eval.ts:593) は payloadKey 指定時
  side/filter でしか絞れず、「targetUid === 自分自身の uid」を直接照合する field が無い
  (`excludeSource` はあるが逆方向の除外用)。side:'opp'+filter:{cardId} では同名カードが
  複数現場にいる場合に over-fire する。
- action:declare payload には既に `targetUid` が同梱済 (state-machine.ts:199、B08048 で
  実証済 exemplar あり)。`scope:'contact'` の charModifyAP も D11007 a3 / B01028 a2 で
  既出荷 (precedent 有)。
- Q&A「このキャラが指定されたアクションをガードしたとき」でもAP+1000 は適用済という記載から、
  トリガは action:guarded ではなく action:declare (宣言時点) で確定させる必要がある
  (rules/22 のガード判定前確定パターンと整合)。

## DSL 案
- a1: `trigger:{hook:'action:declare', matcherCondition:{kind:'triggerCharMatches',
  payloadKey:'targetUid', **selfUid:true (要追加 field)**}}` →
  `effect:{kind:'atom', verb:'charModifyAP', args:{uid:'$self', delta:1000, scope:'contact'}}`
- a2 (宣言): 既存 primitive で表現可 — cost `[{kind:'sleepSelf'}]` +
  effect `charGrantKeyword{uid:'$picked', kw:'ブレット', scope:'turn'}` (対象1枚まで pick)
- a3 (ヒラメキ): `draw{player:'self', n:1}` (既存 exemplar 多数)

## tier + 理由
- T2 (既存 Condition kind `triggerCharMatches` への additive field 1個。新 hook/新 verb 不要)

## 罠
- 「アクション宣言時点で発火」であって「コンタクト参加時」ではない点に注意。action:guarded
  ではなく action:declare を使うこと (ガードされて実際にはコンタクト不参加でも AP+1000 は
  適用済という Q&A の literal な扱いを反映する)。
