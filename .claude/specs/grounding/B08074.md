# B08074 降谷零 grounding (2026-07-10, sonnet5)
> 状態: DEFER (T3)

## 印字 (要約)
【登場時】〚特徴〛を1つ指定し、〚捜査3〛する。指定した特徴のカードが発見された枚数につき、
ターン終了時までこのキャラは以下を持つ：【1枚以上】〚突撃[キャラ]〛/【2枚以上】〚突撃〛/
【3枚以上】〚迅速〛。

## engine gap（実在、確認済み）
1. **trait-declare 機構が無い。** `$declared.*` 名前空間（src/engine/dyn/eval.ts:566-582）は
   `declareName` verb が書き込む **カード名の宣言のみ**（ctx.declaredNames）。特徴を宣言する
   verb (`declareTrait` 相当) / `ctx.declaredTraits` は grep で 0 件。
2. **動的宣言値によるフィルタ済み集合の枚数カウンタが無い。** 既存の枚数系 primitive は
   `boundCountCompare`（bound 配列の生長さを固定 n と比較、src/engine/cond/eval.ts:228-236）と
   `boundAnyMatchesFilter`（bool、any-match のみ）の2つのみ。「捜査3で発見した中で、宣言した
   特徴に一致する枚数」を段階的閾値（1+/2+/3+）で判定する **フィルタ済み部分集合の count** は
   どちらでも表現不可。

## DSL 案（新規 primitive 2点、設計として同系統）
- `declareTrait{trait:'$pick'}` — declareName の trait 版。ctx.declaredTraits[key]=trait を書く。
- 新 cond kind `boundFilterCountCompare{bindKey, filter:{trait:{dyn:'$declared.traitKey'}}, cmp, n}` —
  resolveFilterDynObj が既に確立している「filter 内 {dyn} を dispatch 時解決」機構を条件評価側にも
  移植。
- カード側: `chain[declareTrait, deckRevealUntil{n:3,bind:'revealed'}, conditional{if:boundFilterCountCompare{bindKey:'revealed',filter:{trait:{dyn:'$declared.traitKey'}},cmp:'ge',n:1},...}]` を1+/2+/3+の3段。

## tier + 理由
T3。2 primitive は独立した新規機構（宣言種別の拡張 + 動的フィルタ count 評価）で、複数消費者を
見越した設計判断が要る。DEFER note にある「新規 row として起票」を支持。

## 罠
- DEFER note の「backlog の soleUnlock=2 は誤り（実質1）」は正しい — 2つの gap に見えるが
  根は同一パターン（宣言値を dynamic filter param として使う）で、実装は1回の設計でまとめて
  出荷できる。2件の独立 primitive として過剰見積りしないこと。
