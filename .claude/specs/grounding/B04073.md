# B04073 千葉和伸 grounding (2026-07-10, sonnet5)
> 状態: SMALL_GAP

## 印字
自分の現場にいるキャラがガードしたとき、アクション終了時までそのキャラをAP＋1000する。
アクションで指定されていたのが〚カード名［三池苗子］〛だった場合、代わりにアクション終了時
までそのキャラをAP＋3000する。
【ヒラメキ】（証拠からリムーブされるときに発動する）キャラを1枚まで選び、スリープさせる。
公式Q&A: 「自分の現場にいるキャラがガードしたとき」の能力は、相手がガードを宣言しガードする
キャラをスリープさせた時点で発動 (【カットイン】等の行動よりも前)。

## engine gap (現行 code で再検証、DEFER 行は非stale)
- `action:guarded` emit (src/engine/flow/action/state-machine.ts:293-300, `tryGuard`) は
  `{ byUid: ax.byUid, guardUid }` のみ — 元のアクション対象 (`ax.target`) を積まない。
- 対照的に同ファイルの `passGuard` (line 312-330, `action:unguarded`) は
  `{ byUid: ax.byUid, target: ax.target }` と **既に target を同梱している** — 非対称。
  B04073 の第2文はまさにこの非対称のせいで書けない (「指定されていたのが三池苗子だったか」を
  guarded 側で読む手段が無い)。
- `triggerCharMatches{payloadKey:...}` 機構 (cond/eval.ts:593-620) は既に汎用: payload の任意
  フィールド (uid 文字列) を読み、実際の scene char を lookup して filter (cardName 等) 評価する。
  B08048 a1 が `triggerCharMatches{payloadKey:'targetUid', filter:{levelMax:6}}` で
  **`action:declare` payload.targetUid** を同じ形で読んでいる (shipped exemplar)。
  → `action:guarded` に targetUid さえ乗れば condition 側は無改修で流用可能。

## 必要 primitive (見積)
`tryGuard` の emit に1フィールド追加するだけ:
```ts
event.emit(state, 'action:guarded',
  { byUid: ax.byUid, guardUid, targetUid: ax.target.kind === 'char' ? ax.target.uid : undefined },
  { player: ax.byPlayer, uid: ax.byUid });
```
state-machine.ts 単一ファイル、1-2 行。追加時点の既存 `action:guarded` 消費カードには
additive/非破壊。現在はB09041とD11016/B06091が`targetUid`を利用する。

## tier + 理由
T2 (emit payload へのフィールド追加 = 1 emit site のみ、消費側は既存 `triggerCharMatches`
condition kind を無改修流用、新規 condition kind 不要)。2 lens (semantic + edge-test:
target.kind==='case' 時の undefined 安全性、既存 action:guarded 消費カードへの regression 無し確認)。

## 罠
- `targetUid` は「ガードしたキャラ」(guardUid) ではなく「アクション**宣言時**に指定されていた
  対象」= `ax.target` (rules/22 「宣言時 snapshot 固定、ガード成立後も差し替えない」原則、
  B08048 の「ガードされてもレベル-1 が効いている」と同じ設計思想)。
- `ax.target.kind` が `'case'` (事件へのアクション) の場合は targetUid=undefined になる —
  B04073 のカード側 filter (cardName) は char 対象のみ意味を持つため自然に不一致=false扱いで
  問題ないが、undefined アクセスで throw しないことをテストで確認。
