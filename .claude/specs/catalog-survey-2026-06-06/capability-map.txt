## Effect WRAPPERS (`resolver.run` runtime semantics)

- **sequence** `{steps:Effect[]}` — runs steps in order. If a step **enqueues a pick** (`__pendingEffectPickQueue` grows), saves remaining steps to `__pendingChainContinuation` and **returns (pauses)**; remainder runs post-pick on updated board via `applyPickAndContinuation`. Steps are otherwise independent (no no-candidate break).
- **chain** `{steps:Effect[]}` — "そうした場合" semantics. Like sequence, BUT also: after each step checks `__chainStepNoApply`; if a step had **no candidate** (set by `substituteAtomPick`), **breaks** (skips all later steps). Pick-await also pauses+continues like sequence.
- **parallel** `{steps:Effect[]}` — currently **identical to sequence** (runs in array order; no true parallelism; TODO). Does NOT pause on pick the way sequence does (plain loop).
- **choice** `{options:Effect[], chooser:'self'|'opp'|'owner'}` — runtime: runs `options[ctx.dyn.choiceIndex]` (default 0). Index out of `[0,len)` ⛔ **throws**. In resolve-picks walk: if `ctx.dyn.choiceIndex` valid → unwraps that option (consumed/deleted to avoid leak); else if `humanChooser && options.length>1 && chooser!=='opp'` → surfaces `__pendingEffectChoiceSide` + holds resume, returns empty parallel (pauses, no option run). AI/single-option/opp-chooser → walks all, runtime default 0.
- **optional** `{effect:Effect}` — runtime: runs `effect` only if `ctx.dyn.optionalRun===true`, else skip. In resolve-picks walk: `optionalRun` boolean → run/skip (consumed); `humanChooser` → surface `__pendingEffectOptionalSide` + hold resume, pause (empty parallel); **AI/non-human → skip** (default off; ⚠ optional effects with self-cost are never auto-taken by CPU).
- **conditional** `{if:Condition, then:Effect, else?:Effect}` — `evalCond(if)` → run `then` else run `else` (if present).
- **forEach** `{over:TargetingRef, do:Effect}` — resolves `over` to Candidate list, binds each to `ctx.bindings['$each']=[cand]`, runs `do` per candidate; restores prior `$each` after (try/finally).
- **replace** `{trigger, with}` ⛔ / **negate** `{trigger}` ⛔ — `resolver.run` **throws** (`replace/negate are immediate-resolution; not runnable via effect.run`). These are handled by the resolver-stack/trigger layer (immediate-resolution per rules/15), NOT executable as plain effects.
- **atom** — dispatches `runAtom(verb,args,ctx)`.
- **custom** `{fn:(s,ctx)=>void}` — runs `fn` directly. **Not JSON-serializable** (validate exempts it; only place a function is allowed).

`validate.walk` rejects: function values outside `kind:'custom'`; unknown atom verb; unknown Effect kind; `forEach.over.kind` not in `{self,pick,all,fromBound}`; `conditional` missing `if`/`then`; `choice` with <1 option; `sequence/parallel/chain.steps` not array; `custom` missing `fn`. Condition trees and atom `args` are NOT deep-validated (args validated only at runtime in `runAtom`).

## Pick mechanisms (single vs multi `pickedUids`)

Two descriptor patterns (`substituteAtomPick`):
- **Pattern A** — `args.uid:'$pick'` (+ optional pick query in `target`). Resolves by substituting `uid` → picked char uid; drops `target`. Used by `sceneRemove`/`charModifyAP|LP|Level`/`sceneSetState`/`charSetCard`/`charRemoveSetCard`/`sceneToHand`/`sceneEnter(switch)`. Pattern A **requires `picked.kind==='char'`** in AI path. Runtime: handlers detect short-form (`uid` absent + n/max) and call `tryRePickFromAtom` to enqueue, logging `…:awaiting-pick`.
- **Pattern B** — `args.uid` absent/non-`$pick` (e.g. `discard`/`evidenceToHand`/`handAddFromRemove`), or bind contracts `cardId:'$pick.cardId'` (sceneEnter) / `cardIds:'$pick.cardIds'` (charStackCard). Resolves `target`→`[cardId]` array, or fills `cardId`/`cardIds` from candidates. **Pattern B push is suppressed in initial walk** (`!_fromAtomHandler`) to avoid later steps stealing earlier targets — pushed at runtime via `tryRePickFromAtom`.

Candidate kinds folded into picks: `char` (uid,cardId), `card` (synthetic uid `cardId#index`), `evidence` (synthetic uid `evidence:side:idx`). `file` kind (face-down) is **skipped**. Empty candidate set → sets `__chainStepNoApply=true` (chain break signal) + returns atom unchanged (no-op fallback, rules/10 0-target legal).

Multi-pick:
- `nMin`/`nMax` come from `target.n.{min,max}` (default 1/1). `nMin===0` ⇒ skippable (0-pick legal; e.g. "〜枚まで").
- **Human**: `__pendingEffectPickQueue` FIFO of `PendingEffectPickSide{player,candidates,atomVerb,atomArgs,nMin,nMax,source,distinctNames}`. `distinctNames` (from `target.query.distinctNames`) blocks same-name-component multi-select (rules/19). UI resolves via `applyPickAndContinuation(state,pending,pickedUid,pickedUids?,switchRemoveUid?)`.
- **Multi `pickedUids`** (Pattern A): if `pickedUids.length>1`, builds a `sequence` of per-uid atoms (one atom per picked char). Single → single atom. (Pattern B multi: `cardIds`=all resolved cardIds; `target:[cardId]` single only — n>1 needs extension for generic target form.)
- **AI** (`drainAiEffectPicks`/`chooseAiPick`): drains queue (guard 64). `chooseAtomTarget` policy picks best char, else first candidate. `nMax>1` → greedy `cands.slice(0,nMax)` as `pickedUids`. `pickedUid===null` (empty) → skip + drop paired continuation. AI/heuristic never surfaces choice/optional (choice default 0, optional skipped).
- **`{dyn}` args** (e.g. `delta:{dyn:'$cost.flipFaceUpEvidence.count*N'}`, D08026/D11021) are literalized by `resolveDynArgs` at the human-pick boundary (ctx with `costPaid`) and in AI path — cost-dependent dyn **cannot** be resolved after crossing the human-pick boundary.

Choice/optional resumption (apply-pick): `applyChoiceAndContinuation(state,pending,choiceIndex)` and `applyOptionalAndContinuation(state,pending,run:boolean)` re-walk the held resume effect with `ctx.dyn.choiceIndex`/`ctx.dyn.optionalRun` (+ restored `triggerPayload` for `$trigger.*`), then `event.queue` + `runAllUntilEmpty`. Continuations (`__pendingChainContinuation`) re-run on the same saved ctx to preserve bindings across steps (BUG-107).

# Detective Conan TCG Engine — Condition Reference (FROZEN)

Source: `src/engine/cond/eval.ts`, `src/engine/types/effect.ts`. Every `Condition.kind` is enumerated below. All are fully evaluated in `evalCond` (no throws, no stubs in the condition evaluator itself). Player semantics: `'self'` = card owner (`ctx.source.player`); `'opp'` = opponent of owner.

## Boolean combinators
- **`true`** — always `true`. No args.
- **`false`** — always `false`. No args.
- **`not`** `{ c: Condition }` — negation of inner.
- **`and`** `{ cs: Condition[] }` — all inner conditions true (`.every`).
- **`or`** `{ cs: Condition[] }` — any inner condition true (`.some`).

## Turn / player phase
- **`turn`** `{ player: 'self'|'opp' }` — current turn player equals resolved player. (【自分ターン中】/【相手ターン中】)

## Case / partner color & trait
- **`partnerColor`** `{ color: string|string[] }` — owner's partner CardDef.colors intersects `color` (OR semantics; array means "has any of"). (【パートナー(色)】)
- **`caseColor`** `{ color: string|string[]; combine?: 'or'|'and' }` — owner's case colors. `combine:'and'` ⇒ must have ALL; default/`'or'` ⇒ any. Falls back to `caseInfo.colors` if CardDef unregistered. (【事件(色)】, &-combine supported)
- **`caseTrait`** `{ trait: string }` — owner's case has `trait`. Evaluates **union of `CardDef.caseTraits` + `CardDef.traits`** (BUG-124 fix — 古城/婚活 both work). Single trait only (no array).

## FILE / case status
- **`fileAtLeast`** `{ n: number }` — owner's `file.length >= n`. Assisted-partner entries are already in the file array, so they count. (【FILE(X)】)
- **`caseStatus`** `{ status: '事件編'|'解決編' }` — owner's case status equals. (【事件編】/【解決編】)
- **`fileTopType`** `{ type: 'card-back'|'assisted-partner' }` — owner's file top (last-pushed) entry `.type` equals. `false` if file empty.

## Scene / character presence
- **`bond`** `{ cardName: string|string[] }` — owner's **scene** (NOT partner) contains a char whose CardDef name-components (incl. split names via `allCardNameComponentsForDef`) intersect `cardName`. (【絆】)
- **`sceneHas`** `{ query: TargetQuery; nMin?: number }` — `candidates(query)` count `>= nMin` (default 1). Full `TargetQuery` power (area/side/filter/filterAny/state/excludeSelf/named/distinctNames). The most general presence/count predicate available.

## Character stat thresholds (via `TargetingRef`)
Each resolves the ref to char uids (`resolveCharsForRef`) and is true if **ANY** resolved char meets the threshold (`.some`). Ref kinds: `self` / `pick` (uses `ctx.picked` else candidates) / `all` / `fromBound`. Resolution failure ⇒ `[]` ⇒ `false`.
- **`apAtLeast`** `{ ref: TargetingRef; n: number }` — some char's current AP `>= n`.
- **`lpAtLeast`** `{ ref: TargetingRef; n: number }` — some char's current LP `>= n`.
- **`stackedCountAtLeast`** `{ ref: TargetingRef; n: number }` — some char's stacked-card count `>= n`.

## Evidence
- **`evidenceAtLeast`** `{ player: 'self'|'opp'; n: number }` — that player's `evidence.length >= n`.

## Remove-area (リムーブ) counts by attribute
Each filters the player's `remove` pile (array of cardIds) by CardDef attribute and checks count `>= n`. ⚠ These are the ONLY remove-area predicates — there is **NO total remove-count condition** and no remove-by-kind/level/keyword.
- **`removeColorAtLeast`** `{ player; color: string|string[]; n }` — count of removed cards whose colors intersect `color`.
- **`removeTraitAtLeast`** `{ player; trait: string|string[]; n }` — count by `CardDef.traits` (キャラ特徴 only; case-traits not unioned here).
- **`removeNameAtLeast`** `{ player; cardName: string|string[]; n }` — count by name-components (split names honored).

## Trace / turn flags / declared-use
- **`scratchTrace`** `{ player: 'self'|'opp'; v: '発見済'|'未発見' }` — `state.scratchTrace[p]` equals. (痕跡; note: own-refresh never sets 発見済 per rules, enforced elsewhere.)
- **`flag`** `{ player; key: keyof TurnScopedFlags; v: boolean }` — `state.turnState[p][key] === v`. Only boolean turn-scoped flags (key must be a literal `TurnScopedFlags` member). ⚠ Numeric turn-state (e.g. declaredAbilityUseCount Records) NOT comparable here — use `declaredUseUnder`.
- **`declaredUseUnder`** `{ uid: string; abilityId: string; max: number }` — that char's declared-ability use count `< max`. (【ターン①】/【ターン②】 gating, by literal uid — not ref-resolved.)

## Bindings
- **`bound`** `{ key: string; presence?: 'exists'|'matched' }` — `ctx.bindings[key]`. `presence:'matched'` ⇒ is a non-empty array; default/`'exists'` ⇒ `!== undefined`.
- **`boundMatchesFilter`** `{ bindKey: string; filter: TargetFilter }` — evaluates the cardId of `ctx.bindings[bindKey][0]` against a **CardDef-driven** filter. ⚠ Only these filter fields honored: `cardId`, `cardName`, `trait`, `color`, `levelMin`, `levelMax`. ⛔ `apMin/apMax/lpMin/lpMax/keyword/kind/hasSetCards/custom/state` are IGNORED here (SceneCharacter-state fields out of scope — only CardDef statics). (「〚カード名[X]〛を登場させた場合」)

## Trigger-payload-dependent (only valid inside a triggered hook with matching `ctx.triggerPayload`)
These read `ctx.triggerPayload`; if the expected payload shape is absent ⇒ `false`. Only meaningful as `matcherCondition` on the corresponding hook.
- **`contactOpponentApHigher`** — requires `contact:start` payload `{aUid,bUid}`. True only if `aUid === ctx.source.uid` (self is attacker) AND defender AP `> ` attacker AP. ⚠ Self-as-attacker only (BUG-098); does NOT fire when self is defender.
- **`guardedBySelf`** — `action:guarded` payload `.guardUid === ctx.source.uid`. (「このキャラがガードしたとき」)
- **`enterOrderEquals`** `{ n: number }` — enter-hook payload `.enterOrderThisTurn === n` (turn-reset counter, not cumulative). (【疾風 N】)
- **`triggerCharMatches`** `{ side?: 'self'|'opp'|'either'; filter?: TargetFilter }` — payload `{uid,player}` (e.g. `reasoning:end` reasoning char). `side:'self'` ⇒ payload.player === owner side; `'opp'` ⇒ opposite; `either`/undefined ⇒ no side gate. If `filter` set, runs **full `matchOneFilter`** against the scene char (all TargetFilter fields honored, incl. ap/lp/keyword/kind/state via SceneCharacter). ⚠ Only matches chars currently in `scene` (payload char must still be on scene to apply filter).

## Escape hatch
- **`custom`** `{ check: (state, ctx) => boolean }` — arbitrary TS predicate. NOT JSON-serializable; bypasses the DSL. Use is a last resort (骨格凍結/DSL-first policy). Treat any card requiring `custom` as **needing a function-valued condition** (not declarative).

## NOT expressible as a condition (⛔ — require engine/new-condition work; do NOT assume implementable)
- ⛔ **Hand count** — no `handAtLeast`/`handCount` condition. `TargetQuery.area:'hand'` exists for `sceneHas`, so **hand-card-by-filter presence IS expressible** via `sceneHas{query:{area:'hand',...}}`, but a raw "hand size ≥ N" (any card) is only reachable by `sceneHas` with an empty/match-all filter.

- ⛔ **Numeric turn-state comparison** — `flag` is boolean-only; numeric counters (e.g. per-turn use Records) not comparable except via `declaredUseUnder` (single uid+abilityId).
- ⛔ **`boundMatchesFilter` dynamic-stat fields** — ap/lp/keyword/kind/hasSetCards/state on a bound card are silently ignored (CardDef-statics only).
- ⛔ **Cross-turn / historical predicates** beyond `scratchTrace` (痕跡) — no generic "this game, X happened" memory condition.
- ⛔ **MR-specific gates** (isMR flag, color-count of a card) — no condition kind exposes `isMR` or "card has ≥2 colors". This is a known **DEFER gate** for 2-color MR / partner-area MR enumeration (engine has no isMR/色数 filter nor partner-area MR GameState slot; B07045/B09047 deferred).

# Engine Target Filter Reference (FROZEN)

Authoritative as of read of `src/engine/target/{candidates,resolve}.ts`, `src/engine/types/{candidate,effect}.ts`, `src/engine/read/keyword.ts`. Covers `pick` / `all` / `forEach over` target queries. Validation path = `matchOneFilter` (the canonical pick-enumeration path).

## TargetingRef.kind (top-level target shapes)
- `self` — the effect's source card. No filter applied. Always 1 candidate (min/max=1).
- `pick` — `{ query, n:{min,max}, chooser }`. Enumerated via query; player picks. `legalCount` clamps min/max to candidate count (so "N枚まで" allows 0 when fewer exist).
- `all` — `{ query }`. All matching candidates auto-selected (min=max=count).
- `fromBound` — `{ bindKey }`. Returns `ctx.bindings[bindKey]` verbatim (no filter re-applied). ⛔ Empty array if binding absent.

## TargetQuery — selectors (apply BEFORE filters)
- `area` — one of: `scene` (default), `partner-area`, `hand`, `deck`, `remove`, `evidence`, `file`, `case`.
  - `scene` → `char` candidates (full filter support incl. state/named/numeric).
  - `partner-area` → single `partner` candidate per side (partner.cardId filtered by-cardId only).
  - `hand` / `deck` / `remove` → `card` candidates with `index`.
  - `evidence` → `evidence` candidate; filtered by the evidence's `cardId`.
  - `case` → `card` candidate (the case card) area=`case`.
  - ⛔ `file` → emits `file` candidates UNFILTERED. `query.filter`/`filterAny`/`state`/`named` are NOT applied to file area (loop pushes every index unconditionally). Treat file targeting as "all file cards, no predicate".
- `side` — `self`, `opp`, `either` (default; both sides), `owner` (= source's player), `opp-of-owner`. Default/`undefined` = `either` (both sides eligible).
- `excludeSelf` — bool. Scene only. Drops the candidate whose `uid === ctx.source.uid`. ⛔ Only meaningful for `char` candidates; no effect on non-scene areas.
- `state` — array of `'active' | 'sleep' | 'stun'`. Scene-char only (checked in `matchesQueryForChar`). ⛔ NOT evaluated for partner/hand/deck/remove/evidence/file/case candidates (no `state` field there).
- `named` — `true` = only 名乗り(isNamed) chars; `false` = only non-named; `undefined` = no filter. ⛔ Scene-char only (uses `c.isNamed`); ignored elsewhere.
- `distinctNames` — bool. Enforced at `resolve()` time only (rules/19 split-name): no two picks may share any card-name component. ⛔ Not a candidate filter — it rejects illegal multi-pick combos, throws on violation.
- `filter` — single `TargetFilter`, ALL its fields ANDed.
- `filterAny` — `TargetFilter[]`; passes if ANY one matches (OR group). Combined with `filter` as: `filter AND (any of filterAny)`.

## TargetFilter predicates (each field ANDed within one filter object)
- `cardId` — `string | string[]`. Exact match against candidate's `cardId` (membership if array).
- `cardName` — `string | string[]`. Matches via `allCardNameComponentsForDef` → honors split-name cards (rules/19, e.g. 江戸川コナン&工藤新一 matches each component). Needs a registered CardDef; if def missing, components=[] → no match.
- `trait` — `string | string[]`. True if def.traits intersects wants (OR within array). Empty traits if no def.
- `color` — `string | string[]`. True if def.colors intersects wants (OR). 2-color card matches if it has ANY listed color. ⛔ No "must have ALL listed colors" mode; no color-count predicate.
- `keyword` — `string | string[]`. Via `defHasKeyword`: checks `def.keywords[]` AND icon-abilities. Supported icon keywords: `カットイン`, `ヒラメキ`, `変装`, `ミスリード` (resolved from AbilityDef structure, BUG-122). Other keyword strings (迅速 / 突撃[X] / ブレット / 痕跡 etc.) matched only if literally present in `keywords[]`. OR within array.
- `kind` — `'character' | 'event'`. Exact match against `def.kind` (BUG-118; now honored on this path). ⛔ Only these two literals; no `'partner'` / `'case'` kind filter.
- `apMin` / `apMax` — numeric AP bound (inclusive). Effective AP = `apOverride ?? def.ap ?? 0` + `apMod_permanent` + `apMod_turn` + `apMod_contact` (from `c.turnEffects`). For non-scene candidates (`c===null`) uses printed only (no mods).
- `lpMin` / `lpMax` — numeric LP bound (inclusive). Same formula with `lpOverride` + `lpMod_*`.
- `levelMin` / `levelMax` — numeric level bound (inclusive). `def.level ?? 0` + `lvlMod_permanent`/`_turn`/`_contact`. ⛔ Non-scene candidates: printed level only.
  - ⚠ Numeric note: continuous-delta (e.g. D08005 dyn continuousDelta) is intentionally OMITTED to avoid cycles → residual mismatch tracked as BUG-113.
- `hasSetCards` — bool. `true` requires `c.setCards.length > 0`. ⛔ Scene-char only (needs `SceneCharacter`); always treated as "no set cards" / false-branch for non-scene candidates (`c===null` → has=false).
- `custom` — `(state, candidate) => boolean`. Arbitrary escape-hatch predicate. ⛔ NOT JSON-serializable (function) — violates DSL serializability; avoid for new DSL cards.

## Predicates that DO NOT EXIST ⛔ (cannot be expressed without engine change)
- ⛔ `isMR` / MR-rank filter — no MR flag predicate. (Known DEFER gate: 2色MR / partner-area MR enumeration; see B07045/B09047 — no `isMR` + no GameState slot for partner-area MR列挙.)
- ⛔ `colorCountMin` / color-count / multi-color / mono-color predicate — none. `color` is membership-OR only; cannot require "2+ colors" or "has ALL of these colors".
- ⛔ "has ALL listed colors" (【事件(色1)&(色2)】-style AND over colors) — not supported (color is OR).
- ⛔ "has ALL listed traits" — `trait` is OR-only; no trait-AND mode.
- ⛔ `hasSetCards` on non-scene areas / set-card count / set-card content filter — only boolean presence, scene-char only.
- ⛔ `state` / `named` / `excludeSelf` on non-scene areas — silently ignored.
- ⛔ `filter`/`filterAny`/`state`/`named` on `area:'file'` — file candidates are emitted unfiltered.
- ⛔ AP/LP/level filters reflecting continuous-delta (dyn) modifiers — omitted (BUG-113).
- ⛔ Numeric/state/setCard filters with correct values on non-scene candidates — only printed stats, no turnEffects (no `c`).
- ⛔ `kind` values beyond `'character'|'event'` (no partner/case/event-subtype).
- ⛔ Keyword filter for arbitrary keywords not in `keywords[]` and not one of the 4 icon abilities (カットイン/ヒラメキ/変装/ミスリード).
- ⛔ Any predicate on FILE/refresh/痕跡/評価-of-opponent-hand-contents, zone-count thresholds, "topmost only", evidence-face state, stun-vs-sleep transitions — none exist as target filters.

## Candidate kinds produced (for downstream verb compatibility)
- `char` (scene), `partner` (partner-area), `card` (hand/deck/remove/case), `evidence`, `file`. A verb expecting a `char` target (e.g. `sleepChar`, `removeFromScene`) ⛔ cannot consume `partner`/`card`/`evidence`/`file` candidates — area choice constrains usable verbs.

# Detective Conan TCG Engine — Card-Triggerable Hook Reference (FROZEN)

Source of truth: `src/engine/listeners/triggered.ts`, `src/engine/types/hooks.ts`, `src/engine/types/card-def.ts` (`TriggerDef`/`AbilityDef`), `src/engine/listeners/hirameki.ts`, `src/engine/listeners/misread.ts`, plus emit sites. A card can only react to a hook if (a) it appears in the `TRIGGERED_HOOKS` registration list **and** (b) something `event.emit(...)`s it. All else is internal-only (cards cannot subscribe).

## How a `type:'triggered'` ability fires (common gate, `handleHook`)
- Engine scans all cards in play each emit: scene chars, partner (uid `partner:<p>`), case (uid `case:<p>`), and **hand cards** (uid `hand:<p>:<cardId>`). Evidence/leaving cards handled by special handlers (below).
- Per ability, in order: `type==='triggered'` → hook match (`trigger.hook` OR any of `trigger.hooks[]`) → `scope` gate → `selfOnly` → `matcher(payload,state)` (closure) → `matcherCondition` (declarative Condition, payload in `ctx.triggerPayload`) → `ability.condition` (6-stage condition icons) → `ability.effect` exists → `limit:{kind:'turn',n}` not exceeded (counted via `declaredUseCount` per `uid+abilityId`). Passing → `event.queue` of the `$pick`-resolved effect.
- **`scope`** gates which area a card reacts from: `on-scene`(default)=scene only; `on-partner-area`=partner-area OR scene; `on-hand`=hand; `on-evidence`=evidence (virtual only); `always`=all.
- **`selfOnly`** (`selfOnlyMatches`): hand cards match on `payload.cardId===card.cardId && source.player===card.player`; scene/partner/case match on `source.uid===card.uid`. ⛔ For hooks whose `source.uid` is NOT the reacting card (e.g. `action:guarded` source.uid = attacker), `selfOnly` cannot express "this card guarded" — use `matcherCondition` instead (BUG noted in spec; e.g. `guardedBySelf`).
- **`matcherCondition`** & **`condition`** receive `ctx.triggerPayload=payload`; `triggerCharMatches{side,filter}` reads `payload.uid`+`payload.player` (requires both present in payload) and matches the trigger char by side (`self`=same side as owner) + `TargetFilter`.
- **`limit`**: only `kind:'turn'` (n=1|2) is enforced for triggered. `kind:'game'` ⛔ NOT enforced for triggered abilities.
- **`optional:true`**: special. For `evidence:remove-by-action` → routed to hirameki side-channel (fire/skip). For `effect:declared`+`scope:'on-hand'` → marks the ability as a **cut-in** (player-chosen via contact flow), NOT auto-queued.

## CARD-TRIGGERABLE HOOKS (registered + emitted)

- **`enter`** — char登場時 (【登場時】/【疾風 N】). Emitted by `atom-handlers` sceneEnter/sceneSwitch and `next-hint`/`hand-use-card` char登場.
  - payload: `{ uid, viaEffect, enterOrder, enterOrderThisTurn }`. source: `ctx.source` (the entering char's source for atom paths). selfOnly: ✅ (`source.uid`). matcherCondition: `enterOrderEquals{n}` reads `enterOrderThisTurn` (疾風). ⛔ Disguise does NOT fire `enter` (rules/09); only `disguise:into`.

- **`disguise:into`** — 【変装時】. Emitted by `flow/contact.ts` disguise.
  - payload: `{ uid, fromCardId, newCardId }` (uid preserved, cardId swapped to disguise card). source: `{ player, uid: targetUid }`. selfOnly: ✅ (`source.uid`=disguised char uid). Reacting card is the post-disguise cardId (scene scan). selfOnly/triggerCharMatches supported.

- **`leave:to-remove`** — 現場リムーブ時 (any cause). Emitted by `mutate/scene.ts` on removal.
  - payload: `{ uid, cause }` (cause: `'contact-ap'|'effect'|'switch'|'cost'|'misplay-overflow'`). source: `{ player, uid: leavingUid, cardId: leavingCardId }`. Dual path: `handleLeaveToRemoveSelf` (the leaving card's own 【現場リムーブ時】, virtual scene location) + `handleHook` (other in-play cards reacting). selfOnly: ✅; matcher/matcherCondition/condition supported. ⛔ Misplay-overflow removal: rules/30 says such removals do NOT trigger 【現場リムーブ時】 — engine emits with `cause:'misplay-overflow'`; a card must self-gate via matcher if it must exclude this.

- **`action:declare`** — アクション宣言時. Emitted by `flow/action/state-machine.ts` (after attacker sleeps).
  - payload: `{ byUid, target, uid: byUid, player: byPlayer }` (`uid`/`player` added so triggerCharMatches works). source: `{ player: byPlayer, uid: byUid }`. selfOnly: ✅ (attacker). Shared 【ターンN】 with `reasoning:end` via `hooks:[...]`.

- **`action:guarded`** — アクションがガードされたとき. Emitted by `state-machine.ts`.
  - payload: `{ byUid, guardUid }`. source: `{ player: ax.byPlayer, uid: ax.byUid }` (= **attacker**, NOT guard). selfOnly matches the attacker. ⛔ "this card guarded" cannot use selfOnly (guardUid is only in payload) → must use `matcherCondition` (`guardedBySelf`) which reads payload.guardUid vs source.uid.

- **`action:pre-target`** — attacker選択時、target列挙前 (target拡張用). NOTE: NOT processed by the generic `handleHook` queue path at enumeration time — `flow/action/target-expander.ts` does a **synchronous inline walk** of scene abilities with `trigger.hook==='action:pre-target'`.
  - payload: `{ byUid }`. source: `{ uid, cardId, player }` (attacker). selfOnly: ✅ (inline: `sceneCard.uid===byUid`). Effect MUST be a single atom `expandActionTargets{ side, state[], levelMin, levelMax }`; args read directly. ⛔ Only `expandActionTargets` is consumed here; other effects on this hook via the generic listener fire too late to affect enumeration.

- **`contact:start`** — コンタクト発生時. Emitted by `state-machine.ts`.
  - payload: `{ aUid, bUid }`. source: `{ player: ax.byPlayer, uid: ax.byUid }`. selfOnly: ✅ (attacker uid). ⚠ payload has no `player` → `triggerCharMatches` (needs payload.player) won't match.

- **`reasoning:end`** — 推理後 (証拠加算後). Emitted by `flow/main/reasoning.ts`.
  - payload: `{ uid, player, gained }` (`gained`=evidence count). source: `{ player, uid }` (推理 char/partner). selfOnly: ✅. `$trigger.gained` usable in effect. triggerCharMatches supported. Shared 【ターンN】 with `action:declare`.

- **`case:to-resolved`** — 事件編→解決編移行 (fires once per game, one-way). Emitted by `mutate/case.ts`.
  - payload: `{ player }`. source: `{ player, uid: case:<p>, cardId }`. selfOnly: ✅ (case uid). ⚠ payload has no `uid` → triggerCharMatches won't match.

- **`phase:end:start`** — エンドフェイズ開始時. Emitted by `flow/turn.ts`.
  - payload: `{ player }`. source: `undefined`. ⛔ selfOnly cannot match (source is undefined → `source.uid` undefined); use `condition`/`matcherCondition` keyed on `payload.player` instead. Common for "ターン終了時にこのキャラをリムーブ"-style scheduled effects (gate by player, not selfOnly).

- **`effect:declared`** — multi-purpose "card was used / ability declared". Emitted from **5 sites**, payload kind varies:
  - hand-use-card: `{ kind:'event-use'|'character-use', cardId }`, source `{ player, cardId }` → **event card self-trigger** (e.g. `eventRemoveByAP`). scope `on-hand`, selfOnly matches `payload.cardId+source.player`.
  - next-hint: `{ kind:'event-use'|'character-use', cardId }`, source `{ player, cardId }`.
  - contact cut-in: `{ cardId, abilityId:'cutin' }`, source `{ player, cardId, bindings: contactBindings }` → **CUT-IN** (`scope:'on-hand'` + `optional:true`; `source.bindings` like `$contact.byUid` persisted into queued effect).
  - declared-ability: `{ kind:'declaredAbility', uid, abilId }`, source `{ player, uid, cardId }`.
  - partner-ability: `{ kind:'partnerAbility', abilId }`, source `{ player, cardId }`.
  - ⚠ A card reacting to `effect:declared` MUST filter on `payload.kind`/`cardId`/`abilityId` (matcher/matcherCondition) — the hook is heavily overloaded.

- **`evidence:remove-by-action`** — 証拠がアクション[事件]でリムーブされる時 (ヒラメキ). Special handler `handleEvidenceRemovedHook` (NOT in-play scan; def looked up from `payload.ev.cardId`).
  - payload: `{ player, ev:{ cardId } }` (`player`=removed side = ヒラメキ holder). source may carry `bindings`. scope must allow `on-evidence` (virtual CardLocation). ⛔ `selfOnly` NOT evaluated here (handler skips selfOnly). matcher/matcherCondition/condition ✅.
  - `optional:true` → pushes to `pendingHirameki` side-channel (`{player,cardId,abilityId}`), UI/AI decides fire/skip; only **first** optional match per event is queued. `optional:false/undefined` → forced queue (rules/15 必須効果).

## 1. Declared-ability COST kinds (`Cost`)

`canPay` (read-only feasibility) and `pay` (mutation) handle exactly these — both switches are exhaustive, no `default`. A cost kind not listed here cannot be expressed.

- **`sleepSelf`** — sleeps `ctx.source.uid`. Payable ONLY if char is `active` (sleep/stun ⛔ unpayable; stun cannot be slept via cost).
- **`sleepChar { target: TargetingRef }`** — sleeps picked/all candidate chars. Payable if ≥1 candidate is `active`. (Pays via `ctx.picked` if set, else ALL active candidates — no built-in count cap here; relies on caller's pick.)
- **`removeFromHand { target, n }`** — discard n hand cards to remove area. Payable if candidates ≥ n.
- **`removeFromScene { target, n }`** — remove n scene chars to remove area (reason `'cost'`). Payable if candidates ≥ n.
- **`removeDeckTop { player: 'self'; n }`** — remove n from own deck top. `player` typed `'self'` ONLY (⛔ cannot target opponent deck). Payable if deck.length ≥ n.
- **`discardEvidence { n }`** — remove n from TOP of own evidence (`ctx.source.player`). Payable if evidence.length ≥ n.
- **`selfToDeckBottom`** — move `ctx.source.uid` char to deck bottom. Payable if char exists.
- **`fileFrom { n }`** — pop n from top of own FILE. Payable if file.length ≥ n.
- **`flipFaceUpEvidence { n: { min, max } }`** — flip facedown evidence face-up; player picks indices via `ctx.dyn.costParams.flipFaceUpEvidence.indices`. Payable if facedown count ≥ `n.min`. Records `ctx.costPaid.flipFaceUpEvidence.count` (consumable via `$cost.flipFaceUpEvidence.count`). ⛔ `pay` THROWS if picked count ∉ [min,max].
- **`pay { items: Cost[] }`** — composite AND. Payable iff every item payable.
- **`choice { items: Cost[] }`** — composite OR. Payable iff some item payable. Branch chosen via `ctx.dyn.costChoice` (number index), else first payable.
- **`custom { check, pay }`** — ⛔ escape hatch: arbitrary closures. NOT JSON-serializable; violates DSL-first convention. Use only as last resort.

### Cost gaps / DEFER gates ⛔
- ⛔ No cost to remove/manipulate OPPONENT resources (all costs scoped to `ctx.source.player`; `removeDeckTop` typed self-only). "Self's"省略 per rules/21 is enforced structurally.
- ⛔ No "reveal/look" cost, no "return to hand" cost, no "stun self" cost, no level/AP-threshold cost.
- ⛔ `sleepChar` payment sleeps `ctx.picked ?? ALL active candidates` — there is no n-cap in the cost type itself; exact-count selection depends on the runner populating `ctx.picked`.

## 2. DYN expressions (`evalDyn`) — for scaling/late-binding

Evaluator: tokenizer + shunting-yard. Supports `+ - * / %`, parentheses, precedence, unary minus. NO `eval()`/`Function()`. Plain strings (no `$`) pass through literally. Booleans → stringified (not arithmetic-able). String operands in arithmetic ⛔ THROW.

### `$self.*` (scaling source = the effect source)
- **`$self.sceneTrait.<trait>`** — count of chars on `ctx.source.player` scene with trait `<trait>`. Works WITHOUT `ctx.source.uid` (player-based) → usable from hand-origin (cutin) effects.
- **`$self.faceUpEvidence`** — count of face-up evidence on `ctx.source.player`. Player-based (no uid needed).
- **`$self.ap`** — current effective AP of source uid (includes overrides + turnEffects + continuous). Requires `ctx.source.uid` (⛔ throws if absent).
- **`$self.lp`** — current effective LP of source uid. Requires uid (⛔ throws if absent).
- **`$self.uid`** — source uid (string). Requires uid.
- **`$self.cardId`** — source cardId (`ctx.source.cardId ?? ''`).
- ⛔ Any other `$self.<prop>` → THROWS (`unknown $self property`). No `$self.level`, `$self.traitCount` (only `sceneTrait.<x>`), no opponent-side `$self`.

### `$contact.*` (requires `ctx.contact`, else ⛔ throws)
- **`$contact.byUid`** — attacker uid.
- **`$contact.targetUid`** — target uid.
- **`$contact.guardUid`** — guard uid.
- **`$contact.attackerSide`** — `'self'|'opp'`.
- ⛔ Other `$contact.<prop>` → THROWS.

### `$cost.<key>.<path>` (requires `ctx.costPaid`, else ⛔ throws)
- Reads `ctx.costPaid[key]` then drills `<path>`. Currently only producer is `flipFaceUpEvidence` → `$cost.flipFaceUpEvidence.count`.
- ⛔ Missing key / undefined entry → THROWS. Non-primitive leaf → THROWS.

### `$dyn.<key>[.path]` (requires `ctx.dyn`, else ⛔ throws)
- Reads `ctx.dyn[key]` (pre-computed by parent effect) then optional drill.
- ⛔ Key not in `ctx.dyn` → THROWS.

### `$pick`
- ⛔ NOT evaluable in dyn — always THROWS. Pick results are resolved elsewhere (`resolve-picks`, per memory: `$`-prefixed, only in `resolveDynArgs`).

### DYN gaps ⛔
- ⛔ No `$opp.*`, no player/evidence-count except `$self.faceUpEvidence`, no FILE/deck/hand size placeholders, no `$turn`, no comparison/boolean operators (only arithmetic).
