# D08015 小嶋元太 — エンジン内部処理トレース (参考)

> [D08015-workflow.md](D08015-workflow.md) は **カード固有の意味** のみを表す ([WORKFLOW-GUIDELINES.md](WORKFLOW-GUIDELINES.md))。
> 本ファイルはエンジン内部 (event 通知 / pick 解決 / continuousModifier 等) を平易語でトレースした **companion**。
> カード仕様には無関係なため workflow 図には含めない (BUG-064)。

## a1 登場時効果 — 内部トレース

```text
[ D08015 が現場に出る ] (出方 4 通り: 手札使用 / ネクストヒント2段目 / 効果で呼出 / スイッチ)
   ▼ どの経路でも以降は同じ
[ 現場にカードを置く ] 名乗り状態 ON、登場順を記録
   ▼
[ 「キャラが登場した」イベントを全カードに通知 ] 中身: 登場カードID / 効果経由か / 登場順
   ▼
[ 登場時能力を持つカードを全エリア scan ] 現場 / パートナーエリア / 事件 / 手札
   ▼
[ D08015 a1 が「登場した本人なので発動」と判定 ] selfOnly フラグ ON
   ▼
[ 効果内の「選ばせる箇所」を先に解決 ] AI=自動 / 人間=「選択待ち」で一時停止
   ▼
[ 効果を「あとで処理するリスト」に登録 → 上から順に実行 ]
   ├─▶ step 1: デッキから 1 枚引く
   │       ▼ デッキ 0 枚?
   │       ├ 0 枚 → リフレッシュ (rules/14): リムーブも0 なら敗北 (理由 deck-out, BUG-036)
   │       │                          成功なら リムーブ全シャッフル→デッキ / 相手証拠+1 / 再ドロー
   │       └ 残あり → デッキ最上 1 枚を手札へ
   └─▶ step 2: 「手札から 1 枚リムーブ」(選択肢1つ=実質確定)
           ▼ 誰が選ぶか
           ├ 人間 → 選択待ちフラグ → EffectPickerModal → クリック → 結果を engine へ返却
           │         → 処理対象を確定カードに差替 → 「あとで処理するリスト」へ再投入
           └ AI  → 捨て候補 heuristic で 1 枚自動選択
   ▼
[ 選ばれたカードを 手札 → リムーブ へ移動 ]
   ▼
[ a1 効果完了 → ログ記録 → Toast / OppTurnOverlay 更新 ]
```

## a2 カットイン効果 — 内部トレース

```text
[ アクション宣言 ] 攻撃キャラ + 対象 (相手キャラ / 相手事件) を指定
   ▼
[ ガード判定 ] 相手がアクティブキャラでガード or しないを選択
   ▼
[ 「コンタクト発生」イベントを全カードに通知 ] 中身: 攻撃側 / 対象 (or ガード) キャラ
   ▼
[ カットイン / 変装フェーズ ] CutInDisguisePickerModal 表示
   │ 攻撃側手札のカットイン可能カードを列挙、事件の色と合致チェック (rules/20)
   ▼
[ プレイヤー / AI が「D08015 をカットイン使用」を選択 ]
   ▼
[ D08015 を 手札 → リムーブ ] rules/09 カットインカードは即リムーブ
   ▼
[ AP +1000 効果を起動 ] 持続効果 (continuousModifier) / scope=contact / 効果先=攻撃側 actor
   ▼
[ 「現在有効な効果リスト」に登録 ] + 「カットイン使用済み」フラグ ON (1 コンタクト 1 枚, rules/09)
   ▼
[ AP 比較時、攻撃側最終 AP に +1000 反映 ] 元 AP2000 + 効果合算 = 3000 で比較
   ▼
[ コンタクト結果判定 (AP 比較で対象リムーブ / 維持) ]
   ▼
[ 「コンタクト終了」イベント通知 → scope=contact の持続効果が自動解除 ]
   ▼
[ カットイン使用済みフラグは次コンタクト開始時にリセット ]
```
