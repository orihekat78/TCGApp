# 12. 確認動作（プレイヤー間の合意ポイント）の設計

> 出典: B群対戦動画3本の字幕に頻出する確認フレーズの分類
> 物理対戦では口頭で行う「相互確認」を、Webアプリの **モーダル/ログ/通知** で再現する。

## 観察された確認動作の5種類

### 1. リソース変動の確認
> 例: 「ワンドローしてください」「証拠もらってください」「2枚リムーブで」

→ 自動処理だが、相手が認識する必要がある変動。

### 2. 効果発動の宣言
> 例: 「効果使います」「登場時、〜」「事件効果使います」

→ プレイヤーがアクティブに発動を選択する効果。

### 3. 対象指定の宣言
> 例: 「ベルモットでお願いします」「7000以下のキャラリムーブで」「赤いシーちゃんで」

→ 効果のターゲットを指定。

### 4. 状態遷移の宣言
> 例: 「リフレッシュ入ったので痕跡発見済になりました」「アシストで解決編に入ります」

→ 自動的に発生する大きな状態変化を相互合意。

### 5. ターン進行の合図
> 例: 「終わります」「終了です」「ターンエンド」

→ ターン制御の引き渡し。

## Webアプリでの実装方針

### 自動処理 + ログ表示パターン
リソース変動（カテゴリ1）と一部の状態遷移（カテゴリ4）は自動処理し、
**画面右側のイベントログ** に記録。クリックでロールバック確認可。

```
[10:23] あなたのターン
   📋 デッキから1枚ドロー (手札: 4→5枚)
   📂 FILEに2枚追加 (FILE: 3→5枚)
   🎯 ネクストヒント: FILE一番上を手札へ
   🎴 服部平次 (Lv5) を現場に登場 [名乗り]
   👀 推理: 江戸川コナン → 証拠+1 (証拠: 4/7)
   🛑 ターンエンド
```

### 効果発動モーダルパターン
プレイヤーが選択する効果（カテゴリ2）は **モーダル + 「使用する/使用しない」ボタン**：

```
┌─────────────────────────────────┐
│ 江戸川コナン【宣言】            │
│ デッキ上1枚を表向き 引く        │
│                                  │
│ 使用しますか?                    │
│ [使用する]  [使用しない]         │
└─────────────────────────────────┘
```

### 対象選択UI（カテゴリ3）
効果が対象を要求する場合：
- 候補カードが **黄色の枠で点滅**
- 候補外カードは **半透明グレーアウト**
- カウント要求時は「あと N枚選択」のヒント
- キャンセルは Esc キー or「キャンセル」ボタン

### 大状態遷移は確認モーダル
リフレッシュ、痕跡発見、解決編移行など重要遷移は
**画面中央に2〜3秒のオーバーレイ** で告知：

```
   ┌──────────────────────────┐
   │ 🔄 リフレッシュ          │
   │  リムーブ→デッキへ       │
   │  相手は証拠+1            │
   └──────────────────────────┘
```

### ターンエンドは明示的ボタン
画面下部固定の **大きな「ターンエンド」ボタン**。
押下時に未解決効果が残っていれば確認モーダル：
「未解決の効果があります。本当にターンエンドしますか?」

## カットイン応答UIの即応性

コンタクト中にカットイン使用可能な場面では：
- 攻撃キャラと防御キャラの中央に **「カットイン使用?」モーダル**
- 手札のカットイン可能カードのみ **金色オーラ** で強調
- 5秒のソフトタイマー（タイムアウトでスキップ）
