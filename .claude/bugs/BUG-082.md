## 発見契機

commit f7861dd で「カットインを type:'triggered' + trigger:{hook:'effect:declared'} に統合」
する Option C migration を実施。移行直後の Playwright 実機検証で **cut-in を発火させても
AP boost (charModifyAP) が反映されない** ことが判明。

## 期待動作

cut-in card の effect に書かれた `target: { uid: '$contact.byUid' }` が、
deferred effect が runtime で実行された時点でも contact 中のキャラ uid に解決される。

## 実動作 (修正前)

`$contact.byUid` が `undefined` のまま atom-handlers に到達し、charModifyAP が no-op で
silent skip。AP boost が掛からないため AP 判定で負けてキャラがリムーブされる
(視認結果: cut-in 発動 → 何も起こらない → コンタクト負け)。

## RCA

Option C 後の cut-in は `effect:declared` hook で emit され、triggered listener 経由で
effect が **queue** に push される。実行は別タイミングなので、emit 時点の `ctx.bindings`
(`contact: { byUid: ... }`) が **queue→dispatch→runtime** の間に **drop** されていた。

具体的には EffectStackEntry に `bindings` フィールドが無く、queue push 時の bindings 情報が
保存されず、`entryToCtx` で復元できなかった。icon-cutin 時代は immediate evaluation だった
ため bindings 永続化が不要 → migration で deferred 化したことで初めて顕在化。

## 修正 (commit ff73d79)

EffectStackEntry に `bindings?: EffectCtx['bindings']` フィールドを追加し、
emit→queue→entry→entryToCtx→ctx.bindings の全パスで bindings を persist:

- `EffectStackEntry.bindings` 追加 (optional)
- `buildEntry` / 関連 queue push API が `bindings` を accept
- `entryToCtx` で `ctx.bindings = entry.bindings ?? {}` を復元
- triggered listener の emit 時に `source.bindings` (contact 情報含む) を queue に渡す

これにより deferred effect 実行時にも `ctx.bindings.contact.byUid` が利用可能になり、
resolveBindRef ('$contact.byUid') が正しく cut-in 対象 uid を返す。

### 型エラー対応

`entryToCtx` で bindings 復元時に `as EffectCtx['bindings']` cast を追加
(Candidate union の差異を吸収、原観測 7511-7514 で文書化)。

## 水平展開

- 他の deferred effect (declared ability の queue path、hirameki の non-immediate path 等)
  でも同じ bindings 永続化が有効。本 fix で **全 deferred effect** で bindings 利用可能化
  (既存 immediate effect は変化なし、影響ゼロ)
- hirameki Option C migration (f4ec641) で生成される `pendingHirameki` 経路は
  別 side-channel (listeners/hirameki.ts) で持つため本 fix の影響範囲外、回帰なし
- 既存 cut-in test (vitest) は 1609 → 1609 PASS で 0 件回帰、bindings 機構の生やしは
  既存テストを破壊せず

- DSL migration (immediate → deferred / icon-X → triggered など) を行う際は、
  effect ctx の全フィールド (bindings / source / contact / triggerPayload) が queue/
  dispatch path で persist されるか **必ず audit**
- EffectStackEntry の各フィールドに「emit→entry→ctx で復元される」comment を付与
- 将来 BUG-068 (resolveBindRef 全 atom 配線) と合わせて bind ref まわりの
  「emit 時点 ↔ runtime」整合性 spec を `.claude/specs/engine-api-bindings.md`
  として書く案 (現状未作成、follow-up タスク)
