### 2. selfOnlyMatches の hand 経路に player 比較追加 (root cause fix)

[src/engine/listeners/triggered.ts](../../src/engine/listeners/triggered.ts) `selfOnlyMatches` で hand area の場合 `payload.cardId === card.cardId` のみ照合していたため、両プレイヤー手札に同 cardId があると `selfOnly: true` でも誤発動していた。

修正後: `payload.cardId === card.cardId && source.player === card.player` で完全 player-filter。

## 期待動作

`handUseCard` で event card (例: D08025 蘭の一撃) を使用したとき、`effect:declared` hook の listener は **使用したプレイヤー自身の手札** にある該当 event card の effect のみを `pendingEffects` に queue する。相手プレイヤーの手札に同じ cardId の event card が含まれていても、それらの effect は queue **されない**。

## 実動作

[src/cards/_shared/eventRemoveByAP.ts](../../src/cards/_shared/eventRemoveByAP.ts) の factory は `trigger.selfOnly: true` を **未設定**。そのため [src/engine/listeners/triggered.ts](../../src/engine/listeners/triggered.ts) `handleHook` の `selfOnlyMatches` filter (line 90-98) が **通らない経路** で両プレイヤー手札の同 cardId event card 全てが scan され、それぞれの effect が queue される。

E2E 検証 (Round 4i [tests/e2e/patterns/event-remove-by-ap.spec.ts](../../tests/e2e/patterns/event-remove-by-ap.spec.ts)) で確認:

```
[Round 4i gap-1 detected] D08025: opp.source の pendingEffects が 1 個混入 → BUG-032 登録対象
[Round 4i gap-1 detected] D11020: opp.source の pendingEffects が 1 個混入 → BUG-032 登録対象
```

両カード共に self が `handUseCard` した直後の `pendingEffects` に、opp.hand 上の同 cardId source からも entry が積まれている。

## RCA

`eventRemoveByAP` factory 設計時、`triggered.ts` の `selfOnlyMatches` 経路 (hand area の場合 `payload.cardId === card.cardId` で同一カードのみ通す) を活用すべきだったが、factory 側で `trigger.selfOnly: true` を明示しなかった。`payload.player` 比較経路もなく、結果として両プレイヤー手札を等しく scan する経路に乗ってしまった。

個別実装の D11020 (sequence ability) も同様に `selfOnly` 未設定なので同じ症状を示す。これは shared factory 仕様の問題ではなく **on-hand triggered ability の慣習** の問題。

## 影響範囲

- 相手プレイヤーが同じ event card を手札に持っているとき、効果が二重発動する可能性
- 現状は smoke baseline (525/475) では誤動作が表面化していない (AI が同 event card を同時に持つ確率が低い + condition 評価で multi-fire が後段で潰される [BUG-033 関連])
- 競技対戦シナリオで両プレイヤーが同 event card を同時に手札に持つと engine state 不正になる可能性

## 修正方針 (別 Round で実装予定)

1. `eventRemoveByAP` factory の `trigger` に `selfOnly: true` を追加
2. `D11020.ts` の a1 ability も同様に `trigger.selfOnly: true` 追加
3. unit test 追加 (`tests/engine/listeners/triggered.test.ts`): opp.hand に同 cardId を入れて dispatch、`pendingEffects` に opp source が含まれないことを assert
4. E2E spec 側の `console.warn` を `expect(scan.oppCount).toBe(0)` に格上げ

> hiramekiDraw / hiramekiCharStun / その他 on-hand triggered ability に対する **水平展開** も必要 (Round 4i-fix で全件 grep + 一括対応推奨)。
