## ユーザー指摘 (再掲)

BUG-053 で human player effect の auto-pick は停止したが、UI からの対象選択
modal が未実装のため、現状は「効果が見えないまま終わる」体感だった (例: 蘭の
一撃使用 → 何も起きない)。

> #2: 蘭の一撃を使ったときに、効果が発動したんですがカードを自分で選べなかった。
> 自動でカードが選択されてしまった。
> #6: カードを選ぶ効果などユーザー依存の効果が自動で処理されるようになっている。

## 期待動作

D08025「蘭の一撃」等の human player 効果使用時:
1. AI heuristic で auto-pick されない (BUG-053 で対応済)
2. **対象候補 modal 表示** → ユーザーが選択 (本 BUG で対応)
3. 任意効果 (`n.min === 0`) なら「対象を選ばない」ボタンで skip 可
4. 必須効果 (`n.min >= 1`) なら必ず 1 つ選ぶまで modal 解除不可

## 実動作 (BUG-053 直後 = 本 BUG 修正前)

`resolveEffectPicks` が `humanChooser=true` で呼ばれても `chooseAtomTarget`
が undefined のため、`picked ?? cands[0]` の fallback で「先頭候補」が auto
選択されていた (前 BUG-053 では完全停止と書いたが実際は fallback で進む)。

修正方針: $pick を「未解決」のまま返却 + side-channel `__pendingEffectPickSide`
にセット → caller (triggered listener) が queue 抑止 → UI 側 dispatch
drain で store.pendingEffectPick に転送 → modal 表示 → 選択結果を
`effectPickResolve` dispatch で event.queue へ。

## RCA (Root Cause Analysis)

BUG-053 は「auto-pick を停止する基盤」のみ実装し、proper UI integration を
defer していた。本 BUG はその follow-up で hirameki / misread の side-channel

## 修正

### resolve-picks.ts

```ts
export interface ResolveEffectPicksOpts {
  chooseAtomTarget?: ChooseAtomTargetFn;
  byPlayer?: Player;
  humanChooser?: boolean;
  source?: { cardId: string; abilityId: string };
}

export type PendingEffectPickSide = {
  player, candidates, atomVerb, atomArgs, nMin, nMax, source
};

// substituteAtomPick:
if (opts.humanChooser) {
  setPendingEffectPickSide({ ... });
  return atom as Effect; // 未解決のまま
}
```

### triggered.ts

```ts
const resolvedEffect = resolveEffectPicks(..., {
  chooseAtomTarget: isHumanEffect ? undefined : aiPolicy.chooseAtomTarget?.bind(aiPolicy),
  humanChooser: isHumanEffect,
  source: { cardId, abilityId },
});
if ((globalThis as any).__pendingEffectPickSide) {
  continue;  // queue 抑止、UI 側で resolve 後 re-queue
}
```

### useEngineDispatch.ts

新 action `effectPickResolve`:
- `pickedUid: string | null` (null = skip、n.min===0 の任意効果のみ)
- pending atomArgs.uid を picked で置換 → resolved atom を event.queue
- post-dispatch drain で store.pendingEffectPick = null

### useEffectPickFlowDriver.ts (新規)

- `pendingEffectPick !== null && pending.player === 'self'` で modal が表示される
  (modal 自体は EffectPickerModal で render)
- AI side fallback: 先頭採用 (将来 chooseAtomTarget 経由予定)

### EffectPickerModal.tsx (新規)

- 候補 list を表示、各候補に `data-testid="effect-pick-cand-${uid}"`
- 任意効果 (nMin===0) のみ「対象を選ばない」button + data-testid="effect-picker-skip"
- 必須効果ではスキップ button 非表示
