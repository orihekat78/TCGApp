## 概要

engine-extension #2 (2026-06-05) で追加した `charModifyLevel` verb は `mutate/char.ts`
`modifyLevel` で `turnEffects['lvlMod_turn']` / `lvlMod_contact` に積む。しかし turn-end の
唯一の reset 経路 `clearTurnEffects` (mutate/char.ts, scope:'turn') は
`apMod_turn/lpMod_turn/apMod_contact/lpMod_contact/grantedKeywords` のみ delete し、
**`lvlMod_turn` / `lvlMod_contact` を削除しない**。

結果、`scope:'turn'`「ターン終了時までレベル±N」が事実上 **permanent** 化。
`read.char.level` と filter level (candidates.ts の levelMin/Max 判定) の両方に残留し、
翌ターン以降の対象判定・logic 勝負 (フロアルール 2.5A) にも波及する。

## 影響カード (6 枚)

B07103/B07103P/B05066/B05066P/B07093/B07093P — いずれも a2 が
`charModifyLevel {delta:-1, scope:'turn', side:'opp', max:1}` (相手キャラを 1 枚 ターン終了時までレベル-1)。
DSL の符号化自体は text-faithful。engine の turn-end cleanup 脱落が原因 (カード修正不要)。

## 再現

`flow/turn.ts:75-78` が両プレイヤー scene に `clearTurnEffects(_, 'turn')` を呼ぶが lvlMod を残す。
`grep lvlMod` 全件で他に clear 経路が無いことを確認済。

## 修正 (engine バグ修正 / additive)

`clearTurnEffects` の 'turn' 分岐に `delete te['lvlMod_turn']; delete te['lvlMod_contact'];` 追加
(ap/lp の turn/contact と対称化)。lvlMod 未使用キャラは不変。

## 防止策

新しい turnEffects key (lvlMod 等) を `mutate/char.ts` に追加したら、必ず同ファイルの
`clearTurnEffects` にも対応する delete を追加する。e2e は「適用 → ターン跨ぎ → 解除」まで検証する
(既存 charModifyLevel e2e は同一ターン内のみで未検出だった)。
