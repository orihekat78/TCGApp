## 期待動作

宣言コスト〚FILE から n 枚〛(`fileFrom`) で支払ったカードは FILE 所有者の **リムーブエリアへ移動**
する (rules/03)。リムーブエリアはリフレッシュ (rules/14) の母数なので、消失するとデッキ枯渇敗北の
判定が公式と乖離する。canPay は「全部行えなければ使用不可」(rules/21) に従い、popTop が skip する
アシストパートナーを **数えない** で判定する。

## 実動作 (修正前)

1. pay: `mutate.file.popTop()` の戻り値を破棄 → カードがどのエリアにも存在しなくなる (消失)
2. canPay: `file.length >= n` (アシストパートナー込み) → FILE=[アシストパートナーのみ] で
   canPay=true だが実際は 1 枚も支払えない → コスト未払いのまま効果解決 (BUG-116 同型)

## RCA

pay 実装時に「FILE から取り除く」だけ書いて「どこへ置くか」を書き漏らし、テストも枚数減少のみ
assert していた。canPay は popTop の skip 仕様 (rules/12 由来) を知らない素朴な length 比較。

## 修正

- pay.ts `fileFrom`: popped cardIds を `mutate.remove.add` で remove へ。paidItems に ids 記録
- evaluate.ts `fileFrom`: `file.filter(f => f.type !== 'assisted-partner').length >= n`
- 回帰テスト: pay (remove へ移動) / canPay (パートナーのみ→false) を追加

## 影響カード

- B05037 (既実装で fileFrom cost 使用)。スモーク/実機では「FILE コストカードがリムーブに無い」
  形で顕在化するはずだったが、リフレッシュ到達前にゲームが終わる対戦が多く未検出だった
