## 状況

User が D08003 Pilot Stage 3 を実機 verify 中、CPU (opp) のターンで人間 (自) の証拠が
予期せず +1 増えるのを発見。痕跡が「自・相」両方とも「未発見」のままだった点から
refresh-penalty (rules/14) ではないと特定。

## 期待動作

card def の `{ player: 'self' }` は card owner (= source card の所有プレイヤー) を指す。
- 人間の D11003 enter trigger → 人間 evidence +1
- CPU の D11003 enter trigger → **CPU evidence +1**

## 実動作

- 人間の D11003 enter trigger → 人間 evidence +1 (正しい)
- CPU の D11003 enter trigger → **人間 evidence +1 (誤り)**

`player: 'self'` リテラルが ctx.source.player を介さず、絶対 ID 'self' = 人間と解釈
される。CPU 側 card のすべての `player: 'self'` 効果が人間に適用、`player: 'opp'`
すべての効果が CPU に適用される (符号反転)。

## RCA

`atom-handlers.ts` 全 verb で `const p = a.player as Player;` (literal 取り出し)
を使用。`cond/eval.ts:resolvePlayer` のような ctx.source.player ベースの relative
resolution が atom 側に **未実装**。

- card DSL の慣習: `'self'` = source card の owner、`'opp'` = opp-of-owner
- engine 内部の型: `Player = 'self' | 'opp'` (絶対 ID)
- → リテラル解釈すると CPU 側でも 'self' = 人間に効果が向かう

## 影響範囲

CPU 側で trigger される全 atom の player 引数:
- evidenceGain, evidenceLose, evidenceFlip, evidenceToHand
- draw, discard, mill, fileAdd, filePopToHand, handAddFromRemove
- partnerAssist, partnerSetState, partnerSolveCase, caseToResolved
- sceneSwitch (player 抽出箇所), deckRevealUntil, deckToBottomBound, deckShuffle, souza
- 約 30+ 箇所

CPU が trigger を起こさない / 起こしても CPU が play しない card 群があるため
smoke test では露見しなかった (AI heuristic が D11003/D08013/D08021 enter 系を
あまり play しなかった可能性)。

## 修正方針

### Step 1: ヘルパー追加

`atom-handlers.ts` 冒頭に `resolvePlayer(p, ctx)` を追加:

```typescript
function resolvePlayer(p: unknown, ctx: EffectCtx): Player {
  if (p === 'self') return ctx.source.player as Player;
  if (p === 'opp')  return ctx.source.player === 'self' ? 'opp' : 'self';
  // 既に絶対 ID で渡されている場合 (mutate path 等) はそのまま
  if (p === 'p1' || p === 'p2') return p as Player;
  // fallback: ctx.source.player
  return ctx.source.player as Player;
}
```

### Step 2: 全 verb 置換

`const X = a.player as Player;` を `const X = resolvePlayer(a.player, ctx);` に
一括置換 (30+ 箇所)。

### Step 3: 各 verb の player 抽出箇所も統一

- `mutate.log.append(..., { player: a.player as Player, ... })` → `resolvePlayer(a.player, ctx)`
- short form 展開時の `defaultPickTarget(undefined, ..., p, ...)` の p も resolved
- side パラメタ `srSide` (sceneRemove 短縮形) は別 (side: 'self'|'opp'|'either') が source.player relative

### Step 4: 回帰テスト追加

`tests/engine/effect/player-resolution.test.ts` に全 atom × CPU/人間 side のマトリクス:
- evidenceGain, draw, discard, evidenceToHand, handAddFromRemove, mill, fileAdd
- 各 verb で CPU 側 enter trigger → CPU の state が更新されることを確認

### Step 5: 既存テスト互換性確認

- 人間側 (selfDelta) test はそのまま通る (ctx.source.player='self' → 'self' resolved = 'self' literal と同じ)
- CPU 側を hardcode で `player: 'opp'` と書いていた test があれば修正 (現状 card 側にそのような例なし)

## 防止策

- atom-handlers.ts の各 verb に「ctx.source.player を必ず通すこと」を comment + lint で明示
- `tests/engine/effect/player-resolution-matrix.test.ts` を必須 regression として追加
- card DSL spec (`engine-api-atom-verbs.md`) に 'self'/'opp' = relative-to-owner を明記
