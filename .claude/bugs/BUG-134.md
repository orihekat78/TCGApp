## scan 結論 (2026-06-22 — ユーザー指示「scan → 実害あれば修正」)

probe (実 engine) で機構を確認: `effect:declared` 以外の全 hook の triggered entry pick は
**queue 時 (発動時) の盤面で候補確定**し、先行 entry の解決後も後続 entry の候補は再評価されない。
co-fire する 2 entry の pick 候補は両方とも発動時盤面で固定される (characterization test で pin)。

実害を 2 形態に分類して出荷カードを scan:

- **害B (先行が候補を「追加」→ 後続が新候補を選べない)** = 真の rules 違反:
  turn-end (`phase:end:start`) で `sceneEnter` (現場へ追加) する出荷カードが **0 件** のため
  **構造的に実在しない**。enter-batch (疾風/複数登場) も add+pick の co-fire 組合せは未発見。

- **害A (先行が候補を「削除/スタン」→ 後続 pre-resolved が stale target)**:
  多 copy の turn-end 削除 pick (例 B07094 either-side 削除) で原理上発生しうるが、atom handler の
  splice 防御 (BUG-132 dedup guard) により**適用結果は rules-correct な no-op** (rules/25「同時リムーブで
  両方消えていれば条件不成立」と一致)。不正状態 (複製・crash) は生じない。残差は「2体目の削除/スタンが
  浪費されうる」AI 最適性 / human の stale 候補表示という狭い tail。manifesting カード (B07094 等) は
  **MVP smoke デッキ (CT-D08/CT-D11) 外**なので smoke baseline 影響もなし。

判定: **rules 違反の実害なし**。engine 全面の遅延 substitute 一般化 (declaredReaction 方式を全 triggered
entry へ拡張) は 骨格凍結原則の risk (core pick 解決経路の全面改変 + AI 挙動変化) に対し過大なため見送る。
将来 human の stale 候補表示を改善する場合の最小手は「pick 解決時 (surface / drain 両経路) に
pending.candidates を現盤面で再 filter」(害A の stale を落とす)。

回帰ガード: `tests/engine/effect/bug-134-cofire-pick-staleness.test.ts` (機構 pin + guard 不変条件)。

## 概要

triggered.ts handleHook は queue 時に `resolveEffectPicks` で pick 候補 (AI は選択まで) と
{dyn} を確定する。rules/15「未解決効果に『〜の場合』…は**解決時**に参照/選択」+ rules/25
「効果解決時の状態を参照」に照らすと、**同時に複数 entry が queue され、先行 entry の解決が
盤面を変える場合**に後続 entry の候補が古い盤面で固定される構造が全 hook に存在する。

## 実害条件 (狭い)

同一 hook 発火で複数 entry が同時 queue され (例: 同時登場 2 枚の【登場時】pick)、
先行解決が後続の候補集合を変える場合のみ。単発 trigger では queue→解決が即時で乖離しない。

## 修正方針 (defer)

declaredReaction と同じ「raw queue + runOne 遅延 substitute」を全 triggered entry に一般化する。
AI smoke baseline がずれる可能性があるため、専用 wave で baseline 差分を検証して導入する。
