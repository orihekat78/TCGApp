# BUG-173: 効果解決後の ActionsPanel 永久ロック

## 期待動作
効果解決が完了したら (未解決 pending/resolving が無くなったら) main action を再開できる
(rules/05 割り込み禁止は「解決中」のみ)。

## 実動作 (修正前)
`pendingEffects` は resolved/cancelled entry を **prune しない累積配列** (resolve/stack.ts 設計、
BUG-151 で確立した「UI は state フィルタで読む」規約)。しかし `selectInteractionLocked`
(2026-06-19 Task1 8a0af5b1) は `pendingEffects.length > 0` の**無フィルタ判定** — 効果を 1 つでも
解決した後、そのゲーム中ずっと ActionsPanel がロックされる (手札の使用/宣言/アクション等の
main action 全部が不能)。B01058 手札使用後の実機で再現。

## なぜ今まで見えなかったか
- AI/probe 経路は panel を経由しない (dispatch 直呼び)。
- playwright E2E の多くも dispatch 直 or 1 アクション完結シナリオ。
- human 実戦の連続 main action (効果持ちカード使用 → 次の行動) だけが踏む。

## 修正
`pendingEffects.some(e => e.state === 'pending' || e.state === 'resolving')` に変更
(TopBar の効果スタック表示と同じ BUG-151 フィルタ規約)。cancelled も非ロック (解決不要 entry)。

## 関連ファイル
- src/ui/state/interactionLock.ts

## 水平展開
`pendingEffects.length` を無フィルタで読む他 site を grep → TopBar (Playmat.tsx) は
filter 済 / useEngineDispatch は id 検索のみ — 他に該当なし。

## 防止策
- BUG-151 規約 (「pendingEffects は必ず state フィルタで読む」) の lint 化検討
  (`.length` 直読みを scripts/lint-* で検出) — 月次 audit 課題。
