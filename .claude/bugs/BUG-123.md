## 概要

リムーブエリア・手札 (= **イベントも存在しうるエリア**) からカードを選ぶ pick で、公式テキストが
「**キャラ**」を指定しているのに filter が `color` (± `levelMax`) のみで `kind:'character'` を欠いていた。

イベントは **色とレベルを持つ** (特徴のみ traits:[] で空) ため、同色・同レベル帯のイベントが
`matchOneFilter` で候補に混入する。テキストの語義 (キャラ限定) と画面処理が乖離する text-faithfulness バグ。

> 対比: `trait` filter (例 trait:'少年探偵団') は全イベントが traits:[] のため本質的にイベントを除外する
> ので安全。`cardName` filter も同様。**色 / レベルのみ**の filter が危険。

## 影響カード (3 ability / 4 ファイル)

| card / abil | エリア | テキスト | 修正前 filter |
|------|-------|---------|--------------|
| B01094 a1 ①（+B01094P spread） | remove | 「【黄】のキャラを1枚まで…手札に加える」 | `{ color:'黄' }` |
| B09044 a1（hand sceneEnter） | hand | 「手札からレベル6以下の【青】か【白】のキャラを1枚まで登場」 | `{ color:['青','白'], levelMax:6 }` |
| B09044 a2（handAddFromRemove） | remove | 「リムーブの…レベル6以下の【青】か【白】のキャラを1枚まで…手札に」 | `{ color:['青','白'], levelMax:6 }` |

特に B09044 a1 は sceneEnter なので、誤って選んだイベントを現場に登場させようとする不正動作になる。

## 修正

各 filter に `kind: 'character'` を追加 (card 修正のみ・engine 不変)。`kind` は matchOneFilter /
targetFilterToPredicate 両経路で評価済 (BUG-118)。B01013「LP0の【青】の**キャラ**」が既に
`kind:'character'` を持つ正しいパターンと統一。B01094P は `{...B01094}` spread のため base 修正で追従。

## 水平展開調査 (全 catalog-reuse + ct-p01〜p09)

色 filter で `kind` 欠落の全 35 箇所を grep → 内訳:
- **scene area / sceneHas** (char 専用エリア): D02013/B01088/B02046/B02061/B02040/B03011/B09088 a1/B09093/D06006 等 → kind 不要・安全
- **deckRevealUntil** でテキスト「【色】の**カード**」: D01013 一族 / B01016/34/55/72/90 一族 → kind 不要・安全
- **deckRevealUntil** でテキスト「キャラ」: B01013/B01053/D11019 → 既に `kind:'character'` 保持・正
- **trait / cardName 併用** (イベント除外される): B04080/B09085/PR235/D11012/B02009/B03004/B04025/B04071/B05055/B05083/B09088 a2 → 安全
- **イベントを意図** (kind:'event'): B04009 → 正
- **remove/hand area で色のみ・テキストはキャラ**: **B01094 / B09044 a1 / B09044 a2** ← 本 BUG (3 件のみ)

handAddFromRemove / handAddFromDeck / sceneEnter(from hand) / discard(cost) を全列挙し、
no-filter の hand pick は全て removeFromHand コスト (テキスト「手札を1枚リムーブ」= 任意札) で安全と確認。

## 検証

  `kind:'character'` を持つことを構造検証 + remove に同色イベント decoy を置いて candidates が
  キャラのみ返すことを behavioral 検証。
- typecheck clean / 全 vitest pass / 既存 e2e 回帰 0。

## 教訓 (BUG-122 の続き)

「型に field が在る≠評価する」(BUG-117/118) と「値の格納先を確認」(BUG-122) に加え、
**filter のエリアとカード種別の整合**を必ず確認する。イベントを含むエリア (hand/remove/deck) から
「キャラ」を選ぶ pick は `kind:'character'` 必須 (scene area は char 専用なので不要)。
