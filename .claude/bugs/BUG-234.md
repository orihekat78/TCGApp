## 期待値

Gitがcleanと判定するcheckoutは、`core.autocrlf`設定やworktree EOLに関係なく
wave scope gateでも変更0件になる。pre-existing本文hashもEOL差だけでは変化しない。

## 実際値

`core.autocrlf=true`のclean checkoutでGit statusはcleanだったが、scope gateは
769 pathを変更扱いした。pre-existing `contentSha256`もraw CRLFに依存した。
autocrlf/hash修正前の`f4` clean scopeは219 errorsで、raw hash 204件に加え、
dirty mainだけに存在するpre-existing ownership 15件を未変更として拒否した。

## RCA

`collectChangedPaths`が`git -c core.autocrlf=false diff`を実行し、repository設定を
上書きしていた。LF blobからCRLFへcheckoutされた正常なworktreeを強制設定下では
本文差と判定した。pre-existing hashもraw bytesを直接SHA-256へ渡していた。
さらにownership完全一致検査とhash検証がpre-existing snapshot entryにも無条件適用され、
base以降または現在のcloneで変更されていない保護対象まで変更必須としていた。

## 水平調査

強制`core.autocrlf=false`はscope collector内のtracked/untracked取得2経路だけだった。
manifestのpre-existing hashは同じscript内の1経路で検証され、既存hashはraw EOL由来だった。

## 再発防止

Git diffはrepositoryの`core.autocrlf`を尊重する。UTF-8 pre-existing本文は
CRLF/CRをLFへ正規化してからSHA-256化する。実Gitの`core.autocrlf=true` repoで
LF commit→CRLF checkout→Git status clean→scope変更0件を回帰する。
hashはLF/CRLF/CR同値と実内容差を固定し、manifest既存値も同じ規則で再計算する。
pre-existing ownershipはchanged pathに無い場合だけ許容し、hash検証もchanged path限定にする。
通常ownerのownership-not-changedと、changed pre-existingのhash不一致は失敗を維持する。
