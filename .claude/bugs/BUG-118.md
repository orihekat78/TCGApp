## 概要

`src/engine/target/candidates.ts` `matchOneFilter` (target pick 候補列挙の正準経路) が
`filter.kind` ('character' | 'event') を **一切評価しない**。
cardId/cardName/trait/color/keyword/ap/lp/level/hasSetCards/custom のみ判定していた。

`kind` を honor する別経路 `targetFilterToPredicate` (atom-handlers.ts) は deckRevealUntil 専用で、
handAddFromRemove 等の候補列挙はそちらを通らず matchOneFilter を通る。さらに `kind` は当時
TargetFilter 型に **存在しない** field で、card args が `unknown` 型のため typecheck も通過していた。

## 影響カード

- **B04009 灰原哀**: 【宣言】「リムーブの【青】の**イベント**を1枚まで手札に加える」
  (`handAddFromRemove`, `filter:{color:'青', kind:'event'}`) → kind 黙殺でリムーブの
  **青キャラも候補化**。テキストに反して「青のキャラ」を手札に戻せてしまう。
- 水平展開: `filter.kind` を使う他カードは全て deckRevealUntil (targetFilterToPredicate, 評価済) →
  matchOneFilter 経路で kind を使うのは B04009 のみ (全 .ts grep 確認)。

## 修正 (engine バグ修正 / additive)

1. `kind?: 'character' | 'event'` を `TargetFilter` 型 (effect.ts) に昇格。
2. `matchOneFilter` に `if (filter.kind !== undefined && d?.kind !== filter.kind) return false;` 追加。
3. `targetFilterToPredicate` の旧キャスト (`filter as TargetFilter & {kind?}`) を `filter.kind` に簡素化。

kind 未使用カードは不変 (additive)。

  候補が D08024 のみ (D08009 除外) を実機 assert。修正前 fail (`["D08024","D08009"]`) → 修正後 pass。

## 防止策

declarative filter の field は型と評価経路の両方に在って初めて有効。TargetFilter に field を足したら
matchOneFilter / targetFilterToPredicate の両経路に評価を入れる (BUG-117 と同教訓)。
