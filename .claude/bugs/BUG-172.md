# BUG-172: declared-ability:ability picker のクリック面不在

## 期待動作
宣言能力を 2 つ以上持つキャラを選択後、どの能力を使うかを player が選べる。

## 実動作 (修正前)
`runDeclaredAbilityFlow` は `picker.start({candidates: ['a1','a2'], purpose:'declared-ability:ability'})`
を await するが、Playmat の picking UI は **盤面 uid の candidate 強調のみ** を描画 — ability id には
クリック面が存在せず、Promise が永久 pending (status 表示「宣言能力 の対象を選択してください。」の
まま操作不能)。B09108 (宣言 2 つ持ち) の playwright 実機で hang を確認。

## 影響範囲 (水平展開)
既出荷の宣言能力 2 つ持ち: B05028/B05028P・B05045・B05074・B06069/B06069P ほか
(`grep -c "type: 'declared'"` ≥2 の全カード) — **human 経路は全て同 hang だった** (AI 経路は
policy 直 dispatch のため無影響。human 実戦未投入で未発覚)。本修正で一括解消。

## 修正
ability 択を ChoicePickerModal (BUG-108 の択一 modal) に差し替え — options = 各 ability の
`description` 全文 (画面文言 = カードテキスト 1対1)。source cardId 解決 helper
`resolveDeclaredSourceCardId` を新設 (scene / case。hand:/partnerMR: は enumerator 未対応で対象外)。

## 関連ファイル
- src/ui/hooks/useActionsPanelFlow/flows.ts (runDeclaredAbilityFlow step2)

## 残 nit
- rider (on-set-host) ability は host def に無いため択一/confirm の文言が「能力 (a3)」fallback
  になる (B07014 実機で確認、機能は正常) — rider description 表示は PA宣言19 batch で
  findDeclaredAbility 経由の解決に統一する際に対応。

## 防止策
- picker.start の candidates は「盤面クリックで選べる uid」のみ許可 (ability id / index 等の
  抽象値は modal 系 picker を使う) — ui-action-flows spec に規約追記候補。
