## ユーザー指摘

> ログには証拠→手札となっていますが、証拠 -1・手札 +1 にはなっていない

(BUG-076 commit `8d18c4f` 適用後、Playwright 同等の実機検証で発覚)

## 期待動作

D08013 a1 step 2 evidenceToHand で:

1. modal で証拠候補から 1 枚選択
2. **証拠エリアから該当 cardId を削除 (-1)**
3. **選択した cardId を手札に追加 (+1)**
4. log に `効果: 証拠 → 手札` 記録

## 実動作

- modal は表示される (BUG-075 / BUG-076 修正効果で OK)
- 選択後、log に `効果: 証拠 → 手札` は出る (atom-handler の log.append は走った)
- **しかし証拠エリアは -1 されず、手札も +1 されない**
- 動作なし (moved=false で何もしない path)

## RCA 仮説

`src/engine/effect/atom-handlers.ts:evidenceToHand` の処理:

```typescript
const target = normalizeTargetToString(a.target); // [cardId] → cardId
const list = s.players[p].evidence;
const idx = list.findIndex(e => e.cardId === target);
if (idx !== -1) { ... } else { moved = false }
```

仮説 1: `target` に渡される cardId が **evidence list の e.cardId と一致しない**。

可能性:
- `cand.cardId` が UI 表示用の何か (例: `'card-back'`) で、内部の evidence cardId と異なる
- effectPickResolve dispatch で synthetic uid (`evidence:self:0`) から cardId 逆引きする際、間違った cardId を取得
- evidence の faceUp=false 時に cardId が隠蔽されている (とは限らないが、要確認)

仮説 2: dispatch の draft state と atom-handler の state が **immer の関係で別 instance**、findIndex で参照する list が古い

## 修正方針 (RCA 後)

仮説に応じて:
- cand.cardId が間違っている → resolve-picks の evidence kind 処理を見直し
- findIndex 不一致 → atom-handler の比較 logic 見直し (cardId 比較ではなく index 比較に変更等)
- evidence の faceUp 隠蔽 → そもそも evidenceToHand が表向きにする処理が必要 (rules/10 参照)
