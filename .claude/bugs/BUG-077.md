## ユーザー指摘

> ログには証拠→手札となっていますが、証拠 -1・手札 +1 にはなっていない

(BUG-076 commit `8d18c4f` 適用後、Playwright 同等の実機検証で発覚)

## 期待動作

D08013 a1 step 2 evidenceToHand で:

1. modal で証拠候補から 1 枚選択
2. **証拠エリアから該当 cardId を削除 (-1)**
3. **選択した cardId を手札に追加 (+1)**
4. log に `効果: 証拠 → 手札` 記録

## 実動作

- modal は表示される (BUG-075 / BUG-076 修正効果で OK)
- 選択後、log に `効果: 証拠 → 手札` は出る (atom-handler の log.append は走った)
- **しかし証拠エリアは -1 されず、手札も +1 されない**
- 動作なし (moved=false で何もしない path)

### Phase 2 (2026-05-23 PM): **真の root cause 発見 — 初期 walk で step 3 が step 2 の側チャネルを横取り**

Playwright trace で evidenceToHand entry に `console.log` を仕込み、D08013 a1 を実機実行
した結果、`pendingEffectPick.atomVerb === 'discard'` (step 3 の hand pick) になっていた
ことを発見。期待は `evidenceToHand` (step 2)。

#### 実際のデータフロー (Playwright trace 結果)

`triggered.ts` が `resolveEffectPicks(state, sequence, ctx, {humanChooser: true})` で
sequence 全体を初期 walk する際:

| step | 内容 | 初期 walk 時点の cands | substituteAtomPick の side-channel set |
| --- | --- | --- | --- |
| 1 | `evidenceGain (n=1)` | (no pick) | 関与なし |
| 2 | `evidenceToHand (target=pick evidence)` | 0 件 (`state.players.self.evidence` は空) | cardLikeCands=0 → set せず |
| 3 | `discard (target=pick hand)` | 5 件 (hand の 5 枚) | **side-channel に set (atomVerb='discard')** |

→ runtime drain で:

- step 1 実行で evidence +1
- step 2 awaiting-pick → tryRePickFromAtom → `__pendingEffectPickSide` が step 3 で set 済 → **bail (no-op)**
- step 3 awaiting-pick → 同じく bail

結果、UI に表示される modal は step 3 の hand pick だが、ユーザーは step 2 の evidence pick だと
思って evidence と同名のカードを選択。実際は discard が走り、選んだ hand card が remove へ送られ、
evidence は触られず終わる。log は step 2 (`effect:evidenceToHand:awaiting-pick`) と step 3
(`effect:discard:awaiting-pick`) の双方が出るので「ログには出る」状態。

### 修正 (commit TBD)

`src/engine/effect/resolve-picks.ts`:

1. `ResolveEffectPicksOpts` に `_fromAtomHandler?: boolean` を追加。
   - 初期 walk (triggered.ts → resolveEffectPicks) では false (default)
   - runtime atom-handler awaiting-pick (tryRePickFromAtom) では true
2. `tryRePickFromAtom` 内の `substituteAtomPick` 呼出に `_fromAtomHandler: true` を渡す。
3. `substituteAtomPick` の `humanChooser` 分岐に Pattern B 抑止条件を追加:

   ```ts
   if (isPatternB && !opts._fromAtomHandler) {
     return atom as Effect;  // 初期 walk は Pattern B の side-channel set を skip
   }
   ```

   → Pattern B は **runtime tryRePickFromAtom 経由でのみ** side-channel set される。
   → 初期 walk で sequence の後続 step が先行 step の target を横取りする問題を解消。
   → Pattern A は runtime に awaiting-pick path が無いため、引き続き初期 walk で set。

### 後続課題 → BUG-078

step 2 解決後、step 3 (discard) modal が表示されない問題は別途 BUG-078 を起票。
原因: effectPickResolve dispatch が resolved step 2 atom を単発 queue するだけで、
sequence の残り step を再 queue する仕組みが無い。

### 元仮説 (RCA で却下)

`src/engine/effect/atom-handlers.ts:evidenceToHand` の処理:

```typescript
const target = normalizeTargetToString(a.target); // [cardId] → cardId
const list = s.players[p].evidence;
const idx = list.findIndex(e => e.cardId === target);
if (idx !== -1) { ... } else { moved = false }
```

仮説 1: `target` に渡される cardId が **evidence list の e.cardId と一致しない**。

可能性:

- `cand.cardId` が UI 表示用の何か (例: `'card-back'`) で、内部の evidence cardId と異なる
- effectPickResolve dispatch で synthetic uid (`evidence:self:0`) から cardId 逆引きする際、間違った cardId を取得
- evidence の faceUp=false 時に cardId が隠蔽されている (とは限らないが、要確認)

仮説 2: dispatch の draft state と atom-handler の state が **immer の関係で別 instance**、findIndex で参照する list が古い
