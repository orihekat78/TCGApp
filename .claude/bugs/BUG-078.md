## 状況

BUG-077 修正後 Playwright で D08013 a1 を実機検証した際、step 2 までは正しく解決
されるが step 3 の discard modal が出ない。

## 期待動作

D08013 a1 = sequence([evidenceGain, choice([evidenceToHand]), choice([discard])])
の 3 step を順次:

1. step 1 evidenceGain: 自動実行 (+1 evidence)
2. step 2 evidenceToHand: modal → ユーザー選択 → evidence -1 / hand +1 (BUG-077 で修正済)
3. **step 3 discard: modal 表示 → ユーザー選択 → hand -1 / remove +1**

## 実動作

- step 1 OK
- step 2 OK (BUG-077 修正後)
- **step 3 modal 未表示**: 解決後 pendingEffectPick=null、step 3 は queue に残らない

## RCA 仮説

step 2 awaiting-pick 時、sequence の `runEffect` は step 2 が awaiting-pick に
なっても sequence を継続し step 3 も実行する。step 3 は side-channel が
step 2 で set 済みなので tryRePickFromAtom で bail。`effect:discard:awaiting-pick`
log は記録されるが、step 3 自体は no-op 完了扱い。

→ 元 sequence (entry e_1) の state は 'resolved' に遷移。step 3 は再 queue されない。

その後ユーザーが step 2 modal を解決すると effectPickResolve dispatch が走り、
**step 2 の resolved atom 単体** が新規 queue + run される (`engineEvent.queue`
+ `runAllUntilEmpty`)。これは step 2 atom 1 つだけ実行する単発操作で、
step 3 を再開する仕組みは無い。

## 関連ファイル

- `src/engine/effect/atom-handlers.ts:251-282` (evidenceToHand awaiting-pick + tryRePickFromAtom)
- `src/engine/effect/atom-handlers.ts:162-180` (discard awaiting-pick + tryRePickFromAtom)
- `src/engine/effect/resolver.ts:30-45` (sequence は awaiting-pick でも継続実行)
- `src/ui/hooks/useEngineDispatch.ts:effectPickResolve` (resolved atom 単体 queue)

## 修正方針候補

### Option A: effectPickResolve で残り sequence を再構築

resolved step 2 atom を queue する代わりに、元 ability effect の残り step を
含む sequence を queue する。要追加情報: original effect, current step index。

### Option B: atom-handler awaiting-pick path で「pending sequence」を遅延 queue

step 2 awaiting-pick 時、tryRePickFromAtom で side-channel set すると同時に
「残り sequence step」を別 side-channel に保存。effectPickResolve 後の post-drain で
残り step を新規 queue。

### Option C: effectPickResolve 後、original effect を最初から再 walk

resolved atom を queue ではなく、ability effect 全体を再 walk して、既に解決済の
step は skip、step 2 は resolved 状態で実行、step 3 以降を新規 queue。要 step
完了状態管理。

→ Option A が最小工数。current step index は pending.atomVerb / atomArgs から
逆引きで特定可能。

## 検証手順

1. Playwright で D08013 a1 を実機実行 (BUG-077 と同じ流れ)
2. step 2 modal で証拠選択 → 解決
3. **step 3 modal が表示されること** を verify (現状 表示されない)
4. step 3 で hand カード選択 → hand -1 / remove +1 を verify
