## 仕様 (rules/13, 20, 26)

D11019 a1:「デッキ上からレベル4以下【黄】のキャラが出るまで1枚ずつ公開し、それを登場させる。
残りをデッキの下に移しシャッフル。リムーブに【黄】20枚以上ならそのキャラに突撃[事件]を付与。」

## 期待動作

deckRevealUntil でマッチした黄キャラを sceneEnter で現場に登場させる。

## 実動作

**マッチしても現場に登場しない**。ログは `matched=D11013` だが「効果:登場」が無く scene 空。

## RCA (bind ref キー規約の不一致)

- `deckRevealUntil` は `a.bindMatch='$matched'` を **そのまま** `ctx.bindings['$matched']` ($込み) に格納
  (atom-handlers.ts deckRevealUntil case)。`$revealed` も同様。
- 一方 `resolveBindRef('$matched.cardId')` は `key = value.slice(1, dot) = 'matched'` ($**無し**) で
  `ctx.bindings['matched']` を lookup → undefined → 未解決の `'$matched.cardId'` を返す。
- `sceneEnter` は `cardId.startsWith('$')` を検出して **silent no-op return** → 登場せず。
- 加えて sceneEnter の uid write-back も `'$matched'.slice(1)='matched'` でキー不一致 →
  `$matched.uid` (charGrantKeyword の対象) も解決不能だった。
- キー規約が混在: `contact.ts` は `'contact'` ($無し) で格納 (resolveBindRef と一致して動作)、
  deck-reveal 系は `'$matched'/'$revealed'` ($込み)。deckToBottomBound (a.bindKey 直読) と
  bound 条件 (key '$matched') は $込みで一致するため動いていた。resolveBindRef だけが非対称。

## 修正 (Option B: resolveBindRef に $込みキー fallback / Workflow 8 agents で安全性確定)

1. `atom-handlers.ts resolveBindRef`: stripped key ($無し) で失敗時、`value.slice(0,dot)` ($込み) を
   fallback で lookup。純粋に additive — contact 等 ($無し格納) は従来通り stripped key で解決。
2. `atom-handlers.ts sceneEnter` uid write-back: `'matched'` と `'$matched'` の両キーを試して
   登場キャラの新 uid を $matched binding に書き戻し ($matched.uid = charGrantKeyword 用)。

## 水平展開
