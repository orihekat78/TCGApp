## 概要

「**このキャラをスリープさせ(…)てもよい。そうした場合、X**」型の能力は、効果解決時に self が既にスリープなら
optional 自体を行えない (= X も起きない)。公式qAndA (PR138/PR144/B04049):「スリープ状態で登場した場合
『このキャラをスリープさせ…てもよい』はできますか？ → **いいえ。スリープさせることができないので行えません**」。
これは **一般裁定** (B04049 が理由を一般機構として明記)。

エンジンの旧挙動: `sceneSetState{$self,sleep}` ハンドラは冪等に呼ぶだけで、対象が既にスリープでも
`__chainStepNoApply` を立てない (chain を break しない)。→ already-sleep でも discard + reanimate 等が
実行できてしまい qAndA 違反。Condition union に self の状態を見る条件が不在で engine変更0 では gate 不能だった。

## 期待動作 / 実動作

- 期待: 能力は必ず発動し、解決時 self が active でなければ optional 自体不可
  (sleep/stun とも discard / reanimate / activate は発生しない)
- 旧実動作: self が sleep でも optional を取れ、後続効果が走る

## 修正方針 (engine 変更あり — self-state condition 追加)

1. **engine**: `Condition` union に `charStateIs{ref:TargetingRef, state}` 追加 (effect.ts / cond/eval.ts case /
   CONDITION_KIND_MAP / taskA-validate-specs.cjs CONDS の 4点同期)。`ref` 解決は apAtLeast 同流儀。
2. **card**: mandatory trigger は listener で常に queue し、effect を
   `conditional if charStateIs(self,active) then optional(...)` にする。
   - BUG-161 前の旧実装は両枝を prewalk したため ability.condition を使ったが、発動自体を落とし裁定違反だった。
   - 既存の印字 condition (partnerColor 赤 / turn self / fileAtLeast 8) は ability.condition に維持する。
3. **active のみ実行可**。sleep/stun はどちらも self を sleep へ実移動できないため optional を出さない。
   これは「sleep 中の self を stun にできる」別効果の裁定とは別である。
