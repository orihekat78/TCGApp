## 概要

PR138《ラム》の a1 は `optional{ chain[ sceneSetState{uid:'$self',state:'sleep'}, discard{n:1},
sceneEnter(reanimate) ] }` として **既に出荷済** (src/cards/pr-01/PR138.ts、_reuse 登録、ALL_CARDS live)。

公式テキスト: 「【登場時】このキャラをスリープさせ、手札を1枚リムーブしてもよい。そうした場合、…登場させる。」
公式qAndA (cards-data TSV): 「Q：「スリープ状態で登場させる」効果によって登場した場合など、効果を解決する際に
このキャラがスリープ状態の場合は『このキャラをスリープさせ、手札を1枚リムーブしてもよい。』はできますか？
**A：いいえ、できません。**」

エンジン実動作: `sceneSetState` ハンドラ (atom-handlers.ts:889) は `mutate.scene.setState` を**冪等に**呼ぶだけで、
対象が既にスリープでも `__chainStepNoApply` を立てない (resolve-picks.ts の no-candidate path のみが立てる)。
→ PR138 が **already-sleep で登場** した場合 (別カードの「スリープ状態で登場させる」効果でこのカードが対象に
なった等) でも chain は break せず、discard + reanimate が**実行できてしまう** → qAndA 違反。

## 期待動作 / 実動作

- 期待: 解決時に self が sleep なら optional 自体が不可 (discard / reanimate ともに発生しない)
- 実動作: self が sleep でも optional を取れ、discard + reanimate が走る

## 影響範囲 / 到達性

- 到達条件: 別カードが PR138 (特徴[黒ずくめの組織]、lv7) を「スリープ状態で登場させる」こと。MVP/現プールでの
  該当カード有無は未調査 (到達稀)。エンジンは全状態で正しくあるべきという原則から bug として記録。
- 同パターンの shipped precedent: B09013 (「このキャラをスリープさせてもよい」を同形 optional{chain[sceneSetState$self,…]}
  で実装)。ただし B09013 の qAndA は【ターン1】消費の話で、already-sleep 不可を**明示していない** → 近似許容。
  PR138 は **明示qAndAで禁止** されている点が決定的に異なる。

## 修正方針 (DEFER — engine変更必要)

engine変更0 では gate 不能 (Condition union に self/source の状態を見る条件が**不在**)。修正には新 engine 機構が必要:

- 案A: `charStateIs { ref:TargetingRef; state:'active'|'sleep'|'stun' }` 条件を追加し、PR138 a1 を
  `condition:{kind:'charStateIs',ref:'$self',state:'active'}` で ability-level gate (sleep時は能力が発動扱いに
  なるが optional surface が出ない = 「できません」と等価)。3点 whitelist 同期 + cond/eval.ts 実装。
- 案B: sceneSetState を chain step で「既に同状態なら no-apply」にする案は **B09013 の出荷挙動を壊す**ため不可。
- → 案A を将来の micro-cluster (self-state 条件追加) で実施。それまで PR138 は現状維持 (latent、稀)。

## 防止策 / 教訓

- **certify+adversarial-verify が green を返しても意味等価は自前で 1対1 突合する** (card-wave SKILL §2、教訓 B01011)。
  本件は verify lens が sceneSetState の冪等性 (chain を break しない) と qAndA を突合し損ねた false-green。
  → LESSONS-LEARNED 追記候補: 「『このキャラをスリープさせ』を chain 先頭 atom にする spec は already-sleep qAndA を必ず確認」。
