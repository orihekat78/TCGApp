## 概要

「**このキャラをスリープさせ(…)てもよい。そうした場合、X**」型の能力は、効果解決時に self が既にスリープなら
optional 自体を行えない (= X も起きない)。公式qAndA (PR138/PR144/B04049):「スリープ状態で登場した場合
『このキャラをスリープさせ…てもよい』はできますか？ → **いいえ。スリープさせることができないので行えません**」。
これは **一般裁定** (B04049 が理由を一般機構として明記)。

エンジンの旧挙動: `sceneSetState{$self,sleep}` ハンドラは冪等に呼ぶだけで、対象が既にスリープでも
`__chainStepNoApply` を立てない (chain を break しない)。→ already-sleep でも discard + reanimate 等が
実行できてしまい qAndA 違反。Condition union に self の状態を見る条件が不在で engine変更0 では gate 不能だった。

## 水平展開 (起票時 PR138 のみ → 11 能力)

24 self-sleep カードを機械抽出し「self-sleep が optional の先頭 gating clause」を満たす **11 能力**を gate:

| trigger | カード |
| --- | --- |
| enter (明示qAndA) | PR138・PR144 (黒ずくめ reanimate) / B04049 (FBI remove) |
| enter (一般裁定) | B09058・B09058P (赤井家 reanimate) / B09057 (黒 summon) / B08058・B08058P (FILE8 deck-bottom) |
| ターン終了時 (self 既スリープ到達性高) | B06102 (キャンティ active) / B09065 (FBI active) |
| action:declare【ターン1】 | B09013 a2 (毛利小五郎/AP8000 reanimate) |

## 期待動作 / 実動作

- 期待: 解決時 self が sleep なら optional 自体不可 (discard / reanimate / activate ともに発生しない)
- 旧実動作: self が sleep でも optional を取れ、後続効果が走る

## 修正方針 (engine 変更あり — self-state condition 追加)

1. **engine**: `Condition` union に `charStateIs{ref:TargetingRef, state}` 追加 (effect.ts / cond/eval.ts case /
   CONDITION_KIND_MAP / taskA-validate-specs.cjs CONDS の 4点同期)。`ref` 解決は apAtLeast 同流儀。
2. **card**: 各能力に `condition: not{charStateIs(ref:self, state:'sleep')}` を AND マージ。
   - **ability.condition で gate** する (effect 側 `conditional` ラップは不可: resolveEffectPicks が
     conditional の両枝を walk するため optional **prompt** が surface してしまう。triggered.ts:226-238 は
     condition=false なら effect を walk 前に continue するので「非所持扱い」rules/17 = surface も出ない)。
   - 既存 condition (partnerColor 赤 / turn self / fileAtLeast 8) は `and:[既存, gate]` で維持。
3. **sleep のみ gate** (active 案は不採用)。⚠ **sleep/stun 非対称** が公式: 自スリープは already-sleep で不可だが、
   **自スタン (PR157/PR163) は already-sleep でも可** (qAndA「スリープ状態で登場した場合スタンさせることはできますか→はい」)。
   `state:'active'` で gate すると stun-from-sleep を誤って阻害するため `sleep` 等値 gate が正しい。

## 防止策 / 教訓

- **certify+adversarial-verify が green でも意味等価は自前で 1対1 突合** (教訓 B01011)。本件は verify lens が
  sceneSetState の冪等性と qAndA を突合し損ねた false-green。
- **effect 側 conditional ラップは optional の prompt を gate しない** (walk が両枝を訪れる)。状態 gate は
  ability.condition で行う。→ LESSONS-LEARNED 追記。
