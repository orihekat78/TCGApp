# autonomous full-scene effect entry

## 期待動作

- CPUが効果登場対象を選び、現場上限を超える場合、必要数の自分の現場
  キャラも選んでスイッチ登場を完了する。
- humanの`switchRemoveUid(s)`経路と同じscene-cap契約を使う。

## 修正前

- `drainAiEffectPicks`は登場対象だけを`applyPickAndContinuation`へ渡した。
- 直接`sceneEnter` pickには`switchRemoveUid`が無く、full-scene handlerが登場を
  skipした。continuation内の固定登場を使うB10088制御だけは別経路で通った。

## RCAと修正

- BUG-109のAI drainは一般pickを共有化したが、UIが別途収集するswitch victimを
  autonomous経路で補完していなかった。
- 選択後のscene超過数を`sceneCap`から算出し、owner sceneのdistinct victimを
  policyで選択してsingular/plural switch authorityとして共有resolverへ渡す。

## 回帰と水平確認

- RED: B08029 CPUは伊織無我を選ぶが、現場5枚のまま登場しなかった。
- GREEN: CPUのchoice→entry→switch後も現場5枚、1枚がremoveへ移動し、
  entrantへ突撃[キャラ]が付き【登場時】も1回解決する。
- Wave85 CPU effect-entryも同期`enter`時点sleep、偽`state:change` 0を固定した。
