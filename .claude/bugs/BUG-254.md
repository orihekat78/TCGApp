## Expected

When evidence is removed by Action [Case], its Hirameki may trigger whether the evidence was face-up or face-down. Optional fire/skip, suppression, and cards without Hirameki keep their existing behavior.

## Actual

The initial diagnosis added a `faceUp` gate in the common listener. That contradicted the official Hirameki rule and blocked face-down evidence.

## RCA

The pre-removal evidence payload exposes visibility, but visibility is not a Hirameki eligibility condition. The handler confused UI information visibility with triggered-ability eligibility.

## Fix

Removed the visibility gate. `removeOpponentEvidenceTop` regression coverage now verifies face-up and face-down B04028 through the actual action path, plus optional fire/skip, suppression, and no-Hirameki cases.

## Horizontal investigation

All action-removal Hirameki abilities use `handleEvidenceRemovedHook`; no other path required a visibility exception.

## Prevention

Do not introduce hidden-zone gates without an explicit official rule. Tests must exercise both card orientations through the action flow, not only direct event emit.
