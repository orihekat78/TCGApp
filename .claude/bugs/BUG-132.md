## 概要

B08020 (遠山和葉) 実装の敵対レビューで顕在化した **2 件の共有 engine 限界**。
いずれも B08020 固有ではなく **出荷済カードと同一 engine 経路** に存在する既存挙動。
engine変更0 では修正不可のため B08020/B08020P は本 wave で DEFER (engine拡張 wave#2 で修正後に再採用)。

## GAP-1: deckRevealUntil → handAddFromDeck の force-add (「〜まで」decline 不可)

### 期待 (公式)
「上から N 枚見て…を **1枚まで** 手札に加え」+ rules/15「〜まで」=0枚可。
B08020 の公式 Q&A: 「条件を満たすカードがあっても手札に加えないことはできますか？ → **はい、可能**」。
→ プレイヤーは **加えない選択**ができ、加えなければ後続の強制コスト (手札1枚リムーブ) も回避できる。

### 実動作
`deckRevealUntil` (atom-handlers.ts:1196-1207) は maxN 走査で **最初の** match を機械的に
`$matched` へ bind (player choice channel 無し、`matched = cardId; break;`)。カード側 conditional は
`bound $matched matched` → **無条件** handAddFromDeck。「まで」の 0 枚選択 (decline) も
「複数 match からどれを取るか」も surface されず、強制加入 + 後続 discard(min:1) も強制になる。

### 影響範囲 (水平展開)
`handAddFromDeck` 使用カード **50 件** (D01013/B01013/B01016/B01053/B05057 等)。うち
「1枚まで…加える」かつ trailing cost (discard 等) があるものが実害大。D01013 (committed,
bug-117 spec で参照) が代表。**全 50 件の精査は fix 時に実施**。

## GAP-2: effect:declared 反応の pick がイベント効果より先に解決

### 期待 (公式)
B08020 a2 括弧書き「（**イベントを解決してから**キャラを選ぶ）」+ Q&A「使用したイベントの効果を
**先に**解決します」。→ AP≤8000 候補集合は **イベント解決後**の盤面で確定すべき。

### 実動作
`hand-use-card.ts:133-137` がイベントを手札に残したまま `effect:declared` emit →
`triggered.ts collectCardsInPlay` は scene→hand 順走査 → 反応 ability の entry が
イベント自身の on-hand entry より先に queue → 反応側 pick が **イベント効果より先**に解決。
イベントが AP 修正 / キャラ除去・登場を伴う場合、選べる候補が公式順と逆転しうる。

### 影響範囲 (水平展開)
`effect:declared` 反応カード **171 件**。実害は「反応 effect が **盤面依存の pick** を持つ」
部分集合のみ (単純 draw 等は無影響)。B07016 (committed, e2e #104) が代表 (sceneRemove pick)。

## 修正方針 (engine拡張 wave#2)
- GAP-1: deckRevealUntil/handAddFromDeck に **decline channel** (0枚選択 surface) を追加。
  human=pick modal の skip、AI=効果判定。複数 match 時の選択も検討。
- GAP-2: effect:declared を **イベント効果解決後**に emit する (hand-use-card の emit タイミング
  後置 or ownerChosenOrder 強制)。B07016 の e2e #104 が回帰ゲート。
