## 概要

`charSetCard` の PA 短縮形 (atom-handlers.ts) は pending pick の `byPlayer` と
`buildShortFormPick` の chooser に `scsP = resolvePlayer(a.player, ctx)` を渡していた。
`player:'opp'` のカードでは `scsP='opp'` となり、**選択者が controller でなく相手プレイヤー**になる。

`charModifyAP/LP/Level` の短縮形は `byPlayer = ctx.source.player` (controller) を使い、
`side` (どちらの現場) は別に渡す **非対称**。`player` arg が本来「どちらのデッキ/現場を対象にするか」
の指定なのに、誤って「誰が選ぶか」にも流用されていた (rules/15「効果を使うプレイヤーが対象を選ぶ」違反)。

## 影響カード (4 枚)

- B02020/B02020P 大岡紅葉, B03032/B03032P — a2/a3 が
  `charSetCard {player:'opp', side:'opp', fromDeckTop:true, max:1}`
  (【登場時】相手キャラ1枚に相手デッキ上端を裏向きセット)。
- 症状: human が使うと **相手(AI)が対象を自動採用** し human にモーダルが出ない (0枚skip も不可)。
  逆に CPU 使用時は human が CPU 効果の対象を選ばされる。
- self 対象の短縮形 (B02023/B02030/B05029, player:'self') は scsP=self=controller のため元から正 →
  本修正で挙動不変。長形/`uid:'$self'` (B02040/P, B02046/P, B03061, B08054) は短縮形外で無関係。

## 修正 (engine バグ修正 / additive)

charSetCard 短縮形で chooser/byPlayer を `ctx.source.player` (controller) に変更。
deck-source / side は `a.player` (scsP) を後段 resolve (L798) と buildShortFormPick の sideDefault で
引き続き使用 → 「相手の現場/デッキ」対象は保持しつつ「controller が選ぶ」に修正。

## 防止策

短縮形 pick verb を追加する際、`byPlayer`(=選択者=常に controller) と `side`/`player`(=対象の側) を
混同しない。参照実装は charModifyAP (byPlayer=ctx.source.player, sideDefault 別指定)。
opp 対象カードを e2e に必ず含める (既存は self 対象のみで未検出だった)。
