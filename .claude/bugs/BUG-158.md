## 期待動作

carrier-reuse 「キャラを1枚まで選び、…セットし、…AP+/突撃/スリープ」: 1 pick を後続 atom が
`$picked.uid` で再利用し、rider (charModifyAP/charGrantKeyword/sceneSetState) が **human/AI 両経路で**
選んだキャラに適用される (BUG-130 の意図)。

## 実動作

`charSetCard{uid:'$pick', bind:'$picked', target:{pick}}` + rider `{uid:'$picked.uid'}` の **明示形** は、
**human 経路で rider が silent no-op** になる (setCard は成功するが AP/突撃/sleep が落ちない)。

- **実機再現** (main-loop、`__humanPlayerSide='self'` + `applyChoiceAndContinuation`→`applyPickAndContinuation`):
  - bare sequence `[charSetCard{uid:'$pick',bind:'$picked',target}, charModifyAP{$picked.uid,+2000}]` →
    setCount=1 / **AP=3000** (期待5000)。
  - 出荷済 **B02040 a2** (同形、choice 経由) → setCount=1 / **AP=3000**。
  - AI 経路 (`__humanPlayerSide=null`, walk 同期解決) は **正常** (AP=5000)。

## RCA

`runAtom` の bind-writeback preamble (atom-handlers.ts:95) は `typeof a.uid==='string' && !a.uid.startsWith('$')`
の時だけ `ctx.bindings['$picked']` を書く。

- **AI 経路**: `resolveEffectPicks` が walk 時に `uid:'$pick'→実uid` を置換 → preamble 発火 → writeback OK。
- **human 経路**: `applyPickAndContinuation` は pick を **`a.target`** へ解決し `a.uid` は `'$pick'` のまま →
  `!a.uid.startsWith('$')` が false → writeback されず → rider の `resolveBindRef('$picked.uid')` が
  literal を返し `startsWith('$')` guard で no-op。

→ BUG-130 (Task D E0) の writeback は **walk が uid を置換する AI 経路のみ** を実質カバーしていた。
pick-bind.test.ts の "human 経路" は `uid:'$pick'` 直 (target 無) の hand-built pending で検証したため
本症状を踏まず、false-green だった。

## 回避策 (engine変更0、card 側)

**短縮形 carrier 必須**: `charSetCard{player, max, filter, fromDeckTop, faceUp, bind:'$picked'}` (uid/target を書かない)。
`paShortFormAwait` の re-dispatch で `a.uid`=実uid となり human/AI 両経路で writeback 発火 (実機実証: AP=5000)。
本 wave の **B08023 はこの短縮形で出荷** (human 経路 test で pin)。exemplar = B07070/B07079。

## 水平展開 (該当・要修正カード)

明示 `uid:'$pick' + bind:'$picked'` を使う出荷済カード (human 経路で rider 不発):

- **B02040 / B02040P** 黒羽盗一 (a2: 白キャラ setCard + AP+2000)
- **B02046 / B02046P** (a1: setCard + AP+1000)
- **PR049** (setCard + AP+1000)

→ いずれも短縮形へ変換 (engine変更0) する card-session タスク。または engine 側で
human 経路の pick 解決時に `a.uid` も置換する additive 修正 (両経路統一) を行えば 5枚同時に救済できる。

## 防止策

- carrier-reuse は **短縮形のみ** とし、明示 `uid:'$pick'+target` を lint で検出する (将来 enforcement)。
- carrier-reuse の回帰 test は **human 経路** (`__humanPlayerSide` + applyChoice/PickAndContinuation) で
  rider 発火を assert する (AI 経路だけでは false-green)。
