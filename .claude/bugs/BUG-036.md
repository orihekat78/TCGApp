## 期待動作

rules/04 + rules/14:
- プレイヤーがリフレッシュを試みる際、リムーブエリアが 0 枚なら **そのプレイヤーは敗北**
- engine: `GameState.gameResult = { winner: 相手, reason: 'deck-out' }` が設定される
- runMatch / playTurn ループは `gameResult` を見て即座にゲーム終了

## 実動作 (2026-05-21 確認)

`src/engine/mutate/deck.ts:90-97`:
- `refresh()` が `remove.length === 0` の時 `{ ok: false, loserPlayer: p, reason: 'remove-empty' }` を返す
- 呼出元 `draw()` (line 20-24): `if (!result.ok) break;` で抜けるだけ
- **`gameResult` をどこにも set しない**

→ ループは `引いた分だけ ok: true で終了`、ゲーム継続。実質的に deck-out 敗北条件が
**engine 全体で未配線**。`'lose:by-deck-out'` hook も types/hooks.ts:66 で定義されているが
emit されていない。

## 関連ファイル

- `src/engine/mutate/deck.ts:18-30` (draw 関数の refresh handling)
- `src/engine/mutate/deck.ts:90-97` (refresh 内部)
- `src/engine/mutate/gameResult.ts` (gameResult set 関数)
- `src/engine/types/hooks.ts:66` (`'lose:by-deck-out'` hook 型のみ)
- `src/engine/types/results.ts:14-16` (RefreshResult.ok:false 定義)

## RCA (Root Cause Analysis)

- Phase 4/5 で refresh / deck の primitive を実装した時、敗北条件処理は「呼出元 Hook 担当」
  (deck.ts:88 コメント) と委譲した。
- しかし呼出元の Hook (おそらく `lose:by-deck-out`) を emit する場所が実装されておらず、
  responsibility 漏れになった。
- smoke 1000戦は avg 9.85 turns で終わるため deck (25 枚) を使い切らず、
  バグが顕在化しなかった。Phase 6 AI driver も特に問題視せず素通り。

## 水平展開

- 痕跡 (`scratchTrace`) は `refresh` 関数内部で正しく set (deck.ts:119)、リフレッシュ系
  自動遷移としては痕跡のみ実装、deck-out 敗北は未実装。
- 他の敗北条件 (concede / evidence) は別経路で gameResult set 済 (mutate/partner.ts:79 等)。
- リフレッシュ失敗 → 引かなかった枚数を log に記録もない (cleanup follow-up 候補)。

## 修正案

`src/engine/mutate/deck.ts:21-24` を以下に差し替え:

```ts
if (!result.ok) {
  // refresh 失敗 = deck-out 敗北 (rules/04, 14)
  const winner = p === 'self' ? 'opp' : 'self';
  s.gameResult = { winner, reason: 'deck-out' };
  // 'lose:by-deck-out' hook emit はここで (event registry にアクセスが必要なら
  //  draw 経路上の caller か別 listener で処理)
  break;
}
```

## 防止策

- 新規敗北条件追加時は `tests/engine/mutate/deck.test.ts` に remove-empty case を
  必ず追加するレビュー基準
- `gameResult` set 経路を spec で網羅 (`engine-api-game-state.md` に列挙)
