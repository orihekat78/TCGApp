## 仕様 (rules/01, 15, 06)

事件カード D08026 / D11021 の a1:「この事件が解決編になったとき、自分は手札を1枚リムーブする。」

## 期待動作

事件が解決編になったとき、その事件カードの所有者が手札を1枚 discard する。

## 実動作

**一度も発火しない**。解決編になっても手札リムーブが起きない (旧 unit test は descriptor の形しか見ず素通り)。

## RCA (2 層 + matcher)

- **Layer 1 (engine): hook 未 emit**
  - a1 (caseResolvedHandRemove) は `trigger.hook='case:to-resolved'` を待つが、
    `case:to-resolved` を emit するのは **未使用の caseToResolved atom のみ** (atom-handlers.ts)。
  - 実プレイの解決編移行 = **assist atom (partner.ts) / FILE>=7 自動 (file.ts) / AI policy (policy.ts) /
    caseToResolved atom (case.ts)** が `case.status='解決編'` を **直接代入**し hook を出していなかった。
  - triggered listener (case:to-resolved 登録済) に hook が届かず → a1 永遠に noop。
- **Layer 2 (matcher): 二重発火 / opp 未発火** (修正過程で判明)
  - caseResolvedHandRemove の matcher `payload.player==='self'` は payload (遷移プレイヤー) だけ見て
    **カード所有者を見ない** → self 解決編で **opp の事件カードの a1 も発火 (二重 discard)**、
    opp 解決編では **どの a1 も発火しない**。

## 修正

1. `mutate/case.ts toResolved`: status 設定後に `case:to-resolved` を emit。
   source = `{ player:p, uid:'case:'+p, cardId }`。**全移行経路を本関数に集約**。
2. `mutate/file.ts` (FILE>=7) / `mutate/partner.ts` (assist) / `ai/policy.ts` (AI assist 直接代入除去):
   直接代入 → `caseOp.toResolved(s,p)` 経由に統一。
3. `atom-handlers.ts caseToResolved atom`: 重複 emit を除去 (toResolved が emit)。
4. `D08026.ts` + `D11021.ts`: a1 を **D08013 と同様の inline AbilityDef 形**に
   (`trigger{ hook:'case:to-resolved', selfOnly:true }` / `effect{ atom discard player:'self' n:1 }`)。
   matcher → **selfOnly** に変更し `source.uid===card.uid='case:'+p` で「その所有者の事件のみ」発火に修正。

## 水平展開

- `case.status='解決編'` 直接代入は src 全体で **toResolved のみ**に集約 (grep 確認)。
- `case:to-resolved` を listen する ability は D08026 / D11021 の a1 のみ (他に副作用 listener なし)。
- discard atom args.player='self' は resolvePlayer で **card owner 相対**に解決 (opp は opp の手札を discard)。
