## 期待動作

[src/cards/ct-d11/D11021.ts](../../src/cards/ct-d11/D11021.ts) (千速と重悟の婚活パーティー、事件カード) の `traits` に **「婚活」** が含まれる。

これにより CT-D11 デッキの caseTraitConditioned 系カード:
- D11003 a2 (declared, `caseTraitConditioned({ trait: '婚活' })` wrap)
- D11005 a1 (triggered enter, `caseTraitConditioned({ trait: '婚活' })` wrap)
- D11007 / D11011 (partnerColorKeyword の additional condition で間接参照する可能性)

の condition が「婚活」trait 持ち事件 (D11021) で正しく true 評価される。

## 実動作 (修正前)

`D11021.traits = []` 空配列。「婚活」trait なし。

`engine.cond.eval` の `caseTrait` case (src/engine/cond/eval.ts:112-117) は `state.players[p].case.cardId → cardDef.traits` で trait check するため、上記カードの caseTrait 条件は **常に false** となる。

→ AI / engine は D11003 a2 / D11005 a1 の能力を **絶対発動できない** 状態。

## RCA

CT-D11 デッキ実装 (cards/ct-d11/D11021.ts) で traits 配列を空のまま定義。カード名「千速と重悟の婚活パーティー」+ 関連能力 (D11003/D11005/etc.) は明確に '婚活' trait を想定しているため、これは **データ不整合** (engine ロジック自体は正しい)。

## 修正

[src/cards/ct-d11/D11021.ts](../../src/cards/ct-d11/D11021.ts):

```ts
traits: ['婚活'],  // 修正前は []
```

1 line data fix。engine ロジック / 共通クラス変更なし。

## 影響範囲

- D11003 a2 (declared) が「婚活」case で発動可
- D11005 a1 (triggered enter) が「婚活」case で発動可
- AI / state-machine が D11003/D11005 の能力を活用できるようになり、smoke baseline がシフトする可能性 (BUG-030 と類似 positive shift)
