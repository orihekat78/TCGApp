## 仕様 (rules/01, 15)

D08026 / D11021 の a1:「この事件が解決編になったとき、自分は手札を1枚リムーブする。」
ユーザー期待: FILE が7になり解決編へ移行した瞬間に効果が発動し、**手札からリムーブする1枚を選ぶ** picker が出る。

## 期待動作

解決編移行 → a1 発火 → human が手札1枚を選択 → リムーブエリアへ移動。

## 実動作

**何も起きない**。FILE が7になり解決編へ移行しても picker が出ず、手札も減らない。
(BUG-089 で a1 の emit/queue は直ったが、その先の human pick が UI に届かなかった。)

## RCA

- a1 (case:to-resolved → discard) は **human(self) の場合、discard pick を side-channel
  `__pendingEffectPickQueue` に積む**（triggered.ts: humanChooser=true なら auto-pick せず defer）。
- `dispatchEngineAction` は produce 後に `_drainPendingEffectPickSide → store.setPendingEffectPick`
  で side-channel を store へ転送し、`useEffectPickFlowDriver` / `Playmat` が picker を出す。
- ところが **FILE が auto-phase (ターン開始時の自動 FILE 追加) で7に達して解決編になる経路**は、
  `useOppTurnDriver.driveOppTurn` の `flow.startTurn(self) + runAllUntilEmpty` (produce 内) で a1 を
  解決し pick を queue に積むが、**driveOppTurn は side-channel を store へ転送していなかった**。
  → `store.pendingEffectPick` が null のまま → picker 出ず → 「何も起きない」。
- `useSpectatorTurnDriver` も同型の転送欠落 (Workflow 8 agents で確認)。

## 修正

1. `useEngineDispatch.ts`: 共有 helper `surfacePendingSideChannels()` を新設
   (hirameki / misread / effectPick / deckReveal の各 side-channel を drain → store.set、非 null のみ)。
2. `useOppTurnDriver.driveOppTurn`: opp endTurn → startTurn(self) の produce 直後に
   `surfacePendingSideChannels()` を呼び、human auto-phase で積まれた pick を surface。
3. `useSpectatorTurnDriver.driveSelfTurn`: 対称に同 helper を追加 (一貫性 / deckReveal 等)。
- 注: `discard` の pick UI は EffectPickerModal ではなく **HandZone の pick mode** (手札 auto-expand /
  `.hand-card--pickable`)。pendingEffectPick が store に出れば Playmat が自動で expand する。

## 水平展開

- runAllUntilEmpty で human effect を解決しうる経路の sync 有無を全数監査:
  - dispatchEngineAction = 参照実装 (sync 済) / driveOppTurn = 欠落 (修正) / driveSelfTurn(spectator) = 欠落 (修正)。
  - gameStarter (turn1 startTurn) = turn1 は FILE<7 で a1 不発火、scene 空で human trigger 無し → 実害なし (未修正)。
- driver は `Playmat.tsx` で mount → src/App と meta-app/RealMatchView の両経路をカバー。
