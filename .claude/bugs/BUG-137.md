## 概要

`mill` atom (atom-handlers.ts) は `mutate.deck.removeFromTop` を呼ぶだけで、デッキが 0 枚に
なっても refresh を行わなかった。公式: rules/14 (デッキ 0 で即座に refresh) + rules/26
(「上から○枚リムーブ」はデッキ不足時、可能な限りリムーブ → refresh → 残り分は追加リムーブしない)。
B09104 qAndA「デッキの枚数が4枚未満の場合、可能な限りリムーブし、**その後リフレッシュを行います**」が一次根拠。

## 影響範囲

出荷済 mill 使用カード 13 枚 (cluster2 設計時 grep)。smoke デッキ (CT-D08/D11) に mill 使用
カードは 0 のため baseline 影響なし (latent)。実戦では「mill でデッキが尽きたのに refresh も
敗北判定も起きない」状態が発生し得た。

## 期待動作 / 実動作

- 期待: mill 後にデッキ 0 → refresh (リムーブ 0 枚なら deck-out 敗北)
- 実動作 (修正前): デッキ 0 のまま続行

## 修正

atom-handlers.ts の mill case に fileAdd と同型の refresh guard を追加 (X7)。
pin: tests/engine/effect/wave2-cluster2-ability-filter.test.ts §X7 (deck<n / deck==n / 敗北 / 回帰)。
