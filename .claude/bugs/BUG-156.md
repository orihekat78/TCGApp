## 期待動作

〚アクティブ状態の[X]を1枚スリープ/スタンさせる〛(n:{min:1,max:1}) コストは、複数の active 候補が
あっても **プレイヤーが選んだ 1 枚のみ** をスリープ/スタンする (rules/15 「1枚まで」/ rules/21 コスト)。

## 実動作

`cost/pay.ts` の sleepChar は `const targets = ctx.picked ?? cands; for (cand of targets) setState(sleep)`
で、`ctx.picked` が **production 経路で一度も配線されない** ため `cands` (= candidates(target) の全 active
一致) を全てスリープする。`candidates()` は `ref.n` を適用しない (n は display 用 legalCount のみ)。
→ active な [X] が2枚以上あると **全部** スリープされる (over-pay)。実機再現: 3 active 候補 → 3枚スリープ。

- **影響**: sleepChar コストを持つ出荷 15枚 (D01003/B01063/B03060/B04070/B05059(P)/B05074/B07016/B07066(P)/B07067/B09058(P)/B09082)。
  cardName filter のものは同名複数枚が現場にいる場合のみ顕在 (rules/03 同カード複数登場可)。
- **未顕在化の理由**: 既存テストは単一候補のみ。smoke は該当コストの multi-active 局面に到達しにくい。

## stunChar (本 wave 新規) は honor 済

`stunChar` は新規ゆえ `cost.target.kind==='pick'` の `n.max` ぶんだけ stun する faithful 実装で出荷
(`pay.ts` 該当 case、test §6)。ただし「どの active を選ぶか」は ctx.picked 未配線のため **先頭 active 固定**
(arbitrary)。B08004 は cardName[灰原哀] = 同一カードなので等価 (faithful)。trait filter 系 stun cost が
将来出れば player-choice が要る。

## RCA

cost target の human/AI **pick 選択チャネルが sleepChar/stunChar に存在しない**。
`AbilityCostParams` (ability-activate.ts) は flipFaceUpEvidence/sceneToDeckBottom/removeAreaToDeckBottom/
choice のみ運ぶ。`computeAiCostParams` (policy.ts) は非 flip コストで `default: return` (picker 無し)。

## 修正方針 (unified、別 commit / 別 session)

(a) **暫定 (additive)**: sleepChar pay も stunChar 同様 `n.max` で枚数を制限 (player-choice 無しの先頭固定)。
    smoke 再ベースライン要 (既存 sleepChar カードの挙動が変わりうる = 非 additive、要慎重)。
(b) **本修正**: `AbilityCostParams` に sleepChar/stunChar target-pick channel を追加し、UI(flows.ts)/AI
    (computeAiCostParams) が `ctx.picked` を populate。これで player-choice + n 枚数の両方が faithful。

## 防止策

- cost pay の枚数は `cost.target.n` を honor する (candidates 全件をそのまま消費しない)。
- 新規 cost kind 追加時は multi-candidate test を必須化 (本 wave で stunChar は追加済)。
