# 旧セーブの能力使用回数を見失う

## 期待動作

printed、granted、物理set-card由来の各能力は独立して回数制限される。
旧JSONセーブを復元しても、既に消費した能力を再使用できない。

## 実動作（修正前）

旧stateは`declaredUseCount[abilityId]`へ保存するが、Wave35は
`abilityOrigin + abilityIndex`のexact keyを読む。2番目以降の能力を
未使用の`0`と誤認し、復元後に再使用できた。

## RCAと修正

- exact occurrence keyを全printed/granted能力へ使用
- exact不在時だけ旧bare keyを保守的に継承し、writerも旧値から継続
- source無しreaderはbareと全exact occurrenceの最大値を返す
- 負数、小数、unsafe integerは消費済みとしてfail-closed
- physical set-cardとreplacementのturn countも同じ検証・飽和契約へ統一
- pending sourceのlineage 0件偽造、旧PA-MR UID、AI legacy instance ID、
  instance無し`setcard:leave`を個別に閉じた

## 回帰と水平展開

- B10004の旧count 2→3継続、旧count 3再使用拒否
- B01057/B05117/B07014/B10017の複数物理occurrence
- case、scene、PA-MR、off-board、choose-intercept、AI、JSON、UI、E2E
- malformed host/set-card/replacement countとpending lineage偽造
- 同型reader/writerを共有helperへ集約し、raw key直読テストを廃止
