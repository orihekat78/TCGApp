# BUG-183: handReveal「してもよい」の n:1 強制発火 family

## 期待動作
印字「手札から〜を1枚公開してもよい。そうした場合〜」(rules/15「してもよい」= 行わない選択可) は
skip 可能な pick (min:0,max:1)。0 公開なら chain の exact-N gate (chainStepNoApply) で後段不発。

## 実動作
`handReveal args n:1` は buildShortFormPick で {min:1,max:1} に固定 →
EffectPickerModal `canSkip = nMin===0` を満たさず、候補があると辞退不可で強制公開。

## 該当と修正
- 新規 (M1 batch 内で修正): B08082 a1 / B07053 a2 — n:1 → max:1
- shipped (水平 sweep で検出、同 commit 修正): **B07022 / B08064 / B09002 a2** — n:1 → max:1
- **B09061 は対象外 (意図的例外)**: optional 包みは AI が常 skip し strictly-dominant な draw を
  取り逃す既知 trade-off。card コメント + atom-hand-reveal.test.ts §10 で bare-chain 契約として文書化済

## RCA
「してもよい」の担い手を outer optional でなく pick min:0 に置く idiom (B04049/B09040 の discard
max:1 と同系) が確立する前の author が n:1 を使用。verify lens は self 経路の gate-on-0 のみ確認し
「候補ありで辞退」の UI 経路を見なかった。

## 防止策
- finish.cjs idiomLint 候補: 印字に「公開してもよい」を含む unit の handReveal n:number は WARN
- review lens 検査軸「optional vs 必須」に「n vs max (nMin) の辞退可否」を含める (M1 で実証済)
