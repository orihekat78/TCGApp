# BUG-171: declared ability の dyn queue-boundary 喪失 / charSetTurnEffect '$' 汚染

## 期待動作
- W6 step1 設計の供給チャネル: DeclareCardNameModal → `AbilityCostParams.declaredName` →
  `costParamsToDyn` → `ctx.dyn.declaredName` → runtime の `atomDeclareName` /
  `resolveBindRef('$dyn.declaredName')` が読める。
- PR105 a2 skip (「してもよい」decline) 時は nameOverride が**未設定のまま** (書き換え不発)。

## 実動作 (修正前)
1. `useDeclaredAbility` → `event.queue` は **costPaid のみ** entry へ永続化 (2026-06-29d) し
   `dyn` を落とす → runtime `entryToCtx` 再構築 ctx に dyn 不在 → declaredName が**常に未供給扱い**
   (供給しても `boundNameMatchesDeclared` 恒偽 / nameOverride 不発。チャネル全断)。
2. `atomCharSetTurnEffect` は `resolveBindRef` の未解決 passthrough (`'$dyn.declaredName'` 文字列)
   をそのまま `setTurnEffect` → skip 時に `names()` が `['$dyn.declaredName']` を返す汚染。

W6 probe (engine-mega-w6.test.ts) は `runAtom` 直駆動で ctx を手渡ししており **queue 境界を踏んで
いなかった**。first-consumer の behavioral probe (activateDeclaredAbility → runAllUntilEmpty) が初検出。
※ 2026-06-15 の調査 obs「name-designation Gate: ctx.dyn Dropped on Suspend/Resume」が同 gap を
既に指摘していた (設計時に未反映)。

## 修正
- `EffectStackEntry.dyn?` 追加 (costPaid と同型の queue-boundary 永続化)。
  declared-ability.ts が entryExtras で渡し、stack.ts entryToCtx が **shallow-copy** で復元
  (Immer 凍結 entry への runtime `(ctx.dyn ??= {})` 書込対策、bindings と同 posture)。
- `atomCharSetTurnEffect`: 解決後 val が `'$'` 始まり文字列なら no-op + log
  (uid の `startsWith('$')` guard と同 posture)。

## RCA
- queue-boundary 永続化は bindings (BUG-082) → costPaid (2026-06-29d) → dyn (本件) と**同じ穴が
  フィールド毎に再発**。entry へ運ぶ ctx フィールドの追加時に「queue 跨ぎで読む consumer が
  居るか」を設計 checklist 化すべき。

## 水平展開
- ctx の他フィールドで queue 跨ぎ読みがあるもの: `costPaid` (済) / `bindings` (済) /
  `contact` (bindings 経由で済) / `declaredNames` は **effect 実行中に書かれる** (atom 間伝播は
  同一 runtime ctx 内で完結、queue 跨ぎ無し) → 現時点で残 gap 無し。
- triggered listener queue 経路 (partner-ability) は costPaid 同様 dyn も未伝播 —
  effect-stack.ts の costPaid コメント既記の通り consumer 0 のため保留 (同コメントに dyn も準拠)。

## 防止策
- first-consumer カードの probe は **必ず production dispatch 経路 (activateDeclaredAbility +
  runAllUntilEmpty)** で書く (runAtom 直駆動は結線検証にならない) — LESSONS-LEARNED 追記候補。
