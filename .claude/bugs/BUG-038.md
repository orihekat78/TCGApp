## ユーザー指摘

> #7: スリープしていないカードに対してもアクションを行えるんでしたっけ？
> 今は行えるようになっています。

## 期待動作 (rules/07)

アクション対象は「相手の現場のキャラ (**スリープ または スタン状態**)」のみ。
アクティブ状態の相手キャラは対象不可。

## 実動作の検証 (2026-05-21 Playwright headed)

`localhost:5175/` + デモ (turn-4) ロード後、self-2 (active) で「アクション」
→ source picker から self-2 を選択 → opp 側の target picker 状態確認:

```
oppCards: [
  { uid: "opp-1", classes: "card color-blue",                isCandidate: false },
  { uid: "opp-2", classes: "card color-blue sleep candidate", isCandidate: true  },
  { uid: "opp-3", classes: "card color-blue stun candidate",  isCandidate: true  },
]
```

→ active な opp-1 は target picker から **正しく除外**、sleep/stun のみ候補。

opp-1 (active, 非候補) クリック → state 変化なし、confirm modal 開かず。
opp-2 (sleep, 候補) クリック → confirm modal「横溝重悟 で 灰原哀 にアクション
します。」が出現 → rules/07 通り。

## 根本原因

ユーザー指摘 #7 は **#1/#16 (BUG-037) の視覚的副作用**。

BUG-037 (commit `9567c0c`) 修正前:
- `SceneArea.css:128` `animation: scene-card-enter ... both;` の forwards 側が
  100% keyframe の `transform: translateY(0) scale(1)` を保持
- `.card.sleep { transform: rotate(-90deg) }` が animation 100% に上書きされて
  無効化
- 結果: **engine では sleep 状態だが UI で回転していない** カードが存在
- ユーザー視点: 「アクティブに見えるカード」(実は sleep) を attack 対象として
  選択 → 成功 → 「アクティブを攻撃できた」と誤認

BUG-037 修正後:
- sleep -> rotate(-90deg) 適用 ✓
- stun -> rotate(180deg) 適用 ✓
- active -> transform: none ✓
- target picker は engine `canActionAgainstChar()` が sleep/stun のみ候補と
  していたので、視覚化が正しくなれば誤認も解消

## 関連ファイル (engine + UI 全層検証済)

  `canActionAgainstChar` で filter
