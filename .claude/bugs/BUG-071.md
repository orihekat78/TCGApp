## 修正

`triggered.ts:192-194` の skip 廃止、effect 全体を常に queue する形に変更:

- pre-pick step (draw 等) は通常通り実行される
- pick 未解決 atom (例: discard with target.kind='pick') は atom-handler の既存 safety net で no-op skip + log
- UI が modal でユーザー選択 → effectPickResolve dispatch → 解決済み atom が単体で queue → 実行

これで sequence 内の全 step が正しく機能する。

## 防止策

[BUG-066](BUG-066.md) の 3 点 verify を **caller 側 (listener) も含めて適用する**:

修正範囲が engine 側の関数 (例: `resolveEffectPicks`) の場合、**その関数の caller 側コード** (本件では `triggered.ts:175-202`) も同じ 3 点 verify を適用する。caller の skip / branching logic が「旧前提に基づく」場合、新挙動と矛盾する可能性が高い。

→ [LESSONS-LEARNED.md](LESSONS-LEARNED.md) §教訓 11 を「caller 側も verify 対象に含める」と明示する追記候補 (defer)。
