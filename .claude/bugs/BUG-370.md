# Pending decision publication order

## Expected

- 親効果のmandatory decisionを解決してからchild triggerを解決する。
- B07004はswitch登場後も手札1枚リムーブを完了し、その後entrant能力へ進む。

## Actual

- `deckRevealUntil`再開中にparent continuationが後段discard pickを生成。
- stack drainがそのpickをhard boundaryとして扱わず、entry childを先に実行した。
- child optionalが公開され、parent discardより先に`ok:true`で解決できた。

## Root cause and fix

- stackのpending-pick boundaryが`source.triggerBatch`付きに限定されていた。
- pending sourceと次entryのphysical/provenance authorityを既存matcherで照合する。
- 同一entryのdeferred prewalkと`resumesCurrentEffect` carrierだけを通す。
- それ以外のstack entryはparent pick解決まで停止する。
- parent decision解決後、既存`next()`がturn-playerとowner-orderを適用する。
- GameState、public API、side-channel形式は変更しない。

## Horizontal investigation

- triggerBatchなしのdeclared continuationを両所有者で再現。
- child trigger 1件と2件を分け、owner-order前に公開されないことを確認。
- 保存復元、RPS、reorder/place、public hand revealを水平再検証。

## Prevention and evidence

- pending pick中はown deferred entryかexplicit resume carrierだけstackを進める。
- parent完了後のsimultaneous childは既存owner-orderへ戻す。
