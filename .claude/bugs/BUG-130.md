## 期待動作

B02040/B02046 系「【白】のキャラを1枚まで選び、デッキ上から1枚裏向きでセットし、
ターン終了時まで AP＋2000(1000) する」— **選んだ同一キャラ** にセットと AP 修正の両方が適用される。

## 実動作 (修正前)

sequence step1 (charSetCard, uid:'$pick'+target) の pick 解決後、step2 (charModifyAP, uid:'$pick',
target 無し) はリテラル '$pick' のまま handler に到達し、skip-unresolved guard で **silent no-op**。
セットだけ行われ AP+ が一切発動しない (画面上はセットの演出が出るため気付きにくい)。

## RCA

「1 pick を複数 atom で共有する」機構が engine に存在しなかった (pick-share gap)。
authoring 時にコメントで「bindings 経由で同 pick uid を再利用」と書かれたが、その機構は
実在しなかった (検証漏れ)。B07093 a1 は同形状を理由に正しく DEFER されていた一方、
B02040/B02046 は誤って出荷された。

## 修正

- engine: Task D E0 pick-bind (atom args `bind:'$picked'` → runAtom preamble が ctx.bindings へ
  writeback、後続 atom は `uid:'$picked.uid'` で参照)。human/AI 両経路を単一 preamble でカバー
- cards: B02040 / B02040P / B02046 / B02046P の step1 に `bind:'$picked'`、step2 を
  `uid:'$picked.uid'` に修正

## 水平展開

- 全カード走査 (atom args に '$pick' を含み target を持たないもの): 該当は上記 4 ファイルのみ。
  '$matched.uid' / '$trigger.uid' / '$each.uid' 系は bind 実在で正常 ✓

## 防止策

- lint:card-addition に「target 無し atom の uid:'$pick' 禁止」ルールを追加するのが恒久対策
  (リファクタ計画のチェック項目に計上)
- 「DSL に書ける ≠ engine が評価する」(BUG-117/118 教訓) — 新パターンは必ず単体テストで効果値を assert
