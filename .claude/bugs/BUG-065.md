## ユーザー指摘

> このように今、元太の登場時能力が機能しない状態です (D08015 を 2 ターン目に出した時、a1 の step 2 discard が `discard:skip-unresolved-pick` ログを残して消える)

## 期待動作

D08015 の a1 (【登場時】1 ドロー → 手札 1 リムーブ) の step 2 で、人間プレイヤーには EffectPickerModal が表示され、選択したカードが手札からリムーブされる。AI なら heuristic で 1 枚自動選択。

## 実動作 (修正前)

a1 step 2 の discard atom 実行時、`target` が pick query object のまま渡され、[atom-handlers.ts:139-146](../../src/engine/effect/atom-handlers.ts) の暫定スキップが発動して効果が消える。EffectPickerModal は表示されない。

## RCA

`resolve-picks.ts` の `substituteAtomPick` ([line 86-140](../../src/engine/effect/resolve-picks.ts)) が **2 つの effect 記述形式のうち pattern A だけしか解決していない**:

| パターン | 形式 | 例 | resolver 解決 |
|---|---|---|---|
| **A** | `args: { uid: '$pick', target: { kind: 'pick', ... } }` | `sceneRemove` / `charModifyAP` / `charSetState` 等 | ✓ |
| **B** | `args: { player, target: { kind: 'pick', ... } }` (uid なし) | `discard` / `evidenceToHand` / `handAddFromRemove` 等 | ✗ |

resolve-picks.ts:94 で `if (args.uid !== '$pick') return atom` のガードがあり、pattern B はそのまま返却 → discard atom 到達時に target が pick query object のまま → atom-handlers.ts:139-146 の暫定スキップが発動。

BUG-045 で discard atom に「target が配列でない場合は no-op skip + warning log」の暫定対応が入っていたが、「本格対応は別 BUG で resolver 拡張」とコメント記載のまま 7 ヶ月放置されていた。本 BUG-065 が本格対応。

## 影響範囲 (水平展開調査)

## 修正方針

1. **resolve-picks.ts** — `substituteAtomPick` の guard を `args.uid === '$pick' || target.kind === 'pick'` に拡張。pattern B では `target` を `[picked.uid, ...]` (配列) で置換、人間 chooser は side-channel 経由で `target` 置換を待つ
2. **useEngineDispatch.ts** — `effectPickResolve` で `atomArgs.uid` だけでなく `atomArgs.target` も picked uid 配列で置換できるよう拡張 (pattern により分岐)
3. **atom-handlers.ts** — discard の暫定 skip コードを撤去 (BUG-045 暫定対応の終了)

## 検証計画

- D08015 a1 の単体テスト (atom-flow level) を追加し、pattern B が解決されて discard が実行されることを assert
- pattern B を使う他カード (D08003 / D08013 / D11007 / caseResolvedHandRemove) の挙動 regression 確認
- `npm run smoke:1000` で AI vs AI 1000 戦 0 例外維持
- E2E: D08015 を 2 ターン目に出して EffectPickerModal が表示されることを Playwright で確認

## 防止策

- `lint:effect-descriptor` (defer): カード effect の `args.target.kind === 'pick'` の場合に `args.uid === '$pick'` がペアで指定されているか lint で警告 (誤った混在を防ぐ。ただし pattern B は正当なので resolver で受け入れる方が正しい)
- 「暫定 skip コード」と「本格対応 TODO」のペアは BUG ファイル新規作成を必須とするルールを [WORKFLOW-GUIDELINES.md](../specs/cards-analysis/WORKFLOW-GUIDELINES.md) ではなく [card-addition-checklist.md](../specs/card-addition-checklist.md) または別 meta ガイドに追加 (今回 7 ヶ月放置されたため)
