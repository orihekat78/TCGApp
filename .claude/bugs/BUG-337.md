# contact action slot reuse

## 期待動作

- 各コンタクト行動枠で選べるのはカットイン、変装、パスのいずれか1つ。
- 1つを実行した同じphaseで、2つ目の`actionContact`は拒否する。
- 1番目がパス、2番目が行動した場合の`action-1-redo`は別の行動枠。

## 修正前

- `actionContact`はphaseとownerだけを検査し、当該phaseのacted slotを見なかった。
- 初回dispatchは`firstActed`/`secondActed`/`firstRedoActed`を書いたが、
  `actionAdvance`前の再dispatchが通った。
- 公開経路でカットイン→変装と変装→カットインを連続使用できた。

## RCAと修正

- `runEngineAction` のacted-slot書込みと`actionAdvance`の完了条件は正しい。
- 欠落は公開authority境界`useEngineDispatch/can-check.ts`の再送防止。
- 現phaseに対応するacted slotが`undefined`でなければ拒否する。
  `false`のパスも消費済みとして扱う。

## 回帰と水平確認

- RED: 同phaseのカットイン直後の変装が`{ok:true}`。
- GREEN: カットイン→変装、変装→カットインとも`not-allowed`。
- 拒否時は手札と現場が不変。Wave56 public 24テストを通過。
- 既存action FSM/contact driver 43テストを通過。AIは各枠で1つだけ実行後、
  returnするため追加修正不要。
