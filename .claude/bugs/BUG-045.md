## 実動作 (修正前)

### 課題 1: 1 試合通し E2E 未整備

`tests/e2e/` には個別バグ用 spec (bug-006/029/037 等) のみで、mulligan → 終局
までを一貫検証する spec が無かった。今後の「Playmat 配線漏れ」(BUG-040/041/
042/043 で連続発覚した同一 pattern) の予防が困難。

### 課題 2: spectator mode で contact 発生時に hang

`src/ui/hooks/useContactFlowDriver.ts:150 / 197` で defender / decider が 'self'
の場合 GuardPickerModal / CutInDisguisePickerModal を **無条件で開く**。
spectator mode (AI vs AI) では self も人間ではないため、modal が開いて
そのまま操作待ち状態で hang。

### 課題 3: engine atom-handlers 2 件のバグ (E2E で発覚)

(a) `deckRevealUntil` atom が `args.filter` を function として呼ぶが、card
data は declarative TargetFilter object (`{color, levelMax, kind}`) を渡す。
→ `TypeError: filter is not a function` at atom-handlers.ts:246

(b) `discard` atom が `args.target` を string[] として扱うが、card data は
TargetingRef pick query を渡す。Phase 7-2 の $pick resolver は `uid:'$pick'`
にのみ対応で、`target` field の pick 解決は未配線。
→ `TypeError: ids is not iterable` at hand.ts:10

1000-game smoke はこれらの atom path に到達しないため検出できなかった (engine
内部の AI move-enumerator がこれらの effect を選びにくい)。spectator mode で
の長期 AI 対戦で初めて顕在化。

## 修正

### Fix 1: 1 試合通し E2E spec 新規 (`tests/e2e/full-match.spec.ts`)

2 つの test:
- `観戦モード: 試合が console error 無しで完了 or max-turn 到達` — spectator
  起動 → mulligan 自動 skip → 60s 以内に gameResult or turn≥50 で停止、
  console error が空であることを assert
- `GameSetupModal: デッキ選択 UI が両 select で 2 options を持つ (BUG-042
  回帰防止)` — UI 配線の単純チェック

### Fix 2: spectator mode で contact AI 委譲

`useContactFlowDriver.ts`:
- `spectatorMode` を store から read
- `defender === 'self' && !spectatorMode` → GuardPickerModal 開く (既存挙動)
- `defender === 'self' && spectatorMode` → opp 同様 AI policy で chooseGuard
- 同様に action-1/2/redo の self decider も spectator なら AI 委譲

### Fix 3: atom-handlers `deckRevealUntil` filter object 対応

`targetFilterToPredicate(filter)` helper を新規追加。TargetFilter
(cardId / color / trait / levelMin/Max / kind) を `(cardId: string) => boolean`
predicate に変換。`a.filter` が function なら従来通り、object なら helper で
predicate 化。

### Fix 4: atom-handlers `discard` 防御策

`a.target` が非配列なら no-op skip + 警告 log。本格対応 (resolver で
`target` pick query を解決) は別 BUG で取り扱う。Phase 7-2 $pick resolver
拡張または atom 内部で targetCandidates 呼出が候補。
