## 仕様 (rules/17 §【ターン①】)
宣言能力に【ターン①】等の回数制限がある場合、使用ごとに declaredUseCount を increment し、
次の canDeclaredAbility で上限到達を gate すべき。

## 実動作 (latent バグ)
`selfToDeckBottom` 等「自身を場外へ移す」コストは useDeclaredAbility 呼出前に source を scene→deck へ移す。
`incrDeclaredUseCount(state, uid, abilId)` (flag.ts) は scene/case のみ走査するため、off-board の uid では
**無言で no-op** → declaredUseCount が増えず、limit:turn:1 の gate が常に pass → 同ターン複数回使用可。

### 現状の影響: 無し
- 該当条件 = 「自身を場外へ移すコスト」AND「ターン回数制限」。MVP で `selfToDeckBottom` を持つ宣言能力は
  **D11012 a1 のみ**で、これは limit を持たない。よって現カードでは無影響。grep 確認済。
- そもそも declaredUseCount は scene char object に保持するため、char が場を離れると保持先が消える
  (構造的に off-board char の limit 追跡は不可能)。

## 恒久対応案 (DEFERRED)
- cost.pay の **前** に increment する (source が場上のうちにカウント)、または
- 該当ターンの「カード単位 (cardId+abilId) 使用回数」を player/turnState 側で追跡する設計に変更。
- どちらも該当カードが出てから実装すれば良い (現状は YAGNI)。

## 補足 (関連 review 指摘、同じく DEFERRED)
- 「`selfToDeckBottom` コスト + effect が `$self` 参照」の組み合わせは off-board で silent fail する設計脆弱性
  (現状 D11012 a1 は `$self` 非参照で安全、D11005 a2 は sleepSelf で on-board)。カード設計規約に注記推奨。
