## 仕様 (rules/17 §【ターン①】)
宣言能力に【ターン①】等の回数制限がある場合、使用ごとに declaredUseCount を increment し、
次の canDeclaredAbility で上限到達を gate すべき。

## 実動作 (latent バグ)
`selfToDeckBottom` 等「自身を場外へ移す」コストは useDeclaredAbility 呼出前に source を scene→deck へ移す。
`incrDeclaredUseCount(state, uid, abilId)` (flag.ts) は scene/case のみ走査するため、off-board の uid では
**無言で no-op** → declaredUseCount が増えず、limit:turn:1 の gate が常に pass → 同ターン複数回使用可。

### 現状の影響: 無し
- 該当条件 = 「自身を場外へ移すコスト」AND「ターン回数制限」。MVP で `selfToDeckBottom` を持つ宣言能力は
  **D11012 a1 のみ**で、これは limit を持たない。よって現カードでは無影響。grep 確認済。
- そもそも declaredUseCount は scene char object に保持するため、char が場を離れると保持先が消える
  (構造的に off-board char の limit 追跡は不可能)。

## 修正 (2026-06-07, TDD)
**player 単位 turnState fallback** を採用 (per-instance=uid 単位の意味を維持、複数コピーは別 uid なので
cardId 単位化は不採用 = multi-copy の【ターン①】を壊さない):
- `mutate.flag.incrDeclaredUseCount(s, uid, abilId, player?)` — scene/case で見つからない off-board uid は
  `s.turnState[player].declaredAbilityUseCount[uid:abilId]` に fallback 記録 (従来未使用の field を活用)。
- `read.char.declaredUseCount` — scene/case 不在時に同 fallback (self/opp 両 turnState) を参照。
- `flow/main/declared-ability.ts useDeclaredAbility` — `found.player` (BUG-108 救済の player) を渡す。
- turnState は `resetTurnFlags` でターン境界クリア → 【ターン①】の turn-scope と整合。

### 当初案を不採用にした理由
- 「cost.pay 前に increment」: selfToDeckBottom は char object 自体を場外へ出すため、char に記録しても
  保持先が消える → 不可。player 単位 fallback が必要。
- 「cardId 単位追跡」: 同名カード 2 コピーの【ターン①】が合算され誤enforcement → per-instance を壊す。
