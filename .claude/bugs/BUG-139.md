## 概要

self 所有の**必須 pick** (nMin>=1、例: D08026 t1「解決編になったとき、自分は手札を1枚リムーブする」の
discard pick) が surface されたままでも `endTurn` dispatch が許可されていた。rules/05
(効果解決中は次の行動に移れない) 違反。

放置された pick は従来どこにも回収されず**必須効果が黙って不発のまま永久放置** (修正前の実測:
human FILE7 到達 → 解決編化 → discard pick → ターン終了可能 → pick は store に残留し誰も解決しない)。
X8 (BUG-138) で CPU が human pick を横取りしなくなった結果、CPU ターンが正しく待機する＝stall
として顕在化した (e2e full-match で検出)。

## 修正

- `useEngineDispatch.canX('endTurn')`: self 所有の必須 pick (nMin>=1) が store に残っている間は
  ターン終了不可 (narrow gate — 任意 pick / optional / choice は modal が skip/decline を提供
  するため対象外)
- e2e full-match robot: 実プレイヤーと同様に prompt を解決してから進行する
  (`resolvePendingPrompts` — 必須 pick=先頭候補 / 任意=skip / optional=しない / choice=0)

## 影響範囲 / 水平展開

- 解決編化 discard を持つ case カード全件 (D08026/D09027/D06019/B08094 ほか「解決編になったとき」族)
  + self turn 中に必須 pick を積む全カード
- engine 側 (`flow.endTurn`) には gate を足していない — smoke (CPU vs CPU) は drain で
  pick が必ず解決されるため不要。UI dispatch 層のみで十分 (human の操作経路は dispatch 一本)
- AI (playTurn) は X8 の hasPendingHumanPick pause が同等の gate を提供済

## 防止策

- 「必須効果の pick を積む」カードの MCP 実機検証では「未解決のままターン終了できない」ことを確認項目に追加
