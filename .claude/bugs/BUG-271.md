# Resolved effect history was shown as an active stack

## Expected

The public effect-stack indicator shows only `pending` or `resolving` effects.

## Actual

During row 023, after CPU 疾風 AP reduction resolved, the public header still
showed `効果スタック 1件`. Resolved entries are retained as history, so the old
raw-array count falsely implied an unresolved effect and made the CPU overlay
look stalled.

## Evidence and RCA

- Public UI showed the stale count; the public log already showed the AP result.
- `interactionLock` correctly filtered active states, but `useTopBar` used
  `pendingEffects.length`.

## Fix, prevention, and horizontal check

- `countUnresolvedEffects` filters to `pending|resolving` before TopBar display.
- RED/GREEN regression: resolved + cancelled + pending history now displays 1.
- Focused Vitest: `useTopBar` and opponent-turn driver, 11 tests passed.
