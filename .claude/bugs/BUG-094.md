## 仕様 (rules/12, 17)

ネクストヒント step2: FILE枚数以下のレベルのキャラ/イベントを1枚使用できる。
- rules/12: step1 で手札に加えたカードは step2 の FILE枚数判定に数えない。
- rules/17 【FILE(X)】: **アシストしているパートナーも FILE 枚数に数える**。

## 期待動作

step2 の候補化/強調表示の level 閾値 = post-pop の FILE枚数 (アシスト中パートナーを含む)
= engine next-hint.ts の `level ≤ file.length` 判定と一致。

## 実動作

アシスト中パートナーが FILE にいるとき、**強調表示の閾値が 1 少ない**。
- FILE 表示 6 (パートナー含む) なのにレベル6カードが強調されず「レベル5以下」になる。
- engine は level ≤ 6 を許可するが UI 候補フィルタが弾く → ユーザーが選べない。

## RCA

- `useActionsPanelFlow.runNextHintFlow` が閾値を
  `postPopCount = nonAssistedCount - 1` で算出。`nonAssistedCount` は
  **`f.type !== 'assisted-partner'` のみカウント (パートナー除外)**。
- パートナー1枚アシスト中だと `nonAssistedCount = file.length - 1` → `postPopCount = file.length - 2`。
  step1 カードとパートナーの **二重減算** になっていた。
- engine (next-hint.ts:89) は `d.level > state.players[p].file.length` (post-pop, パートナー含む) で
  判定しており UI と不整合。BUG-087 修正時にパートナー不在ケースしか検証せず base 誤りを見落とした。

## 修正

- `postPopCount = file.length - 1` に変更 (アシスト中パートナーを含む total FILE - step1 カード)。
  engine の post-pop file.length 判定と一致。未使用化した nonAssistedCount ループを除去。
- パートナー不在時は `file.length - 1 == nonAssistedCount - 1` で BUG-087 と同値 (回帰なし)。

## テスト / 防止策

- `tests/ui/hooks/useActionsPanelFlow.nextHint.test.ts` に BUG-094:
  FILE 4 (非partner 3 + assisted-partner 1) → postPopCount=3 / Lv3 候補内 (修正前 fail)。
- BUG-087 既存テスト (パートナー不在) 継続 pass / full vitest 1654 pass / tsc green。
