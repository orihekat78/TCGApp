# BUG-180: handAddFromDeck / sceneEnter(deck-splice) が take 後 deck0 の即リフレッシュを行わない

## 期待動作

rules/14「デッキが0枚になった時点で即座にリフレッシュ」+ rules/26 / B03049 公式QA
「登場させたか手札に加えた時点でデッキのカードがなくなったことになり、リフレッシュを行います」。

## 実動作

- `atomHandAddFromDeck` (core.ts:865) と `atomSceneEnter` の deck-source splice (scene.ts:184) は
  take 後に deck.length===0 になっても `mutate.deck.refresh` を呼ばない。
- 相手が本来得る証拠 1 枚 (rules/14 手順2) が得られない / リフレッシュ敗北判定が次の deck 参照まで遅延。
- 再現: デッキ残1枚で B03049 a1 宣言 → 1枚が登場 or 手札 → deck=0 のまま進行 (review 実測
  `deck=0 remove=3 oppEv=0`)。

## RCA

positional 兄弟 verb `atomHandAddFromDeckBottom` (core.ts:888、B03051 Q&A 準拠) は pre/post refresh
guard を実装済 — bind-based の handAddFromDeck と sceneEnter deck-splice だけが guard を欠く非対称。
導入時 (engine-extension #5a) の消費者が「上から N 枚見て…残りデッキ下」型で take 後 deck0 が
実質発生しなかったため顕在化しなかった。

## 水平展開

- 露出消費者 = handAddFromDeck / sceneEnter(from deck) を使う既存 shipped ~152 枚 (deckRevealUntil 系)。
  全て同 class (既存同等) — mini-wave #5 の fromBottom で新規劣化はしない (B03049 else 枝は
  handAddFromDeckBottom に切替済みで guard あり)。
- 対応方針 (次 wave): atomHandAddFromDeck / sceneEnter deck-splice の take 直後に
  handAddFromDeckBottom と同じ post-take refresh 検査を追加 (additive、既存パスは deck>0 で不変)。
  smoke baseline 影響を実測すること。
- ★同 class 追加発見 (2026-07-10 S2 B08057 grounding): **cost 側 removeDeckTop** (cost/pay.ts
  case 'removeDeckTop' → mutate/deck.ts removeFromTop) も post-pay deck=0 の即時リフレッシュ
  (rules/14「行動の途中でも0枚になった時点で実施」) を持たない。B08057 (n:9) がデッキちょうど9枚で
  宣言した場合に露出。sceneEnter cardIds-multi deck-splice (S2 B01022 新経路) も同 class。
  修正時は上記 2 site と合わせて 4 site 一括で。
