## 概要

人間vsCPU で CPU の手を 1 手ずつ可視化 (Task4 per-move) したところ、「登場時効果が毎ターン
発動している」「効果が毎ターン同じキャラに適用される」ように見えると報告。調査の結果、Task4 の
regression **ではなく** CPU 可視化で顕在化した既存バグ (engine) + Task4 由来の UI fallback バグの複合。

## 期待動作 / 実動作

- 期待: キャラ召喚で発火するのは【登場時】(enter hook) のみ。【カットイン】はコンタクト中の
  cutin 起動時のみ発火。効果スタック表示は未解決効果数。解決済み効果はポップを出さない。
- 実動作: キャラ召喚毎に【カットイン】持ちカード (円谷光彦 D08017 等) の charModifyAP が誤って
  pendingEffects に積まれ (コンタクト外なので noop だが) **resolved のまま蓄積**。
  「効果スタック」counter が毎ターン +1。さらに古い解決済み entry を UI が拾い「効果解決」
  ポップが毎ターン幻のように出続ける (entry.source が現場カードだと該当カードに浮く)。

## 根本原因 (3 つ)

- **D1 (engine, 既存):** `handUseCard` はキャラ召喚で `effect:declared {kind:'character-use'}` を emit。
  【カットイン】ability は `trigger {hook:'effect:declared', optional:true, selfOnly:true}` で matcher が
  無く、自分の召喚 emit にも selfOnly 一致 → cutin 効果 (`charModifyAP $contact.byUid`) を queue。
  本来カットインは `flow.contact.cutIn` の emit (`payload.abilityId==='cutin'`) でのみ発火すべき。
- **D2 (ui, Task4 regression):** `Playmat` の activeCard fallback `find(resolving) ?? pendingEffects[0]`
  が **解決済み entry を拾う** (pendingEffects は resolved を prune しない) → 幻の「効果解決」ポップ。
- **D3 (ui, 既存):** 効果スタック counter = `pendingEffects.length` が resolved/cancelled も数える。

## 関連ファイル

- `src/engine/listeners/triggered.ts` (handleHook — effect:declared 走査)
- `src/engine/flow/main/hand-use-card.ts` / `flow/contact.ts` (effect:declared emit 2 経路)
- `src/ui/components/Playmat.tsx` (activeEffectEntry fallback / effectStackCount)
- `src/cards/ct-d08/D08017.ts` 他 cutin カード (optional effect:declared)

## 修正

1. **D1**: `handleHook` で `hook==='effect:declared' && trig.optional===true` の ability は
   `payload.abilityId==='cutin'` (真の cutin 起動) 以外では skip。召喚/イベント使用の emit
   (payload.kind set / abilityId なし) では発火しない。
2. **D2**: `activeEffectEntry = find(resolving) ?? find(pending)` に変更 (resolved/cancelled を採用しない)。
3. **D3**: `effectStackCount` を pending/resolving のみ数える。

## 水平展開

- 全 1350 カードを registry 走査: `effect:declared` ability で guard (optional / matcher /
  matcherCondition) が **無い** ものは **0 件**。cutin (optional) 群が誤発火クラスの全件で、D1 で完全閉鎖。
- 非 cutin の effect:declared は全件 matcher (kind==='event-use') / matcherCondition で gate 済 (回帰なし)。
- D2/D3 は cutin 由来に限らず「解決済み entry 蓄積」全般に効く一般修正。

## 防止策 / 教訓

- effect:declared は「カード使用」汎用 hook。**kind (event-use/character-use) または abilityId
  (cutin) で必ず discriminate** する。optional だけでは generic listener が拾う。
- pendingEffects は resolved を prune しない設計。UI は **必ず state でフィルタ**して読む
  (`pendingEffects[0]` の素朴 fallback は古い解決済みを拾う)。
- 可視化機能は既存の「無害な内部残留」を**表面化**させる。可視化導入時は state 残留物を点検する。
