## 概要

`charSetCard{fromDeckTop:true}` (atom-handlers/char.ts:186 `atomCharSetCard`) は
**deck.shift() で上端カードを除去してから** `mutate.char.setCard(scUid, ...)` を呼ぶ。
`setCard` は host が現場に不在なら `if (!found) return;` (mutate/char.ts:210-213) で no-op。
→ host 離場時、シフトした上端カードが **deck からも remove からも消える (カード消失)**。

## 期待動作 / 実動作

- 期待 (公式Q&A、B05035 等): 効果解決までに対象キャラ (host) が現場を離れていたら
  「裏向きでセット」は実行できず、**公開した/上端のカードはそのままデッキの上に戻す**。
- 実動作: `deck.shift()` が先に走り、その後 `setCard` が host 不在で no-op →
  カードはデッキにも戻らず、リムーブにも入らず、setCards にも付かない = **消失**。

## 根本原因

`atomCharSetCard` の fromDeckTop 分岐 (char.ts:208-220) が **「シフト → setCard」** の順:

```
scCardId = sscDeck.shift()!;          // 先に deck から除去
mutate.char.setCard(s, scUid, scCardId, faceUp);  // host 不在なら no-op (カード行き場なし)
```

host 存在チェックを **shift の前** に置けば修正可能 (host 不在なら shift せず return = カードは deck 上端に残る)。

## 影響範囲 (水平展開)

`charSetCard{fromDeckTop}` を使う全カード (B03061 / B07034 a2 / PR099 a1 / B05030 a1 / B02018 / B02020 /
B02023 / B02030 / B08054 等)。ただし発火は **host 離場が effect 解決前に起きる**場合のみ:

- 単発 atom (B03061/B05030/PR099 等) は enter と atom の間に介入が無く **実用上到達不能**。
- 複数キャラ同時登場 + 一方の【登場時】が他方を除去、等の稀な interleave でのみ到達。
- **B05035 のみ公式Q&A が host-absent 挙動を明示** (「デッキの上に戻す」) → faithfulness 上の差。
  そのため B05035 は本 wave で DEFER (engine変更0 では DSL 修正不可)。他の一族は Q&A 非言及ゆえ
  従来基準で faithful 扱いを維持。

## 修正方針 (未着手、engine additive)

`atomCharSetCard` fromDeckTop 分岐で `findChar(s, scUid)` を **shift 前**に確認し、不在なら
何もせず return (カードを deck 上端に残す)。動作不変 (host 存在時は従来通り) ゆえ回帰ゼロ。
修正後 B05035 を再出荷可 (DEFERRED-INDEX §codegen-handcount-setevent 解禁条件)。

## 防止策

set-facedown 一族の host-absent エッジを decoy test に追加 (host を effect 前に scene から外し、
deck カードが消失せず上端に残ることを assert)。
