## 期待動作

「デッキの上から1枚を裏向きでセットする」効果でデッキが0枚の場合、rules/14・26 と公式Q&A
(B08033「デッキの残り全部セット→リフレッシュ→残り分セット」) に従い **リフレッシュ後にセット** する。
リムーブエリアも0枚ならリフレッシュ失敗 = そのプレイヤーは **敗北** (deck-out)。

## 実動作

`char.ts` の `charSetCard{fromDeckTop}` は deck0 時に `log 'empty-deck'; return` で **silent no-op**
(セットも refresh も敗北判定も行わない)。draw / fileAdd / evidenceGain は BUG-142 (cluster3) で
deck0→refresh を配線済だが、charSetCard は取り残されていた (同族 latent bug)。

→ 36 枚の fromDeckTop 使用カード (B02018/B02020/B02023/B02030/B05030/B08054 等) が、deck0 時に
rules/14 違反の挙動 (セット不発・refresh penalty 無し) を示していた。

## RCA

deck-pull を行う atom への refresh guard 配線が、BUG-142 時に draw/fileAdd/evidenceGain のみに適用され、
charSetCard{fromDeckTop} が水平展開から漏れていた。

## 修正

`char.ts` の empty-deck no-op を draw/fileAdd/evidenceGain (core.ts:201-220) と同型の
refresh-then-loss に置換:

```ts
if (s.players[sscP].deck.length === 0) {
  const r = mutate.deck.refresh(s, sscP);
  if (!r.ok) {
    if (s.gameResult === undefined) mutate.gameResult.set(s, sscP === 'self' ? 'opp' : 'self', 'deck-out');
    mutate.log.append(s, { ..., result: 'empty-deck-refresh-fail' });
    return;
  }
}
scCardId = s.players[sscP].deck.shift()!;
```

BUG-153 の host-absent 早期 return は **refresh より前** に維持 (host 不在なら deck/remove を一切触らない)。

## 水平展開

- charSetCard の deck-pull は `char.ts` の単一 `deck.shift()` (短縮形 path も resolve 後この explicit-uid
  分岐に再 dispatch) → 単一 site 修正で 36 カード全てを被覆。
- 他の deck-pull atom (draw/fileAdd/evidenceGain/mill) は BUG-142/137 で配線済を確認。reasoning の
  addFromDeck は別経路 (cluster3 既知ギャップ、本 bug 対象外)。
