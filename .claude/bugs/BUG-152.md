## 解決 (Phase 3g、2026-06-22)

着手前 opus 3 lens 設計レビュー (403k tok) + ALL_CARDS 1374 枚の object-walk grounding により、
**活性バグは存在しない**ことを確定: chain node 126 個のうち、step が `choice`/`optional` のものは
subtree 含め **0 件**。chain step の atom `$pick` は pre-walk ではなく **dispatch 時** に
`resolver.ts:78` chain case → `run(step)` → atom-handler `tryRePickFromAtom` で解決されるため、
chain を pre-walk しなくても drop しない。B02068/B04023 は optional が chain を **wrap** (step でない)。

→ 対応は **Option A** (chain を walk して救済する Option B ではなく) **明示 passthrough + exhaustiveness ガード**:
`case 'chain': case 'negate': case 'custom': return effect` + `default: { const _exhaustive: never = effect; void _exhaustive; return effect }`。
これで Effect union 11 member の脱落が compile-time (TS2322) で検出され、resolver.ts:174 との構造非対称が解消。
runtime は現挙動を完全保存 (chain/negate/custom は従来 default と参照同一の effect を返す)。

**残 latent**: 将来 chain の step に `choice`/`optional` を持つカードが追加された場合は、`case 'chain'` を
sequence と同様に walk する実装 (Option B) が必要になる。現時点では出荷カード 0 件のため scope 外。

## 概要

refactor Phase 3e/3f の水平展開で発見。`src/engine/effect/resolve-picks.ts:431` の `switch (effect.kind)`
(`$pick` placeholder を列挙候補で置換するため Effect 木を walk) が Effect union 11 member のうち
**`chain` の case を持たない**。未処理 kind は `default: return effect` (L562) で **そのまま返る** (un-walked)。
guarded sibling の `resolver.ts:78` は `case 'chain'` を持つ。

**構造非対称は確認済 (機械検証: resolve-picks の case = atom/sequence/parallel/choice/optional/conditional/
forEach/replace/negate/custom + default、`chain` なし)**。runtime 影響 (実際に top-level chain 内の `$pick` が
落ちるカードが存在するか) は **未確認** — Phase 3g で確定する。

## 期待動作 / 実動作

- 期待: `resolveEffectPicks` は Effect 木全体を walk し `$pick` を置換する。chain の各 step 内に `$pick` が
  あれば置換される (resolver が chain を handle するのと同様)。
- 実動作 (構造上): top-level `chain` effect は `default: return effect` に落ち walk されない。chain step が
  dispatch ごとに resolveEffectPicks を再入するなら実害なし (要確認)。

## 調査方針 (Phase 3g)

1. chain step が dispatch 時に resolveEffectPicks を再入するか確認 (再入するなら実害なし)。
2. 実害ありなら `case 'chain'` を追加 (sequence ブロック踏襲で chain の各 step を walk)。
3. その後 `default` を never ガード化 (applyMove/3e と同型)。
   ※ default は現状 negate/custom/chain の reachable passthrough ゆえ、never 化前にこれらを明示処理する要あり。

## 防止策 / 教訓

- 同一 union (Effect) を walk する switch が複数 (resolve-picks / resolver) ある場合、case 集合を機械突合する
  lint or default:never で乖離を compile-time 検出する (Phase 3f が applyMove で実施した手法)。
