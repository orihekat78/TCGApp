## RCA (確定 — Round 4c)

実機 Playwright で再現確認: `actionDeclareCase` 後に driver が `'judge'` phase で **stuck** 、`actionJudge` を発火せず evidence 不変動。

**根本原因**: `src/ui/state/store.ts:78-82` の `dispatch` は `mutator(current)` (= `produce(state, draft => ...)`) の結果を `set({ gameState: ... })` するが、state-machine `advance()` は module-level `ax.phase` のみ変更し draft を mutate しないケースがある (`contact-pending → judge` の case shortcut, state-machine.ts L319-323)。Immer produce は draft 未変更なら同一参照を返すため、Zustand setState で同一参照 → subscribers 未起動 → `useContactFlowDriver` の useEffect が再 run しない → judge phase で永遠に停止。

dispatch chain 自体は `tests/integration/dispatch-to-state.test.ts` で正常確認済 (sequential dispatch なら subscriber 不要のため pass)。E2E (`tests/e2e/bug-006.spec.ts`) で初めて driver reactivity の問題が浮上。

**修正** (`src/ui/state/store.ts`): `dispatch` で `Object.is(next, current)` なら `{ ...current }` で shallow copy して必ず新参照を保証。

## 水平展開

- **action[char] flow**: 同じ state-machine を通るが、`contact-pending → action-1` 経路で `flow.contact.snapshotAP` が gameState を必ず mutate するため影響なし。BUG-006 は **case-target shortcut のみ** advance() が draft を一切変えない唯一の経路だった。
- **CPU vs CPU**: `resolveActionAgainstCase` (one-shot) は driver を介さないため影響なし (smoke 1000 戦が 524/476 baseline 維持で実証)。
- **他 dispatch**: 修正は store.dispatch 全体に効き、advance 系の他の no-op 遷移 (将来追加されうる) も先回り保護。
