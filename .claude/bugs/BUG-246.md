## Expected

AI move enumeration includes payable declared abilities with `scope: 'on-hand'`, matching the UI source enumerator.

## Actual

`enumDeclaredAbilitySources` includes hand sentinels, but `enumerateMoves` only adds scene, case, and partner-area MR declared abilities.

## RCA

The AI declared-ability loop predates the on-hand source path and has no hand-card iteration.

## Plan

Add the matching hand sentinel loop through `canActivateDeclaredAbility`, then cover AI/UI parity with a public-dispatch regression.

## Fix and grounding

- Rules 05/15/21: declarations are legal only for the current player's main phase and only when the declared cost is payable; `canActivateDeclaredAbility` is the existing shared admission boundary.
- `enumerateMoves` now iterates unique hand card IDs with the canonical `hand:<owner>:<cardId>` sentinel and that boundary. No external API changed.
- `makeDeclaredAbilCtx` now resolves the same hand sentinel for AI cost handling. A direct `sceneEnter` from that source hand consumes one matching card, preventing B06103/B06103P duplicate entry.
- Regression uses asymmetric self/opp hands. It proves allowed dispatch, insufficient cost rejection, ownership/non-main phase/pending/resolver rejection, duplicate identity de-duplication, and stale-source rejection across UI, AI, and public dispatch.
- Shipped B06103 and B06103P run through opp CPU `stepTurn`: their black-character cost is removed, exactly one duplicate hand card is consumed, the card enters asleep, and the effect resolves.
