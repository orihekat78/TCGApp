# live resolver関数によるReplay記録失敗

## 発見契機

公開SETUPから30ターンまで進める実ブラウザE2Eで、D11005解決中の
`structuredClone(state)`が`DataCloneError`になった。

## 期待動作

対戦中の一時resolver表現に関係なく、閲覧専用Replayを記録できる。
Replay読込はlive runtimeをhydrateしない。

## 実動作（修正前）

Replay recorderが生GameStateをcloneし、`TargetFilter.custom`などの関数を含む
`pendingEffects`で失敗した。V3読込は投影前にstore準備を行い、一時runtimeを
global side channelへhydrateし得た。

## RCA

閲覧用artifactと再開可能GameStateの境界が未定義だった。記録と読込の双方で
live resolver continuationを生状態として扱っていた。

## 修正

- 記録時にread-only playback projectionを作り、pending/reserved effect、
  action context、runtime・reasoning・turn・batch continuationを除去。
- V3読込はviewer projectionを先に行い、その後store正規化する。
- 許可外の関数値は引き続きclone失敗とし、無差別な除去は行わない。
- artifactは閲覧専用で、対戦再開用saveではないと仕様へ明記。

## 水平展開

Recorder、viewer projection、V3 load、legacy decoder、seek、History artifact loadを監査。
V1/V2のmove再実行はisolated runtimeを使う既存経路を維持した。
D11005の固定8000 custom filterは`apMaxSource`への別改善候補。

## 検証

- GREEN: recorder / projection / driver focused 29件通過。
