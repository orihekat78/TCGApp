## ユーザー指摘

> #13: 登場時効果があるカードなど特定のカードが手札から出せない

## 期待動作 (rules/20 §スイッチ)

自分の現場に置けるキャラは 5 枚まで。キャラを登場させる際に現場が埋まって
いる場合、既にいるキャラを **リムーブして新キャラを登場させる (スイッチ)**
ができる。リムーブ対象のキャラに状態 (アクティブ/スリープ/スタン/名乗り)
の制限はない。

## 実動作 (修正前)

scene が 5 枚埋まっている状態で、自分の手札にあるキャラカード (色 OK、
レベル ≤ FILE 枚数、handUseUsed 未消費) を使用しようとすると:

- `src/ui/components/Playmat.tsx:367` の `canUse` prop が
  `engineFlow.canHandUseCard()` **のみ** を評価
- `canHandUseCard()` は `scene.length >= 5` で false 返す (switch は別関数)
- HandZone → HandCard 経由で `disabled={true}` が降りる
- `HandCard:75` `onClick={disabled ? undefined : onClick}` で **click 不能**

結果、現場満員時はキャラカードが画面上で grey-out され、tooltip で
「(スイッチ機能で既存キャラと交換可能)」と表示されるにもかかわらず、
**ユーザーは何もクリックできない** = 「特定のカードが出せない」と認識。

## RCA (Root Cause Analysis)

engine 層 / flow 層 / picker store / dispatch — **すべての層で switch 経路は
実装完成済み** だったが、Playmat.tsx の `canUse` prop が switch を考慮せず
`canHandUseCard` のみで判定していたため、UI 側で disabled となり click 不能。

BUG-040 (#15 declared ability) と **完全に同じ pattern**:
「engine + flow + picker は全部実装済みなのに、Playmat.tsx の prop 受け渡し
で 1 行漏れて UI が動かない」。Phase 8 で hand-use の switch 経路が後から
追加されたとき、`canUse` prop の更新を忘れたと推測。

unit test `useActionsPanelFlow.test.ts` は `runHandUseFlow` を直接呼ぶ
ため、`canUse` prop の漏れを検出できなかった。

## 水平展開

Playmat.tsx の他の prop で同様の「正路のみ確認」漏れがないか調査:

## 修正

### Playmat.tsx (4 行)

```diff
   canUse={(c) =>
-    gameState !== null && engineFlow.canHandUseCard(gameState, 'self', c.cardId)
+    gameState !== null && (
+      engineFlow.canHandUseCard(gameState, 'self', c.cardId) ||
+      engineFlow.canHandUseCardSwitch(gameState, 'self', c.cardId)
+    )
   }
```

### handUseReason.ts (1 ブロック削除 + コメント追加)

scene 5 枚で問答無用に reject していたメッセージを削除、switch fallback が
UI 側で評価されることを明示するコメントを追加。null 返却で UI の clickable
を維持。
