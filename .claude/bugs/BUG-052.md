## ユーザー指摘

> #12: 十五の受難を使用したときに登場するカードが？？？になっている。効果が
> 正常に行われていないし、デッキの上からカードを順にめっくていく演出が
> 入っていない。

## 期待動作

D11019「15の受難」(イベント):
> 自分のデッキのカードを上からレベル4以下の【黄】のキャラが出るまで1枚ずつ
> 公開し、それを登場させる。残りの公開したカードをデッキの下に移し、デッキ
> をシャッフルする。自分のリムーブエリアに【黄】のカードが20枚以上ある場合、
> ターン終了時までそのキャラに〚突撃［事件］〛を持たせる。

エンジン effect:
1. `deckRevealUntil` → `$matched` に該当カードを bind
2. `sceneEnter` で `$matched.cardId` を登場
3. 残カードをデッキ下へ
4. デッキシャッフル
5. リムーブ黄20+ なら `charGrantKeyword` で `$matched.uid` に突撃

期待: 実カード名で登場、`??` 表示なし。

## 実動作 (修正前)

`src/engine/effect/atom-handlers.ts` の各 atom handler が `$<key>.<field>`
形式の bind reference をリテラル文字列のまま処理。`sceneEnter` の cardId
パラメータに `'$matched.cardId'` が渡され、`mutate.scene.enter(player,
'$matched.cardId', ...)` で SceneCharacter.cardId が `'$matched.cardId'` のまま
作成。UI が `resolveCard('$matched.cardId')` を呼ぶと null → 名前表示は
`??` (フォールバック)。

`charGrantKeyword` も同様に `$matched.uid` を解決せず、`mutate.char.grantKeyword`
が「不存在 uid」のため no-op → 突撃[事件] 付与されない。

deckRevealUntil 自体は BUG-045 で TargetFilter 対応済、bind は正しく作成
されている。問題は **後続 atom が bind を参照できない**こと。

`resolveEffectPicks` (Phase 7-2) は `$pick` を解決するが `$<key>.<field>`
パターンは未対応の gap。

## RCA (Root Cause Analysis)

Phase 7-2 で `$pick` resolver (BUG-035) を実装した際、bind reference の
substitution は別 task として defer されていた。D11019 が初の多 atom binding
sequence カードだったため、本 BUG が表面化するまで気付かれなかった。

Phase 1 探索で memory 5489: 「BUG-047 根本原因確定: D11019 が deckRevealUntil
に TargetFilter オブジェクトを渡すが handler が関数として呼ぶ」も同 D11019
関連で、`$matched` chain の問題は別 BUG として未着手だった。

## 修正

`src/engine/effect/atom-handlers.ts`:

1. `resolveBindRef(value, ctx)` helper を新規追加
   - `$<key>.<field>` パターン認識 (例: `$matched.cardId`)
   - `ctx.bindings[key]` から配列先頭要素を取り出して field 値を返却
   - 未解決 → 元 value 返却 (caller 側で gate)

2. `sceneEnter` case でcardId を resolveBindRef → 解決失敗時 no-op skip
3. `sceneEnter` で新 uid を `$matched.uid` に書き戻し (後続 charGrantKeyword
   が新 scene uid を参照できる)
4. `charGrantKeyword` / `charRevokeKeyword` で uid を resolveBindRef
