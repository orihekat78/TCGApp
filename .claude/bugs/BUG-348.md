# Contact participant exit termination

## 期待動作

- コンタクト中にどちらかの参加キャラが現場を離れた時点で、AP判定へ進まず
  コンタクト終了処理へ移る。
- B03050が1番目の行動で自身をリムーブした場合、相手の行動は発生しない。

## 修正前

- 参加者存在確認は`contact-order-pending`だけにあった。
- `action-1`は参加者が消えていても無条件で`action-2`へ遷移した。
- UI fallbackは欠落actorの所有者ではなくaction宣言者でpassを試みて拒否され、
  AIも同じstale contextを次のactorへ進めた。

## RCAと修正

- 行動順確定前と行動窓後で同じrules/08終端条件が分断されていた。
- participant presence判定を純粋な共通readerにし、action-1/action-2/redoの
  `advance`前に同じcontact-end遷移と`contact:end` emitを適用した。
- public advance gateは参加者欠落時の未回答flagを終端目的に限り許可し、UIは
  所有者不明の偽passを送らずcanonical advanceだけをdispatchする。
- UIはacted flag済みまたは片方欠落をmodal再表示より先にadvanceし、
  optional/pick/leave-intercept後の同じ行動窓を再回答させない。
- 同期AIは`contact:end`効果をdrainしてstate-owned contextを再取得してから
  action-endへ進み、続く`action:end`効果もdrainする。

## 回帰と水平確認

- RED: B03050 initial/saveは`action-1 → action-2`、generic FSMも4経路で再現。
- GREEN: B03050は相手modal前に終了し、save hydration後も同じ。
- B01098の両参加者除去はsecond action/AP judgeなしで終了する。
- UI driver、AI resolver、action-1/action-2/redo、両参加者残存controlを固定した。
- PR263/PR269がnon-current参加者をoptional/pickで除去する実経路と、PR269の
  save hydration後resumeを固定した。
- guard後の元target離脱、partner participant、effect-generated contactを含む。
- AIは早期終了/通常judge × character/guarded-caseでcontact:end効果が
  action:endより先に解決され、pending queueが空になることを固定した。
