## 仕様
D08021 a1 (登場時): リムーブの異名 [少年探偵団] を 0〜5枚選びこのキャラの下に重ねる (stackedCards 増加)。
これにより a2 突撃 / a3 draw / a4 evidenceGain が stackedCount で unlock される。

## 実動作 (バグ、empirical 確認)
charStackCard の multi-pick contract `cardIds:'$pick.cardIds'` が **AI/CPU 経路で未解決**:
resolve-picks.ts substituteAtomPick の AI heuristic Pattern B (337-371) は単一 pick の `target:[uid]` を
返すのみで `cardIds` を埋めない → cardIds が '$pick.cardIds' のまま handler 到達 → awaiting-pick で
side-channel push → AI は side-channel を drain しない → **stackedCards=0**。CPU の D08021 は a2/a3/a4 が
全 unlock されずバニラ 8000AP/2LP 化。cardIds 解決は human modal (useEngineDispatch effectPickResolve) のみ。

## 修正
resolve-picks.ts substituteAtomPick の AI 初期 walk (heuristic, Pattern A 分岐の直後) に
`args.cardIds === '$pick.cardIds'` 専用分岐を追加: card 候補から最大 max 枚を greedy 選択し
`cardIds` 配列に詰めて返す (target=pick-query は保持 → handler が source area から splice)。
guard 限定 (cardIds:'$pick.cardIds' = D08021 a1 のみ)、他 Pattern B atom (discard 等) は不変。

## 水平展開
cardIds:'$pick.cardIds' multi-pick contract を使うのは D08021 a1 のみ (grep 確認)。
⚠ 別 issue (未対応): AI が side-channel pick (単一 Pattern B: discard/evidenceToHand) を drain しない
構造問題は残存 (D08021 は初期 walk 解決で回避したが、汎用解決は別途)。

## 検証

smoke 1000 例外0 (500/500)。empirical repro で stackedCards 0→3 + remove=[] 確認。
