## 仕様 (rules/12)

ネクストヒント step2: 「FILEエリア枚数以下のレベルのキャラ/イベントを1枚使用できる。
**1で手札に加えたカードは2の判定時のFILE枚数に数えない**」。
→ step1 で FILE-top を抜くので、判定 FILE 枚数 = (非アシスト FILE 枚数 − 1)。

## 期待動作

NH picker 中に FILE-top が手札へ移った表示で FILE = 3 のとき、使用可能なのは **level ≤ 3** の手札カードまで。
(pre-pop FILE 4 → step1 で 1 枚 → postPopCount 3)

## 実動作

FILE 表示 3 で picker が「レベル4以下」と表示し、**Lv4 カードを選択可能**にしていた。
(選択して dispatch すると engine 側は post-pop file.length=3 で `4 > 3` → throw する危険もあった)

## RCA

- `useActionsPanelFlow.ts:212` `const postPopCount = nonAssistedCount ;` — doc コメント
  ([next-hint.ts:54](../../src/engine/flow/main/next-hint.ts) /
  [useActionsPanelFlow.ts:184](../../src/ui/hooks/useActionsPanelFlow.ts)) は「**− 1**」を明記しているのに
  コードで `- 1` が**欠落** (不自然な空白 `nonAssistedCount ;` が痕跡)。
- `nonAssistedCount` は flow 冒頭 (popTop 前) の非アシスト FILE 枚数 = pre-pop 値。
- picker は `level > postPopCount` で候補化 + banner「レベル{postPopCount}以下」を表示 → +1 ずれて表示・許可。
- 起源 commit: `9380314` (NextHint step2 UI 実装) — 元から欠落。BUG-085 マージとは無関係。

## 修正

`const postPopCount = nonAssistedCount - 1;`

## 水平展開

- engine `next-hint.ts:89` は popTop **後**の `file.length` で `level > file.length` を検査 → assist 無し時は
  post-pop = nonAssistedCount−1 で UI と一致 (修正で整合)。
- 通常「手札の使用」(`hand-use-card.ts levelAllowed`) は FILE-top を抜かないので `level ≤ file.length` (−1 なし) が正。
  NH のみ −1 が必要 → 誤って通常側に −1 を入れない。
- 残課題 (別 BUG 候補): assist 中パートナーが FILE にある場合、UI=非アシスト数 / engine=file.length(全) で
  しきい値が不一致になりうる (rules/17 FILE(X) は assist を数える ⇄ rules/12 は曖昧)。本バグ (assist 無し) とは別。

## テスト / 防止策

  (既存テストは Lv2 のみで両しきい値を通過していたため検出できなかった。)
