## ユーザー指摘

> #2: 蘭の一撃を使ったときに、効果が発動したんですがカードを自分で選べなかった。
> 自動でカードが選択されてしまった。
>
> #6: カードを選ぶ効果などユーザー依存の効果が自動で処理されるようになっている。
> 自動にするべき効果とユーザー依存にするべき効果を分けてください。また、
> 任意効果について確認してみてください。

## 期待動作

D08025「蘭の一撃」:
> 【パートナー青】AP8000以下のキャラを1枚まで選び、リムーブする。

- 「1 枚まで」 = `n: { min: 0, max: 1 }` の任意 (optional) 効果
- human player が使用したとき: ユーザーが対象を選ぶ (or 選ばないで no-op)
- AI が使用したとき: heuristic で自動選択

「自動にするべき効果」と「ユーザー依存にするべき効果」を engine + UI で
明確に分離する必要がある。

## 実動作 (修正前)

`src/engine/listeners/triggered.ts:157-161` で **player 不問** で
`HeuristicPolicy().chooseAtomTarget` を `resolveEffectPicks` に渡していた:

```ts
const aiPolicy = new HeuristicPolicy();
const resolvedEffect = resolveEffectPicks(state, ability.effect, resolveCtx, {
  chooseAtomTarget: aiPolicy.chooseAtomTarget?.bind(aiPolicy),
  byPlayer: card.player,
});
```

これにより human player が蘭の一撃を使っても、`$pick` target は AI heuristic
で「敵 max AP」が自動選択 → 「自分で選べなかった」体感。

## RCA (Root Cause Analysis)

Phase 7-3 で `chooseAtomTarget` を導入した際、「human / AI の player 区別」を
listener layer で持たず HeuristicPolicy を一律使用していた。spectator mode は
両 player AI なので問題なかったが、人間 vs CPU では human player の effect
にも AI heuristic が適用される gap があった。

加えて 任意効果 (`n.min === 0`) の semantics 通り「使わない」選択肢を human
に提示する UI 経路が完全未整備。

## 修正 (Phase 1: 自動選択停止のみ、UI 統合は別 BUG-054 で defer)

### 1. globalThis 側チャネル `_humanPlayerSide` 導入

`src/engine/listeners/triggered.ts` 冒頭に declare global + getter/setter
helper を追加 (hirameki / misread の側チャネル pattern と同形):

```ts
declare global {
  var __humanPlayerSide: 'self' | 'opp' | null | undefined;
}
function getHumanPlayerSide(): 'self' | 'opp' | null { ... }
export function _setHumanPlayerSide(side): void { ... }
```

### 2. UI から human side を反映

`src/App.tsx`:

```tsx
const spectatorMode = useGameStateStore((s) => s.spectatorMode);
useEffect(() => {
  _setHumanPlayerSide(spectatorMode ? null : 'self');
}, [spectatorMode]);
```

- 「対戦開始」(human vs CPU) → 'self'
- 「観戦モード」 (AI vs AI) → null

### 3. triggered.ts で human effect 時 chooseAtomTarget を skip

```ts
const humanSide = getHumanPlayerSide();
const isHumanEffect = humanSide !== null && card.player === humanSide;
const resolvedEffect = resolveEffectPicks(state, ability.effect, resolveCtx, {
  chooseAtomTarget: isHumanEffect
    ? undefined  // ← skip auto-pick for human-owned effects
    : aiPolicy.chooseAtomTarget?.bind(aiPolicy),
  byPlayer: card.player,
});
```

### 結果 (本 BUG では暫定)

- AI 所有 effect: 既存通り auto-pick (smoke baseline 維持)
- Human 所有 effect: `$pick` 未解決のまま queue → 該当 atom が no-op skip
  (BUG-052 の resolveBindRef 未解決時 pattern と同じ)
- 「誤選択」は無くなるが、「ユーザー自身で選ぶ UI」は未実装 → カード効果が
  目に見えない (画面に変化なし)。

## 残課題 (BUG-054 として別起票推奨)

- proper UI integration: pendingEffectPick 側チャネル + TargetPickerModal
  driver + dispatch path
- 任意効果 `n.min === 0` のときの「スキップ button」 (use カードしても
  no-op を選択できる UI)
- 必須効果 (`n.min >= 1`) で human が選ばない → ルール違反、強制 selection
