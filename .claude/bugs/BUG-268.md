## Expected

A choice owned by CPU is decided and fully resolved before `stepTurn` returns
to `useOppTurnDriver`. Human-owned choices remain surfaced to the UI.

## Actual

D11012/a1 created an `opp` choice. `stepTurn` drained picks but not choices,
then the driver surfaced the choice and stopped forever on its pending gate.

## RCA

`hasPendingHumanPick` correctly ignores an `opp` decision when human is
`self`, but no CPU choice drain existed between resolver completion and the
driver's side-channel transfer.

## Fix and proof

`drainAiEffectChoices` chooses the first CPU option, runs resolver completion,
and drains resulting CPU picks. A new `stepTurn` test was RED before this fix
and passes afterwards; D11012, choice-picker, driver, and AI smoke tests pass.

## Horizontal investigation

The drain is generic for all `PendingEffectChoiceSide` values and stops at a
human-owned decision, so nested CPU choices are handled without consuming a
human choice.
