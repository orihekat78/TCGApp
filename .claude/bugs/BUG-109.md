## 仕様 (rules/15, 17, 19)
CPU の疾風 AP-1000・リムーブ登場・各種 buff 等、PA 短縮形 atom を含む効果は人間同様に解決されるべき。

## 実動作 (バグ)
`substituteAtomPick` の walk 短縮形展開は `mode==='PB'` のみ。PA 短縮形 (charModifyAP/LP・sceneSetState・
sceneRemove・短縮形 sceneEnter) は walk で展開されず、runtime の atom-handler が `tryRePickFromAtom`
(humanChooser:true 強制) で `__pendingEffectPickQueue` へ push → **AI には drain 機構が無い** → silent no-op。
empirical probe: D11014 a1 (疾風 charModifyAP) AP 未適用 / D08024 a1 (短縮形 sceneEnter) reanimate せず。

## 修正 — AI drain (Approach B)
walk-expand (Aext) は per-verb 構築 risk + sequence の cross-step 依存 (D08024 step2 が step1 登場キャラを対象)
を pre-state で解決できないため不採用。runtime resolution の **AI drain** を採用:
- **新 engine module [apply-pick.ts](../../src/engine/effect/apply-pick.ts)**:
  - `applyPickAndContinuation(state, pending, pickedUid, pickedUids?)` — pending pick の resolved atom build
    (Pattern A/B) + 保存 ctx の runEffect 継続実行 (BUG-107)。human/AI **共通実体**。
  - `drainAiEffectPicks(state, policy)` — `__pendingEffectPickQueue` を heuristic (chooseAtomTarget /
    先頭 fallback) で順次解決。safety cap 64。
  - `resolveCardIdFromPickUid` を useEngineDispatch から移設 (重複排除)。
- **policy.playTurn**: applyMove + runAllUntilEmpty 後に `drainAiEffectPicks(draft, new HeuristicPolicy())`。
  useOppTurnDriver も playTurn 経由のため UI CPU 戦も同時にカバー。
- **useEngineDispatch.effectPickResolve**: inline build/continuation を `applyPickAndContinuation` 呼出に
  置換 (human 経路は同一挙動を維持、重複排除)。

## 効果範囲 / 水平展開
- charModifyAP/LP・sceneSetState・sceneRemove・短縮形 sceneEnter を持つ CPU カード全般が動作。
- cross-step sequence (D08024: sceneEnter→charModifyAP) も continuation で post-step1 盤面を見て解決。
- **D11012 a1 (BUG-108)**: AI の choice 効果が drain で適用されるようになった (既定 option0=LP+1)。
  AI の **intelligent な AP/LP 択一** (choiceIndex 選択) は branch 評価が必要で別途 (BUG-108 AI fan-out 残)。
