## 修正 (Phase 7-2 で完全完了)

### 新規 utility: `src/engine/effect/resolve-picks.ts` (~80 LOC)

[resolve-picks.ts](../../src/engine/effect/resolve-picks.ts) に recursive `resolveEffectPicks(state, effect, ctx)` 関数を新規作成:

- 全 effect kind walk: `atom` / `choice` / `sequence` / `parallel` / `optional` / `conditional` / `forEach` / `replace`
- `atom` で `args.uid === '$pick'` && `args.target.kind === 'pick'` を検出 → `engine.target.candidates` で列挙 → **先頭採用** → deep clone した atom で `args.uid = picked.uid` 置換 + `target` 削除
- 候補 0 件: 元 atom そのまま (rules/10 no-op fallback)

## 期待動作 (元の RCA)

`hiramekiResolve('fire')` または triggered ability fire 時、`$pick` を含む atom (sceneRemove / sceneSetState / sceneEnter / charModifyAP 等) が resolver で展開され、`engine.target.candidates` で候補列挙 → 1 件選択 → uid substitution → mutate 実行 → state 変化 (rules/10 + factory description)。

## 実動作 (修正前の no-op fallback)

`$pick` リテラルがそのまま atom-handler に渡り、`mutate.scene.setState` 等が「scene char uid='$pick'」を探して見つからず no-op。E2E 既存 (`tests/integration/hirameki-e2e.test.ts` Test 5) が「sceneSetState は対象 0 で no-op」と明示コメント。
