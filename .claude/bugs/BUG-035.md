## 期待動作

`hiramekiResolve('fire')` 時、`hiramekiCharStun` (effect = `choice → atom sceneSetState (uid:$pick, state:'sleep')`) が resolver で展開され:

1. choice の唯一 option (atom sceneSetState) が選択
2. `target: {kind:'pick', query:{area:'scene', side:'either'}, n:{min:0,max:1}}` で対象 1 件を pick
3. `$pick` placeholder が pick 結果の uid に substitution
4. `mutate.scene.setState(state, side, uid, 'sleep')` で scene char を sleep 化

→ scene char 1 件が sleep 状態になる (rules/10 + factory description)。

## 実動作 (現状の no-op fallback)

`hiramekiResolve('fire')` 後、scene char の state は **`'active'` 不変**。E2E (`tests/e2e/patterns/hirameki-char-stun.spec.ts`) で確認。

既存 `tests/integration/hirameki-e2e.test.ts:153-171` (Test 5) も「sceneSetState は対象 0 で no-op、dispatch は ok を返す」と明示コメント、state 変化検証は誰も書いていない (既知挙動)。

## RCA

- [src/engine/resolve/stack.ts:35-45](../../src/engine/resolve/stack.ts) `entryToCtx`: pendingEffects 解決時の ctx は `{source, bindings:{}, triggerPayload}` のみ、`dyn` field 未供給 → resolver の choice 分岐 (`resolver.ts:46`) は `ctx.dyn?.choiceIndex` 未定義 → `idx=0` 既定動作
- [src/engine/effect/atom-handlers.ts:154-157](../../src/engine/effect/atom-handlers.ts) `sceneSetState`: `a.uid as string` を **リテラル文字列のまま** `mutate.scene.setState` に渡す。`$pick` placeholder の substitution 処理は engine 全体で未実装 (Grep 確認、0 件)
- [src/engine/target/resolve.ts:11-26](../../src/engine/target/resolve.ts): `pick` kind は `picked` 引数必須で auto-resolve しない。pendingEffects 経路で `picked` を供給する仕組みが現状無い
- [src/engine/effect/resolver.ts:12](../../src/engine/effect/resolver.ts) コメント: 「UI からの選択ルーティングは **Phase 7** で実装する」 → known deferred マイルストーン

## 修正方針 (Phase 7 で実装予定)

1. `entryToCtx` に `dyn` 注入機構: choice index / pick result を pendingEffect から ctx に注入
2. `$pick` substitution API: atom resolver が ctx.dyn から pick result を取り出して `args.uid` 等を substitution
3. AI policy `chooseHiramekiCharStunTarget` 追加 (opp の hirameki も自動選択)
4. UI 経由 picked 供給: `hiramekiResolve` action に pick choice を含める拡張

修正後、本 spec の fire test を `expect(stateAfter).toBe('sleep')` に書き換えて effect 動作を確認。

## 防止策

- 共通クラスでの `$pick` 使用は Phase 7 完了まで shape verification のみで spec 化 (本 spec のパターン)
