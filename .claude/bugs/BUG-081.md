## ユーザー指摘

BUG-080 (NH step2 未実装) を調査中に user/Claude で同時発覚。

## 期待動作 (rules/12)

> ネクストヒントは **メインフェイズ中に何度でも** 使える、場の展開を加速させる仕組み。

- 制限なし、FILE が尽きるまで同ターン反復可能
- NH したターンは通常「手札の使用」不可 (別経路、rules/12 §Point)
- engine `canStartNextHint` は nextHintUsed を見ず FILE 残量のみ判定 = 反復許可済

## 実動作 (修正前)

[src/ui/components/ActionsPanel.tsx:106](../../src/ui/components/ActionsPanel.tsx#L106):
```typescript
disabled: nextHintUsed || nextHintFileCount === 0,
```

`runNextHint` は 1 回目で `nextHintUsed=true` を set するため、以降 button が永久 disable。
engine 側は反復許可、UI のみが過剰に塞いでいた。

## 関連ファイル

- [src/ui/components/ActionsPanel.tsx](../../src/ui/components/ActionsPanel.tsx) — `disabled: nextHintUsed || ...`
- [src/engine/flow/main/next-hint.ts](../../src/engine/flow/main/next-hint.ts) `canStartNextHint` — engine 側は FILE 残量のみで判定
- [src/ui/components/Playmat.tsx](../../src/ui/components/Playmat.tsx) — ActionsPanel に渡す canNextHint を engineFlow.canStartNextHint で計算するよう変更

## RCA

`nextHintUsed` フラグは元々「通常手札使用」を遮断するため engine が立てるもの (rules/12
の「NH したターンは手札の使用不可」)。UI 側で誤って **NH 自身** の disable 条件にも
転用していた。rules/12 を「NH したターンの手札使用不可」と読み替えると同フラグでも整合
するため発見されにくい混同 (UI 実装時の rules 解釈ズレ)。

## 修正 (commit 9380314)

- ActionsPanel: `nextHintUsed` を NH 自身の disable 条件から除去、新 prop `canNextHint: boolean`
  を受け `disabled: !canNextHint`。subtitle のみ「(使用済)」表示で履歴を残す
- Playmat: `canNextHint={gameState ? engineFlow.canStartNextHint(gameState, 'self') : false}`
  を渡す (engine の正しい判定にデリゲート)
- 通常「手札の使用」側の disable は別 prop `handUseRemaining`:
  `(handUseUsed || nextHintUsed) ? 0 : 1` で従来挙動を維持

## 水平展開

- 「engine canXxx に従わず UI が独自フラグで disable」パターンを ActionsPanel 全 button で
  audit:
  - 推理 / アクション / アシスト / 事件解決 / 宣言能力 / パートナー能力 / 手札の使用 —
    すべて engineFlow.canXxx もしくは state 値ベースで判定済、独自誤フラグなし
- NH のみが過去の実装で誤フラグ転用していた歴史 (今回限り)

- card-addition-checklist 系 lint に「button.disabled が engineFlow に対応する canXxx を呼んでいるか」
  チェックを追加 (将来) — 今回は単発のため手動 audit で水平展開クローズ
