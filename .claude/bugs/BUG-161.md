## 概要

`resolveEffectPicks` の `case 'conditional'` (src/engine/effect/resolve-picks.ts) が **then/else 両枝を無条件で walk**
していたため、`if` 条件に関わらず **非taken 枝**の `choice`/`optional`/explicit-`$pick` が
`pendingEffectChoice`/`pendingEffectOptional`/pickQueue として **eager-surface** (= human 経路で余計な modal/prompt)。

runtime (`resolver.ts:134`) は正しく `evalCond(if)` で taken 枝のみ実行するので、これは **pre-walk 専属の surface バグ**
(盤面は正しいが UI に余計な選択を出す)。BUG-145 §修正方針2 が「effect 側 conditional ラップは optional prompt を
gate しない」として既に記録し、当時は ability.condition で回避していた。本件はその **根治**。

## 影響 (shipped、全て over-fire 確認)

`kind:'conditional'` の then/else に choice/optional/$pick を持つ surfacer 8 family:
B06094/P (then:sequence[$pick], else:choice → else-choice が if=TRUE でも surface)、B04071/P・B05067/P
(single-option choice 内 $pick)、B09046/P・B02083 (sequence 非先頭 step の conditional)、PR137/PR143
(choice.options[0] 内 conditional→optional)、PR157/PR163 (conditional→optional)、B07070 (carrier、現状 no-op)。
全て probe で if=FALSE 時の余計 surface を再現。

## 期待動作 / 実動作

- 期待: pre-walk は runtime が実行する taken 枝の pick のみ surface。非taken 枝は surface しない。
- 旧実動作: 両枝 surface → if=TRUE でも else の choice modal が出る等。

## 修正方針 (engine — binding-aware gate)

★naive な `evalCond(if) ? walk(then) : walk(else)` は **deck-look family 約150枚を regress** する (実証: B06048 解決編
test red、discard 不発火)。理由: deck-look (B06048/B01048/B08020/B06010/B05017/D08xx) は conditional が sequence の
**非先頭 step** で `if` が前 step の `deckRevealUntil` 由来の **`$matched`/`$revealed` binding 依存** → pre-walk 時点で
binding 未設定 → evalCond stale-FALSE → 誤って then を RAW 化 → runtime の未 walk pick が target 無しで no-op。

**正解 = binding-aware gate**: helper `conditionIfIsStable(cond)`:
- `bound`/`boundMatchesFilter` → false (binding 依存)
- `not(.c)`/`and(.cs)`/`or(.cs)` を再帰
- default `!JSON.stringify(cond).includes('$')` ($-token を含む条件は保守的に unstable)

`conditional` case: **stable な if のみ** `evalCond` で taken 枝のみ walk (非taken は RAW)。**unstable は従来通り両枝 walk**
(byte-compatible、deck-look 保護)。double-eval safe (runtime resolver が再評価し真の taken のみ実行)。

## 残 latent edge (防止策) — opus 敵対 review (246枚機械走査+差分probe) 確定

- conditional 全 246枚: effect-level if は 168 bound + 16 boundMatchesFilter (= unstable→両枝walk維持、byte-compatible)。
  **stable-if かつ sequence 非先頭 step** は ~30枚、うち **前 step が if の読む domain を mutate する「disagreement」は 7枚**
  (D11020/B08048/B08092/B09021/P/B09092/P)。全て **安全**: short-form pick (sceneRemove{max:1}/discard{n:1}) のため
  AI 経路で stale-suppress されても **drainAiEffectPicks で recover** (probe 実証)。B09021 の disagreement は spurious
  (fileFlipTop は faceUp のみ変え cardId/type 不変)。Pattern-A-in-branch の 2枚 (B02083/B09046) は disagreement 無し。
- ★**真の latent hazard (現出荷 0 件)**: 〈stable-if disagreement (非先頭 step + 前 step が if domain を mutate)〉 **かつ**
  〈その taken 枝に Pattern-A pick (uid:'$pick'+explicit target)〉が同居する将来カード。Pattern-A は runtime awaiting-pick 経路が無く
  **drain で recover 不能** → silent drop (synthetic probe 実証)。short-form/Pattern-B は recover 可。
  → 防止: 「非先頭 conditional で stable-if が前 step mutate domain を読み、枝に Pattern-A pick」を検出する lint/assert を将来追加
  (= posIsFirstStep flag で board 述語を非先頭時 unstable 扱いにする拡張)。
- 教訓: conditional-branch の挙動変更は **naive gate が binding 依存族 (deck-look ~150枚) を壊す** → 必ず probe で確認してから。
  chain は resolve-picks で passthrough (未 walk) なので chain 内 conditional は本 gate に到達しない。
