# Headless inherited-accessor isolation

## Expected

Replay and AI simulation always observe an own `null` human-player side while the
headless callback runs, then restore the caller's exact own descriptor.

## Actual

Ordinary assignment invoked an inherited setter. No own property was created, so
the callback could still observe the inherited interactive player identity.

## RCA

Ownership was checked, but both temporary assignment and restoration used ordinary
property access instead of descriptor operations.

## Fix

Capture the exact own descriptor, define an own `null` data property, then restore
the descriptor or remove the temporary property in `finally`.

## Horizontal investigation

Replay, `runMatch`, MCTS, and tree policy all enter through the same headless helper.
Interactive readers remain shadowed by the temporary own `null` value.

## Prevention

The regression installs an inherited getter/setter and proves the setter is never
called, own `null` is visible during execution, and no own property leaks afterward.
