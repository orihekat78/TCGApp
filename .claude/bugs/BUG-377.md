# Per-character mill crosses refresh boundary

## Expected

- 「現場のキャラ1枚につき2枚リムーブ」は合計枚数を確定して1回解決する。
- デッキ不足時は残りをすべてリムーブし、refresh後は追加リムーブしない。

## Actual

- B07104/PとB09056/Pは`forEach`内で`mill 2`を繰り返した。
- 途中でrefreshすると後続反復が新しいデッキをリムーブした。

## Root cause and fix

- per-card iterationとaggregate quantityを同一視していた。
- `$self.sceneCount`を追加し、B07104/Pは両現場合計、B09056/Pは相手現場数を
  動的に1回評価するaggregate `mill`へ移行した。
- 初回修正ではAI pre-walkの`resolveDynArgs`が後続`mill.n`を前段除去より先に
  数値化し、除去前の枚数を固定した。atom consumer契約を明示し、`mill.n`だけを
  raw dynのまま運び、`atomMill`が実行時stateで評価するよう修正した。
- 既存millの可能な限り処理と単一refresh境界を再利用した。

## Horizontal investigation and prevention

- 全`forEach` + `mill` consumerを走査し、該当4 printingを同時修正した。
- 通常デッキ、短デッキ、両owner、全printingを公開経路で固定した。
- CPUが実キャラを先に除去する経路で、除去後`n=4`と古い`n=6`を識別した。
- engine unitで`mill.n`のruntime保持と、非mill dynのeager snapshot維持を固定した。
