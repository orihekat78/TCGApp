## 概要

rules/18 MR能力①② を additive engine 拡張で配線した (Phase 1 engine core)。実装は別 slot
`PlayerState.partnerAreaMR` を用い real partner singleton を非破壊。下記 **5件はルール条文に明示が無く
暫定保守解で実装**。公式 Q&A (commmune talk002) で裁定確認後に確定する。

⚠ **重要 (敵対review MAJOR-1 で訂正)**: 「MR カード 0枚出荷 → byte-identical」は誤り。**非MRカードの挙動は
byte-identical** (smoke winsA=498、MVP デッキ CT-D08/CT-D11 は MR を含まない) だが、**既登録の MR rarity
カード5 num (B05066/B07079/B07093/B08032/B09054 + 各P = 10 printing、`_reuse` 経由で registerAll 済)**
は `def.isMR`=rarity.startsWith('MR') により **MR①② が本変更で有効化され挙動が rules/18 準拠に変化する**
(意図的・正しい有効化)。これら5枚を含むデッキは byte-identical ではない。smoke は MVP デッキのみ回す harness の
ため MR デッキの additivity は検証していない (MR デッキ smoke は Phase 4 で検討)。card wave (Phase 4) 前に再確認。

## 暫定保守解 一覧

### #1 MR① 中間状態の順序 (rules/18:20-22 + 14)
- 【現場リムーブ時】hook を **先に**解決 (char は一旦 destination=remove に在席) → その後 PA へ移す。
  refresh 二重計上を防ぐため redirect 時に destination から cardId を pop/skip。
- 根拠: rules/18「離れた先のエリアへ一度置かれてから即座に行われる扱い」。
- 要確認: hook 解決中に refresh が走った場合の MR の所在 (remove か PA か)。

### #2 MR②による既存 MR 除去の分類 (rules/18:33)
- 現場 MR の MR②除去 = cause='effect' + noMrRedirect (相手ターン中でも PA へ redirect せず remove へ)。
  「能力によるリムーブ」(rules/18②)。
- PA 常駐 MR の MR②除去 = slot→remove、**現場離脱でないため【現場リムーブ時】hook 発火せず**。
- 要確認: PA 常駐 MR を MR②除去する際に何らかの hook/痕跡が発火すべきか。

### #3 PA-MR の相手 targetability / MR 枚数列挙 (candidates.ts)
- **未配線 (DEFER)**。candidates.ts は real partner 1体のみ列挙のまま。PA-MR は効果/アクションの
  対象候補に **出さない** (real partner も通常 action 対象でない conservative posture)。
- 要確認: PA-MR を対象指定する効果が存在するか (cohort SOLE 15 では不要)。

### #4 MR② × switch の順序 (rules/18②/20)
- switchEnter は MR②除去で **現場に空きが生まれたら victim 除去を skip** (over-removal 防止)。
  非 MR / PA-slot のみ除去 = 従来どおり victim 無条件除去 (回帰0)。
- residual gap: atom-handlers/scene.ts の **AI full-skip 経路** (`scene.length>=5 && !switchUid && !human`)
  は MR②前に fullness 判定するため、MR が満杯現場に効果登場し MR②で空くケースで AI が誤 skip しうる (稀)。
- 要確認: 上記 residual を card wave 時に踏むカードがあるか。

### #5 PA-MR の auto-phase 活性 (rules/05①)
- auto-phase で PA-MR を活性化 (sleep→active, stun→sleep)。
- 根拠薄: rules/05① は「自分のパートナー + 現場キャラ」のみ明示列挙。PA-MR はどちらでもない。
  保守側 (有効化) を採用し sleep-cost でない宣言能力を翌ターン使用可にした。
- 要確認: PA-MR が auto-phase で活性化されるか (公式裁定)。過剰なら「活性化しない」へ。

## 既知の構造的非対称 (実害は cohort 範囲外)

- `read.scene.byUid` は PA-MR sentinel を解決するが `mutate/char.findChar` / `mutate/scene.findChar` は
  scene-only。→ PA-MR を **mutate target** (charModifyAP 等) にすると no-op。PA-MR は推理/アクション/
  被 mutate 対象外 (rules/18:35-39) のため cohort では実害なし。card wave で PA-MR 被 mutate 効果が
  出たら mutate 層拡張を検討。
