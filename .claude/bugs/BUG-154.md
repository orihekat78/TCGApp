## 暫定保守解 一覧 (上記 照会で更新)

### #1 MR① 中間状態の順序 — ✅ 公式裁定で確定
- 実装: 【現場リムーブ時】hook を先に解決 (char は一旦 remove に在席) → その後 PA へ移す。refresh 二重計上防止に pop/skip。
- **公式裁定 (post/2099836)**: 「リムーブによって発動する能力は MR のリムーブによっても発動。MR能力で PA へ移動するが、
  **リムーブエリアへ一度置かれてから PA へ移動**」+「【現場リムーブ時】を持つキャラがデッキ下に移された場合は発動しない」。
  → removeToRemove のみ leave:to-remove emit (リムーブ経由) / toDeck/toHand/toDeckBottom は非発火 = **実装通り**。
- 残 sub-edge: hook 解決中に refresh が走った場合の MR 所在は明示裁定なし (極稀、provisional)。

### #2 MR②による既存 MR 除去の分類 — 直接裁定なし・原則整合
- 現場 MR の MR②除去 = cause='effect' + noMrRedirect (相手ターン中でも PA へ redirect せず remove へ。「能力によるリムーブ」)。
- PA 常駐 MR の MR②除去 = slot→remove、**現場離脱でないため【現場リムーブ時】hook 発火せず**。
- post/2099836「【現場リムーブ時】= 現場→リムーブエリアのみ」原則と整合 (PA からの除去は現場リムーブでない)。

### #3 PA-MR の相手 targetability / MR 枚数列挙 — ✅ 公式裁定で確定
- 実装: candidates.ts 未変更。PA-MR は効果/アクションの対象候補に **出さない**。
- **公式裁定 (post/1690545、事務局 2025-05-23)**: 「スタン/手札/デッキ下等は『現場にいるキャラを選ぶ/にのみ適用』が
  前提ゆえ、**パートナーエリアにある MR の状態を変更したり (MR能力以外で) PA から移動させる方法は存在しない**」。
  → PA-MR 不可侵 = 実装通り。card-Q&A で PA-MR は「キャラ/特徴の枚数」に数えない (現場不在) = candidates 非列挙と整合 (Phase 4 で per-card 確認)。

### #4 MR② × switch の順序 — 公式裁定なし、provisional 据え置き
- switchEnter は MR②除去で **現場に空きが生まれたら victim 除去を skip** (over-removal 防止)。非 MR / PA-slot のみ除去 = 従来どおり victim 無条件除去 (回帰0)。
- residual gap: atom-handlers/scene.ts の AI full-skip 経路は MR②前に fullness 判定 → 稀に誤 skip。実カード遭遇時に再照会。

### #5 PA-MR の auto-phase 活性 — 🔧 公式Q&A 照会で「活性化しない」へ修正
- 当初実装: auto-phase で PA-MR を活性化 (sleep→active, stun→sleep)。← **誤り (推測補完)**。
- 公式裁定なし。但し rules/05① の活性化対象は「パートナー + 現場キャラ」のみ + 事務局 (post/1690545) で
  「PA-MR の状態は (MR能力以外で) 変更できない」(sticky) → **literal rule では PA-MR は auto活性しない**。
- **修正 (本 follow-up、2026-06-24)**: auto-phase の PA-MR 活性化ブロックを削除。PA-MR は MR① 移動時の snapshot 状態を保持。
  test も「状態 unchanged」へ更新。CLAUDE.md「推測でルール補完しない」準拠。

## 既知の構造的非対称 (実害は cohort 範囲外)

- `read.scene.byUid` は PA-MR sentinel を解決するが `mutate/char.findChar` / `mutate/scene.findChar` は scene-only。
  → PA-MR を **mutate target** (charModifyAP 等) にすると no-op。PA-MR は推理/アクション/被 mutate 対象外
  (rules/18:35-39、post/1690545 で裏付け) のため cohort では実害なし。card wave で PA-MR 被 mutate 効果が出たら mutate 層拡張を検討。
