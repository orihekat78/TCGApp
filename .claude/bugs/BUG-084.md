## 発見契機

2026-05-30 の宣言能力UX変更 (常時picker / 事件カード黄色強調 / 名前・説明文表示) の
回帰レビュー workflow で、レビュー subagent が UI と AI の列挙非対称を指摘。

## 仕様 (rules/21-declared-ability-cost.md)

「自分の **事件** にいるキャラ」の【宣言】能力は使用可能。事件カード自身の宣言能力
(例: D08026「青の古城探索事件」a2) も対象。UI / AI 双方が列挙すべき。

## 期待動作

`enumerateMoves(state, p)` が、自分の事件カードに使用可能な declared ability があれば
`{ kind: 'declaredAbility', uid: 'case:self'|'case:opp', abilityId }` を列挙する。

## 実動作 (修正前)

- [src/ai/move-enumerator.ts](../../src/ai/move-enumerator.ts) の declaredAbility 列挙は
  `state.players[byPlayer].scene` のみを走査し、**事件カードを対象外**にしていた。
- UI 側 [enumDeclaredAbilitySources](../../src/ui/hooks/useActionsPanelFlow.ts) は
  case を含む (user_request 20260522_01 #5) ため、UI/AI で挙動が非対称。
- engine (`flow.canDeclaredAbility`/`useDeclaredAbility`) は case:self/opp を完全対応
  済みなので、AI 列挙のみが追従漏れ。
- 現状は人間専用フローのため実害なし。**AI vs AI / spectator で事件の宣言能力が
  選ばれない**潜在バグ。

## 修正内容

1. [src/ai/move-enumerator.ts](../../src/ai/move-enumerator.ts) — scene 列挙の直後に
   事件カード (`case:${byPlayer}`) の declared ability 列挙 (6b) を追加。
   canDeclaredAbility と cost.canPay フィルタは scene と同一ロジックを適用。
2. [src/ai/ability-ctx.ts](../../src/ai/ability-ctx.ts) — `makeDeclaredAbilCtx` に
   `case:self`/`case:opp` 分岐 (area:'case') を追加。これにより列挙時の cost.canPay と
   dispatcher (`policy.applyMove`) の cost.pay の両方が事件 cost を正しく扱う。

## RCA

UI 側で case 宣言能力対応を追加 (user_request 20260522_01 #5) した際、AI 側の
列挙ロジックへ水平展開しなかった。UI と AI で「宣言能力 source 列挙」が別実装
(enumDeclaredAbilitySources vs move-enumerator) のため非対称が生じやすい。

## 水平展開

- partnerAbility 列挙: UI/AI とも対応済 (非対称なし) を確認。
- 他の「UI と AI で別々に列挙するロジック」(reasoning/action source) は engine の
  canX セレクタを双方が呼ぶため対称。declared ability の source 集合のみ二重定義だった。

## 防止策

- 将来 enumDeclaredAbilitySources と move-enumerator の declared 列挙を engine 側の
  共通 public API (例 `getDeclaredAbilitySources(state, p)`) に一元化すると非対称を構造的に防げる
  (今回は骨格凍結のため見送り、両側に case 列挙を追加して整合)。
- テスト: tests/ai/move-enumerator.test.ts に case:self 列挙 + cost フィルタの境界テストを追加。
