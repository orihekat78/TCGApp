# BUG-354: failed or deferred stacking ran the wrong chain tail

## Status

Fixed in QA Wave88.

## Defect

- `charStackCard` fromSelf/fromScene ignored a failed `toStack`, so stale
  decisions could draw or grant Assault without stacking.
- A first correction treated every `toStack(false)` as failure, but `false`
  also represents a legal set-card replacement pause.
- The main effect resolver did not attach a continuation to that replacement,
  so chain tails could run before the physical move resumed.

## Fix

- Gate the chain only when stacking truly fails.
- Detect a newly opened set-card replacement and leave the chain ungated.
- Attach replacement continuations in sequence, chain, and parallel resolver
  paths; append nested outer tails instead of overwriting inner tails.
- Preserve the same continuation chain through pending-runtime JSON hydration;
  resume the stack move before every tail.
- Emit success logs only after a real stack move.
