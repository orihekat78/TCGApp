## 概要

B09100 犯人 (ID:1039) の印字「犯人［ID：1039］はデッキに何枚でも入れることができる。」に対し、
`validateDeck` (src/engine/flow/setup.ts:43-67) が `MAX_SAME_ID=3` を全カード一律に throw で強制し、
例外分岐が無い。`CardDef` 型 (types/card-def.ts) に maxCopies/deckLimit 等の copy-limit フィールドも不在 =
データモデル上表現不可能。runtime ability (2 行目) は実装済。

## 影響

犯人 4 枚以上の合法デッキ (カードが明示許可) が setup.init で reject される。**latent**: MVP デッキ
(CT-D08/CT-D11) は犯人を含まず deckBuilder も生成しない — 現状の実プレイでは踏まない。全カード対応
フェーズ (deck-builder で任意構築) で顕在化する。

## 修正方針 (Track A 送り — 骨格凍結により Track B では触らない)

additive 案: `CardDef.deckLimit?: number | 'unlimited'` を追加し validateDeck が
`def.deckLimit ?? MAX_SAME_ID` を参照 (省略時 3 で挙動不変)。B09100.ts に `deckLimit:'unlimited'` を付与。
deck-builder UI 側の枚数 cap も同 field を読むこと (validate と UI の 2 honor site)。
[.claude/specs/DEFERRED-INDEX.md](../specs/DEFERRED-INDEX.md) に登録済 → Track A engine wave で実装。

## 防止策

- → enforcement: compiler mine gap-suspect 検出が「印字行 > ability」を機械 surface (本件の検出経路)。
- デッキ構築系の印字句 (「デッキに〜枚」) は runtime ability でなく setup/validate 側の honor 確認を要する
  — card-addition-checklist の対象外領域だったことが RCA。
