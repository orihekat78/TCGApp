## Expected

Only TSV/official-text clauses that explicitly say an event may be used are checked before normal hand use, Next Hint, or effect-driven use. Icon/effect conditions remain post-use no-op conditions. An invalid stale selection changes no hand/remove/flag/hook/log state.

## Actual

The first implementation inferred authorization from an event's `AbilityDef.condition`. This incorrectly blocked icon conditions and still lacked a declarative card-level source of truth.

## RCA

`AbilityDef.condition` has two different meanings: a printed use authorization and an ability/effect condition. The type model did not separate them.

## Fix

`CardDef.useCondition?: Condition` is the sole authorization source. The shared `eventUseAllowed` reader is used by hand use, post-pop Next Hint/UI projection, and `useEventFromHand` candidate/recheck. Explicit clauses moved from B02032, B03134, B04027/P, B04064, B05081, and B07056/P; icon conditions remain on abilities. CPU Next Hint currently does not supply `optionalCardId`, so this fix makes no AI optional-use parity claim.

## Horizontal investigation

The exact official-text search for `このイベントは…使用できる` found the six base definitions above. Parallel cards inherit via spread. Other event conditions were not migrated merely because they are conditions.

## Prevention

New event-use authorization must be authored as `CardDef.useCondition`, grounded to printed text, and tested against a decoy event whose ability condition must not block use.
