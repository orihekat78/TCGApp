## 仕様 (rules/15, 21)
CPU の宣言/誘発能力でも、リムーブからの登場 (sceneEnter) は人間同様に解決されるべき。

## 実動作 (バグ)
`substituteAtomPick` の AI 経路 (resolve-picks.ts Pattern B) は `target:[pickValue]` のみ substitute し、
`cardId:'$pick.cardId'` を解決しない。runtime の sceneEnter handler は cardId 未解決 + target=array で
awaiting-pick 分岐 → `tryRePickFromAtom` (target が pick-query でない) → push せず → **silent no-op**。
- **D11014 a2**: CPU がリムーブの警察 Lv5 を登場できず、萩原千速 登場時の 1 ドローも不発。

## 修正
1. resolve-picks.ts の AI Pattern B 経路に `cardId:'$pick.cardId'` branch を追加 (BUG-103 の `cardIds`
   branch と同型)。picked.cardId を cardId へ substitute し、target(pick query) は保持 (handler が
   `target.query.area` を見て source area=remove から splice する)。→ 同期実行で `$entered` bind も自然伝播。
2. **副作用対応 (scene-full)**: 上記で CPU の reanimate が実際に動くようになり、現場満杯 (5枚) 時に
   `mutate.scene.enter` が throw する pre-existing gap が露呈 (smoke 7〜12/100 失敗)。効果駆動 sceneEnter
   handler に「現場満杯なら登場 skip」guard を追加 (rules/15「可能な限り行う」、source-splice 前に判定して
   カード消失を防止)。~~スイッチ対応 (switch-on-effect-enter) は別途 DEFERRED。~~
   → **2026-06-04 実装済**: human は満杯時に SceneSwitchPickerModal で退場キャラを選び switchEnter で登場
   (rules/20)。AI は skip 維持 (0枚選択=合法な辞退)。changelog `2026-06-04-01-switch-on-effect-enter.md`。

## 効果範囲 / 水平展開
- `cardId:'$pick.cardId'` を使う card-DSL は D11014 a2 のみ (D11019 は `$matched.cardId` で別経路)。
- PA 短縮形 atom (charModifyAP/LP・短縮形 sceneEnter D08024 等) は別 gap → **BUG-109** (DEFERRED)。
