## 仕様
中断した sequence/chain の各 pick は、自身に対応する continuation (残り step) と 1:1 で対応すべき。

## 実動作 (latent バグ)
pick は `__pendingEffectPickQueue`、continuation は `__pendingChainContinuation` の **別 side-channel** に
push され、`applyPickAndContinuation` は continuation を「FIFO 先頭 [0]」で peek して current pick の対と
仮定する。しかし resolver.ts は `remainder.length > 0` のときだけ continuation を push するため、
**continuation 無しの pick** (sequence 最終 step や、解決中の triggered ability が積む standalone pick) が、
continuation 付き pick と interleave すると先頭の continuation を誤って消費しうる (off-by-one desync)。

### 再現に必要な条件 (現 MVP では成立しない)
- 解決した atom の runAllUntilEmpty 中に triggered ability が standalone pick を push し、
- 同 sequence の後続 step が自身の continuation を持つ (3+ step の pick 連鎖)。
- MVP カードにこの構造は無い (D08024=2step、D11014 a2 step3 は非pick) ため再現不能。grep 確認済。

## 暫定対応 (本セッション)
- null-pick skip path の continuation shift を防御化 (空配列を触らない、review #1)。

## 修正 (2026-06-07, TDD)
**continuation を pick 本体に同梱** (恒久対応案 1 を採用) — 別 side-channel FIFO `__pendingChainContinuation` を廃止し、
`PendingEffectPickSide.continuation?: {remainder, ctx}` に 1:1 で持たせる。これで「continuation を持たない pick」が
他 pick の continuation を誤消費する index ずれが構造的に発生不能になる (standalone pick も自然に continuation=undefined)。

### 変更点 (5 箇所、human/AI 両経路)
- `resolve-picks.ts`: `PendingEffectPickSide` に `continuation?` 追加。
- `resolver.ts` (sequence/chain): 中断時 `__pendingChainContinuation.push` → 「この step で enqueue した最初の pick」
  (`queue[qBefore]`) の `.continuation` に同梱。
- `apply-pick.ts applyPickAndContinuation`: FIFO peek/shift → `pending.continuation` を参照。
- `apply-pick.ts drainAiEffectPicks`: skip 時の FIFO shift 削除 (pending 破棄で continuation も drop)。
- `useEngineDispatch.ts effectPickResolve`: user skip 時の FIFO shift 削除 (同上)。
- 旧 FIFO `__pendingChainContinuation` / `ChainContEntry` 完全除去 (live 参照 0、comment のみ)。

## 関連未解決 (2026-06-16 batch#4 gate5 発見) — human-decline 経路の chain-gate / 必須末尾

上記 FIFO-pairing は修正済だが、**別 manifestation** が残存 (本体 status は 修正済 のまま、本節を追跡ポインタとする)。
`0-pick (max:1=min:0, 「〜まで」/「〜してもよい」) を candidate在で human-decline したとき`、後続 step の扱いが誤る:

- **chain-gate が効かない** (B05028): `chain[charRemoveSetCard(0-pick), sceneRemove]`「そうした場合」。step1 を 0枚 decline
  しても step2 が発火する。`applyPickSkipAndContinuation` が chain 残りを無条件実行し、decline した charRemoveSetCard が
  `__chainStepNoApply` を立てない (`__chainStepNoApply` は substituteAtomPick の **no-candidate** 経路のみ set)。
- **必須末尾が drop** (B09056=必須 choice / B09038=無条件 draw): 0-pick decline で末尾の **mandatory** step (「〜する」) が
  continuation ごと drop。本来は常時発火が正。
- 共通根: 「candidate在 + human-decline」の skip path が、後続が **chain-gated か mandatory か** を区別せず一律に
  「continuation を無条件実行 (B05028) or 一律 drop (B09056/B09038)」する。AI は greedy で decline せず仮面化するため
  smoke / certify / 敵対verify をすり抜け、**gate5 実機 decoy (human-decline 路) のみが検出**。
- 影響カード (全て DEFER 済、DEFERRED-INDEX batch#4 節): B05028 / B09056 / B09038。解禁にはこの skip-path 修正が前提。
- 修正方針案: decline 時に「declined-pick が chain step なら __chainStepNoApply 相当を set (chain break)」かつ
  「mandatory 末尾 (sequence の非 chain 後続) は decline でも保持」を分離。要 TDD (human/AI 両経路 + decoy)。
