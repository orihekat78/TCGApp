## 仕様
中断した sequence/chain の各 pick は、自身に対応する continuation (残り step) と 1:1 で対応すべき。

## 実動作 (latent バグ)
pick は `__pendingEffectPickQueue`、continuation は `__pendingChainContinuation` の **別 side-channel** に
push され、`applyPickAndContinuation` は continuation を「FIFO 先頭 [0]」で peek して current pick の対と
仮定する。しかし resolver.ts は `remainder.length > 0` のときだけ continuation を push するため、
**continuation 無しの pick** (sequence 最終 step や、解決中の triggered ability が積む standalone pick) が、
continuation 付き pick と interleave すると先頭の continuation を誤って消費しうる (off-by-one desync)。

### 再現に必要な条件 (現 MVP では成立しない)
- 解決した atom の runAllUntilEmpty 中に triggered ability が standalone pick を push し、
- 同 sequence の後続 step が自身の continuation を持つ (3+ step の pick 連鎖)。
- MVP カードにこの構造は無い (D08024=2step、D11014 a2 step3 は非pick) ため再現不能。grep 確認済。

## 暫定対応 (本セッション)
- null-pick skip path の continuation shift を防御化 (空配列を触らない、review #1)。

## 修正 (2026-06-07, TDD)
**continuation を pick 本体に同梱** (恒久対応案 1 を採用) — 別 side-channel FIFO `__pendingChainContinuation` を廃止し、
`PendingEffectPickSide.continuation?: {remainder, ctx}` に 1:1 で持たせる。これで「continuation を持たない pick」が
他 pick の continuation を誤消費する index ずれが構造的に発生不能になる (standalone pick も自然に continuation=undefined)。

### 変更点 (5 箇所、human/AI 両経路)
- `resolve-picks.ts`: `PendingEffectPickSide` に `continuation?` 追加。
- `resolver.ts` (sequence/chain): 中断時 `__pendingChainContinuation.push` → 「この step で enqueue した最初の pick」
  (`queue[qBefore]`) の `.continuation` に同梱。
- `apply-pick.ts applyPickAndContinuation`: FIFO peek/shift → `pending.continuation` を参照。
- `apply-pick.ts drainAiEffectPicks`: skip 時の FIFO shift 削除 (pending 破棄で continuation も drop)。
- `useEngineDispatch.ts effectPickResolve`: user skip 時の FIFO shift 削除 (同上)。
- 旧 FIFO `__pendingChainContinuation` / `ChainContEntry` 完全除去 (live 参照 0、comment のみ)。

## 検証 (TDD RED→GREEN)

## #2 manifestation: human-decline 経路の sequence mandatory-tail drop (2026-06-16 修正済)

batch#4 gate5 で発見された「関連未解決」を、再現テストで RCA を確定し修正した
(commit: 後述 / spec: [.claude/specs/bug-111-human-decline-fix-design.md](../specs/bug-111-human-decline-fix-design.md))。

### 確定した根本原因 (再現で実証、`tests/engine/effect/bug-111-human-decline-repro.test.ts`)
`0-pick (max:1=min:0, 「〜まで」/「〜してもよい」) を candidate在で human-decline したとき`、pending 破棄とともに
continuation (= 中断 sequence の残り step) が **一律 drop** され、**sequence の mandatory 末尾 step が消える**
(skipResolvesAtom=false = deckRevealUntil 以外の全 0-pick)。根本原因は continuation が **sequence / chain の
origin を区別しない**こと。AI は greedy で decline しないため smoke / certify / 敵対verify をすり抜け、gate5 実機のみが検出。

### ⚠ batch#4 記録の訂正 (B05028 over-fire は誤診断)
旧「関連未解決」節は「chain-gate が効かず B05028 step2 が過剰発火」と記録したが、**再現せず誤診断**だった
(opus 敵対レビュー Lens 2 が 5 シナリオ独立再構築で確認)。chain[charRemoveSetCard(0-pick), sceneRemove] を
human-decline すると、pending 破棄 → continuation(sceneRemove) drop → step2 不発火 = 「そうした場合」gate として
**正しく動作**する (charRemoveSetCard の pending は skipResolvesAtom:false で applyPickSkipAndContinuation を通らない)。
→ **B05028 は engine 修正なしで出荷可能** (誤って DEFER されていた)。

### 修正 (2026-06-16, TDD)
continuation に origin `kind: 'sequence' | 'chain'` を付与し:
- decline 時: **sequence-origin は remainder を実行** (mandatory 末尾発火、rules/15 独立 step) / **chain-origin は drop** (rules/25 gate)。
- `applyPickSkipAndContinuation(state, pending, runDeclinedAtom=false)`: sequence-origin decline は declined head atom を
  再実行せず remainder のみ実行 (declined 0-pick=何もしない、単数 sceneEnter の __declined 未対応による再 push を回避)。
- remainder wrap も origin kind で行う (sequence に chain-gate を誤適用しない)。
- 触る engine: `resolve-picks.ts` (continuation 型) / `resolver.ts` (kind 付与) / `apply-pick.ts` / `useEngineDispatch.ts`。

### 検証
- repro 5/5 GREEN (chain decline=不発火 2 経路 / sequence[0-pick,draw] decline=draw 発火 RED→GREEN / choice-tail 安全 / AI control)。
- full vitest 2540 pass / tsc clean / smoke baseline byte 同一 (AI 経路不変) / lint:* 8本 pass。
- 解禁: **B09038** (sequence mandatory draw) を修正で解禁。**B05028** は修正不要で出荷可能。

### 残: B09056 は DEFER 継続 (別 gap)
B09056 の mandatory 末尾は 2択 `choice[A,B]`。continuation の choice は initial walk で eager surface するが、
この eager-surface は optional wrapper 未達でも surface しうる fragile な挙動 (BUG-145 系) で、B09056 の
`optional[seq[..,sceneRemove(0-pick),choice]]` 構造での正しさが未検証。choice-in-continuation surface の整備は別 engine 課題。

## #3 manifestation: continuation-nest (2026-06-22 修正済, commit 後述)
