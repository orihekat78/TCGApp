# B08006の重なったカードの同一性喪失

## 期待動作

B08006のコストで公開した手札は、実カードの同一性を
保持したまま現場キャラの下に重なる。ホスト離場時はその
実カードがリムーブエリアへ移動する。

## 実動作（修正前）

`handStackUnder`は手札を公開・除去後、`stackCard`へ枚数だけを
渡していた。そのため重なり先の`cardId`が`back-card`になる。

## RED

- `tests/cards/engine-mega-w4.test.ts`のB08006実カード経路
- 期待 `SB_HAND`、実際 `back-card`
- 既存47テストは枚数だけを検証し、同一性喪失を検出できなかった

## RCA

`handStackUnder`が公開・除去した`cardId`を`stackCard`へ渡す。
既存実装は`stackCard(state, hostUid, 1)`と枚数しか渡さず、
実カードIDを保持できる既存APIを使っていなかった。

## 修正

`handStackUnder`が公開・除去した`cardId`を
`stackCard(state, hostUid, 1, [cardId])`へ渡す。
ルール上の参照は引き続き枚数だけ。保存状態と離場処理だけが
実カードの物理同一性を保持する。

## 回帰証拠

- `tests/cards/engine-mega-w4.test.ts`: RED→GREEN、公開手札IDとホスト離場順
- `tests/cards/official-qa/stacked-card-semantics-public-wave33.test.ts`:
  公開dispatcher、JSON往復、ホスト離場、重なった能力非発火

## 水平展開

- `charStackCard`の選択カード経路は既に`cardIds`を渡す
- `sceneStackUnderSelf`と`fromSelf`/`fromScene`は`toStack`で実体を移す
- 旧`{ uid, n }`経路だけは物理カードを伴わない互換countで、
  `back-card`を維持
- `canPayAtomically`の非authoritative cloneは現在`back-card`を使う。
  現行唯一の利用カードでは最終costのため安全。将来のidentity依存複合cost前にhardeningする
- `handStackUnder`と`sceneStackUnderSelf`の複数候補UI選択、
  公開可能な重なりカードのUI/replay表示は別課題
