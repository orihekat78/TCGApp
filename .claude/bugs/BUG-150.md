## 概要

対戦盤面 (`src/ui/`) は 1920×1080 固定の `.stage` を `.scaler` の
`transform: scale(min(vw/1920, vh/1080, 1))` で縮小表示する contain(レターボックス)方式。
`html/body/#root` に背景色が無いためブラウザ既定の**白**が盤面外に透け、`transform-origin: top left`
により余白が**右に偏った白帯**になる。横長ウィンドウで盤面がウィンドウを充填しない。

## 期待動作 / 実動作

- 期待: 横長ウィンドウいっぱいに盤面が広がり、白帯・余白が出ない。全ゾーン表示。
- 実動作: 盤面が左寄せで縮小表示され、右側に白帯。大画面でも scale 1.0 上限で盤面が小さいまま。

## 関連ファイル

- `src/ui/hooks/useStageScale.ts` (scale 算出、1.0 上限)
- `src/ui/components/Playmat.tsx` / `Playmat.css` (`.scaler` transform / `.stage` 固定px / 絶対配置)
- `src/ui/styles/tokens.css` (背景色未設定・カードサイズ変数)
- `index.html` (body 背景未設定)
- 各ゾーン CSS (SceneArea/HandZone/ActionsPanel/TopBar/Case/Partner/Deck/File/Evidence/Remove)

## RCA

固定キャンバス + transform:scale は「アスペクト比固定で contain」する設計のため、
ウィンドウ比が 16:9 と異なると必ず letterbox する。加えて背景未設定で帯が白くなった。
副次問題: `position:fixed` モーダルが transform 親内にあり viewport 基準にならない既知不具合。

## 修正 (zoom フィル方式、touched 4 ファイル)

詳細設計: [.claude/specs/board-responsive/01-design.md](../specs/board-responsive/01-design.md)

1. `html/body/#root` をダーク化 + 全面化 (`var(--bg-deep)`、`#root` overflow:hidden) — [tokens.css]。
2. `.stage` の固定px+`transform:scale` を撤去し `width/height:100%`。→ モーダル fixed も同時解消。
3. 盤面コンテンツを `.board-content` でラップし `style={{ zoom: useStageScale() }}` を適用。
   CSS `width/height:100%` 固定で viewport 全面充填。既存 absolute/fr・固定 px・ゾーン CSS は不変
   (zoom が比率維持で一括スケール)。modal/overlay は `.board-content` の外 (.stage 直下・非 zoom)。
4. `useStageScale` を `clamp(0.2, min(vw/1920, vh/1080), 1.6)` に改修 (MAX=soft-cap、戻り値=zoom)。

## 防止策 / 教訓

- 固定キャンバス scale(contain) は「全比率充填」と両立しない。zoom フィル or 実レイアウトで行う。
- `transform: scale` 親の内側の `position:fixed` は viewport 基準にならない (本件で副次解消)。
- **⚠ zoom + `%` 寸法の落とし穴**: `zoom: s` の子要素では `%` 基準が **W/s に拡大**される。
  充填には `width:100%` を使う (`100/s%` は `W/s²` になり s 二重割りで右下 overflow → ActionsPanel/
  ターン終了が見切れる)。`s=1` だけ偶然一致し見落とすため、実装時は **`s≠1` の縦短/横長で
  端要素 (ActionsPanel) の getBoundingClientRect が viewport 内かを必ず実測**する。
- 検証教訓: 「白帯消滅」だけ見て端要素の見切れを見落とした。**充填=端要素が画面内**の両方を確認。
