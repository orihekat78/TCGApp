## 仕様 (rules/07、D11016 公式テキスト)

D11016 大江忍 a1「【相手ターン中】【ターン1】ガードしたとき、ガードしたキャラをアクティブにしAP＋2000」。
「ガードしたとき」= **このキャラ(D11016)がガードしたとき**。

## 期待動作

D11016 自身がガードしたときのみ a1 が発火 (D11016 を再アクティブ化 + AP+2000)。

## 実動作 (バグ)

- D11016 a1 trigger は `matcher:(p)=>typeof p.guardUid==='string'` (ガードが起きたか、だけ判定)。
- `TriggerDef.matcher` の signature は `(payload, state)` で **card.uid を参照できない** → guardUid===自分 を判定不能。
- `selfOnly:false` なので selfOnlyMatches でも絞られない (しかも action:guarded の source.uid は**攻撃者**)。
- condition は `{turn, opp}` のみ。
- 結果: 相手ターン中に**いずれかのキャラがガードするたび** D11016 が自分を再アクティブ化 + AP+2000。
  BUG-096 (limit 未 enforcement) と複合し、ガードのたびに無制限スタック。

## RCA

matcher closure は `(payload, state)` のみ受け取り ability 所有者の uid を知らない。
「自分がガードしたか」を判定するには ability 所有者 (ctx.source.uid) と payload.guardUid の照合が必要だが、
closure matcher では不可能。matcherCondition 経路 ([triggered.ts:156-168](../../src/engine/listeners/triggered.ts)) は
ctxMc に source.uid を詰めるため、そこで判定すべきだった。

## 修正

- [cond/eval.ts](../../src/engine/cond/eval.ts) に Condition kind `guardedBySelf` 追加:
  `ctx.triggerPayload.guardUid === ctx.source.uid`。
- [D11016.ts](../../src/cards/ct-d11/D11016.ts) a1 trigger を closure matcher から
  `matcherCondition:{kind:'guardedBySelf'}` へ (selfOnly/closure/GameState import 除去)。

## 水平展開

- guardedBySelf を使うのは D11016 a1 のみ。action:guarded を listen する他カードは無し。
- ⚠ 同種 (matcherCondition が ctx.source.uid を見ない) の疑い: **D11007 a3 の `contactOpponentApHigher`**
  ([cond/eval.ts:167-175](../../src/engine/cond/eval.ts)) は contact の aUid/bUid のみ見て自分を照合しない
  → 別 issue として要対応 (本コミット対象外、別途報告)。

## 防止策

behavioral test ([triggered-limit-guard.test.ts](../../tests/engine/listeners/triggered-limit-guard.test.ts)):
別キャラがガード→D11016 a1 不発火 / 自分がガード→発火。
