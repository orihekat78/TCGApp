## 期待値

同一Git indexのworktree/cloneは、ignored/untracked artifactとcheckout EOLに関係なく
同じgenerated Source hashと`structure.md`を生成する。

## 実際値

commit `9e4cb1c0`のclean cloneで`structure.md`が1/110 driftした。dirty mainは
ignored reports/raw/TSVも列挙しdirs 268/files 5170、cleanはdirs 243/files 4987だった。
dictionary JSONのCRLF差でSource hashも984bd9から94cb73へ変化した。

## RCA

`computeSourceHash`のEOL正規化が`.ts/.md`限定で、明示JSON sourceは生EOLでhashしていた。
`gen-structure.ts`はfilesystem全体をwalkし、Git index外のignored/untracked artifactも
ディレクトリ数、ファイル数、ツリー本文へ取り込んでいた。
初回のpath集合のみindex化では、heading/JSDocと辞書をworktreeから読むため、
未stageのtracked本文変更・削除でも同一indexの出力が揺れた。`localeCompare`も
ホストlocaleをソート入力に混入させた。さらに非stage-0の競合entryを無視すると
競合中のpathが欠けた部分treeを生成でき、generator/辞書のpartial-stageでは
実行コードとindex blobが異なるまま生成できた。

## 水平調査

Source hashは全generated docsの共通header経路。明示text sourceはJSONなど拡張子が増える。
structure固有のfilesystem walkは`.claude/reports`、raw/TSV、local tool artifactを横断した。
index pathだけでなく辞書、Markdown heading、JS/TS JSDoc、header source hashも
同じindex snapshotから読まないと「同一indexなら同一structure」を満たさない。

## 再発防止

全UTF-8 source内容のCRLF/CRをLFへ正規化する。`git ls-files --stage -z`のstage-0
path/blobをordinal順で純粋にtree化する。説明対象blobは`git cat-file --batch`の
1 processで一括取得し、辞書・heading・JSDoc・header hashの正本にする。
別root、ignored/untracked追加、未stage本文変更/削除不変、stage後変化、NUL path、
explicit exclude、Git failure、codepoint順をfocused testで固定する。競合stageは
path/stage一覧付きで停止する。生成入口でgenerator/辞書のindex内容とworktree内容を
EOL正規化後に比較し、不一致なら`stage inputs before docs`で停止する。
新規untrackedファイルを構造に反映する場合は、先にstageしてからdocsを生成する。
