## 概要

証拠獲得経路の `mutate.evidence.addFromDeck` はデッキ 0 枚で **silent break** する
(`src/engine/mutate/evidence.ts`、「リフレッシュは呼出元が別途行う前提」)。しかし以下 2 つの呼出元が
refresh を配線していなかった:
1. `evidenceGain` atom verb (`atom-handlers.ts`) — D04007「証拠を1つ得る」等のカード効果
2. `gainSelfEvidence` (`flow/action-case.ts`) — アクション[事件] の自証拠+1 (rules/10 手順3)

公式: rules/14「証拠を得る = リフレッシュ後に残りを解決」/ rules/26 (デッキ不足時のリフレッシュ interleave)。
BUG-137 (mill) と同型の refresh-guard 欠落。

## 影響範囲

- evidenceGain 使用出荷カード 13 枚 (smoke 内 D08013/D08021/D11003)。
- gainSelfEvidence はすべてのアクション[事件] 経路 (smoke で頻出)。
- X9/X15 適用後も smoke baseline は byte 一致 (現 smoke はデッキ枯渇直前の証拠獲得が稀 = 回帰証跡)。
- 実戦では「証拠を得るはずがデッキ 0 で何も起きず、敗北判定も refresh も発生しない」状態が起き得た。

## 期待動作 / 実動作

- 期待: 証拠獲得前にデッキ 0 → refresh (リムーブ 0 枚なら deck-out 敗北)、その後残りを獲得
- 実動作 (修正前): デッキ 0 のまま証拠を得られず続行

## 修正

- X15: `evidenceGain` atom に fileAdd 同型の「1枚ごと事前 deck0→refresh→add」ループを追加。
- X9: `gainSelfEvidence` にも同型 guard を追加 (+ 実獲得時のみ evidence:gain emit = false-fire 防止)。
- pin: tests/engine/effect/wave2-cluster3-action-triggers.test.ts §X15 / §X9 (deck<n refresh / remove0 敗北 / 実獲得時のみ emit)。

## 水平展開 / 繰越

- **reasoning.ts (推理による証拠獲得) の同型 gap は本 commit では未修正 (繰越)**: `flow/main/reasoning.ts` の
  reasoning:before-add → addFromDeck も同じく refresh 未配線。推理経路は本クラスタ対象外のため DEFER
  (DEFERRED-INDEX に記録)。修正は別 commit で reasoning ループに同型 guard を追加する。
- draw/mill/fileAdd/boundToRemove は配線済 (各 BUG で対応)。

## 防止策

- `addFromDeck` の docstring「リフレッシュは呼出元が別途行う前提」を呼出元で必ず満たす (静的 grep 監査候補)。
