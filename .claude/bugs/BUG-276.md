# 5174二重待受による検証先の分裂

## 発見契機

in-app browserではfavicon修正が見えず、shellとPlaywrightでは見えたため待受を調査。

## 期待動作

YOU vs CPUループとmeta E2Eは、現在checkoutから起動した一意なサーバーへ接続する。

## 実動作（修正前）

同じ5174で現在checkoutがIPv6、`C:\tmp\conan-official-qa-*` がIPv4待受。
`localhost` の名前解決先により、ブラウザが別checkoutを表示した。
meta Playwrightも既存5174を再利用するため、別checkoutをテストし得た。

## RCA

- meta dev serverのhostが `localhost` でアドレス族を固定していなかった。
- ループURLも `localhost` で、接続先のアドレス族が未固定だった。
- meta Playwrightは5174固定かつ `reuseExistingServer=true` だった。

## 修正

- meta dev serverとループURLを `127.0.0.1` に固定。
- meta Playwrightを既定5194、port上書き可能、既存server再利用なしへ変更。
- E2E起動commandもhost / port / strictPortを明示し、手動5174から分離。

## 水平展開

root Playwrightは既に `PLAYWRIGHT_PORT` 対応。meta側だけ固定5174再利用だった。
ループのfresh-browser復旧は維持し、復旧先URLのみ一意化した。

## 検証

- RED: ループURL2件不一致、meta隔離config 6件不在で計8件失敗。
- GREEN: focused Vitest 13件、隔離5194 meta E2E desktop / 851x393 2件通過。
- in-app browserを `127.0.0.1:5174/#setup` へ新規接続し、現在checkoutの
  favicon宣言1件、href一致、console error / warning 0を確認。
- full Vitest 883 files / 6,991 tests通過、typecheck、lint、meta build通過。
