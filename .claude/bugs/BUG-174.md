# BUG-174: 短縮形 pick side の二重相対化 (owner='opp' で反転)

## 期待動作
`sceneToEvidence` 等の PA 短縮形 `{player:'opp', max:1}` は、能力所有者から見た**相手**の現場を
候補にする (「相手の現場にいるキャラを選び」rules/15)。CPU (state container 'opp') が所有する
カードでも同じ。

## 実動作 (修正前)
`paShortFormAwait(..., side = resolvePlayer(a.player, ctx))` が side に**絶対** container key を渡すが、
`sidesForQuery` (candidates.ts) は query.side を **owner 相対**で再解釈する。二重変換は
owner='self' でのみ恒等 — owner='opp' (CPU側) では反転し、**自陣**が候補になる
(probe 実測: CPU の B06085 a1 が CPU 自身のキャラを自分の証拠に移す)。

## 関連ファイル
- src/engine/effect/atom-handlers/char.ts (4 site) / scene.ts (5 site) — side を相対値 `a.player` のまま渡すよう修正
- src/engine/target/candidates.ts sidesForQuery (owner 相対解釈、変更なし)
- tests/cards/step12-batch3-b06085.test.ts (BUG-174 pin: owner='opp' 宣言で self 側が対象)

## RCA
short-form 導入時 (refactor 2a) から side 引数の座標系が未定義のまま、呼出側は「player を解決して渡す」
convention をコピペ。全 probe test が ctx.source.player='self' 既定で owner='opp' 経路が未踏
(W3 混成 review が「cross-side 短縮形の side/chooser 不整合、現出荷カード未踏」と latent 記録済 —
今回 B06085 で顕在化)。smoke は MVP デッキ固定のため該当カード非収録で検出不能だった。

## 水平展開

  (full vitest / smoke baseline 不変で証跡)。
