## 修正 (Round 4i-fix)

### handleHook に condition gate 追加

[src/engine/listeners/triggered.ts](../../src/engine/listeners/triggered.ts) の `handleHook` に 6 stage 目の filter を追加:

```ts
// matcher check の直後
if (ability.condition) {
  const ctx = {
    source: { cardId: card.cardId, uid: card.uid, abilityId: ability.id, player: card.player, area: card.area },
    bindings: {},
  };
  if (!evalCond(state, ability.condition, ctx)) continue;
}
```

`import { evalCond } from '../cond/eval.js';` も併せて追加。

### 検証

- unit test 追加 2 件 ([tests/engine/listeners/triggered.test.ts](../../tests/engine/listeners/triggered.test.ts)):
  - `ability.condition が unmet なら queue されない (BUG-033 partnerColor false)`
  - `ability.condition が met なら通常 queue される (BUG-033 partnerColor true)`
- E2E spec 新 case 1 件 ([tests/e2e/patterns/event-remove-by-ap.spec.ts](../../tests/e2e/patterns/event-remove-by-ap.spec.ts)): `D08025: partner=黄 → listener が condition gate で reject`
- resolve.stack 側で condition 二重評価なしを Phase 1 探索で確認 (listener 段で単一 gate)
- smoke 525/475 baseline 完全維持

## 期待動作

`handleHook` は triggered ability に対し以下の **6 stage filter** を適用すべき:

1. `ability.type === 'triggered'`
2. `trigger.hook === hookName`
3. `scopeAllowsArea(ability.scope, card.area)`
4. `trigger.selfOnly && !selfOnlyMatches(...)` → reject
5. `trigger.matcher && !trigger.matcher(payload, state)` → reject
6. **`ability.condition && !evalCond(state, ability.condition, ctx)` → reject** ← 修正前は抜けていた

## 実動作 (修正前)

`handleHook` 内に `ability.condition` を見るコードが存在しなかった。`eventRemoveByAP({ additionalCondition:{ kind:'partnerColor', color:'青' } })` (D08025) は自分の partner が青でなくても queue される状態。

[src/engine/cond/eval.ts:22](../../src/engine/cond/eval.ts) の `evalCond` は既存だったが、`triggered.ts` から呼ばれていない。resolve 段でも `ability.condition` 未参照と確認済み。

## RCA

Round 4b (`4c64c79`) で `triggered.ts` 汎用 listener を実装した際、`ability.condition` チェックを実装漏れ。matcher で payload kind/cardId 絞り込みは行っていたが、condition 用の追加経路が必要と認識されなかった。

Round 4e-4h で `partnerColor` / `caseTrait` 等の condition を持つカード (D08009-22 / D11003-11 / D08025) が登場、condition resolver も整備されたが、listener 側 wiring は未更新のままだった → Round 4i E2E spec 化中に検出 → Round 4i-fix で修正。
