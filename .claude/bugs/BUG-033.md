## 期待動作

[src/engine/listeners/triggered.ts](../../src/engine/listeners/triggered.ts) の `handleHook` (line 100-130) は、triggered ability の以下 4 段階フィルタを通過したものを queue すべき:

1. `ability.type === 'triggered'`
2. `trigger.hook === hookName`
3. `scopeAllowsArea(ability.scope, card.area)`
4. `trigger.selfOnly && !selfOnlyMatches(...)` → reject (selfOnly 設定時)
5. `trigger.matcher && !trigger.matcher(payload, state)` → reject
6. **`ability.condition && !evalCond(state, ability.condition, ctx)` → reject** ← 抜けている

例: `eventRemoveByAP({ apMax:8000, additionalCondition:{ kind:'partnerColor', color:'青' } })` (D08025) は self.partner.colors が **青を含まない**場合、condition が false となり queue **されない** べき。

## 実動作

`handleHook` 内に `ability.condition` を見るコードが **存在しない**。具体的には:

```ts
// src/engine/listeners/triggered.ts:100-130 (要約)
for (const card of collectCardsInPlay(state)) {
  // ...
  if (ability.type !== 'triggered') continue;
  if (trig.hook !== hookName) continue;
  if (!scopeAllowsArea(ability.scope, card.area)) continue;
  if (trig.selfOnly && !selfOnlyMatches(...)) continue;
  if (trig.matcher && !trig.matcher(payload, state)) continue;
  if (!ability.effect) continue;
  event.queue(state, ability.effect, ...);  // ← condition 未チェックで queue
}
```

[src/engine/cond/eval.ts:36-43](../../src/engine/cond/eval.ts) `partnerColor` condition resolver は既に存在するが、`triggered.ts` から **呼ばれていない**。`resolve.stack.ts` の `runOne()` 側でも grep で見当たらず (要再確認、Round 4i-fix Phase 1)、結果として condition は engine 全段で skip されている可能性が高い。

## RCA

Round 4b (commit `4c64c79`) で `triggered.ts` 汎用 listener を実装した際、`ability.condition` チェックを実装漏れ。当時は `matcher` の `(p, s) => ...` で payload kind や cardId を絞り込む設計だったため、condition 用の追加経路が必要と認識されなかった。

その後 Round 4e-4h で `partnerColor` / `caseTrait` 等の condition を持つカード (D08009-22 / D11003-11 / D08025) が登場、condition resolver も整備されたが、listener 側の wiring は更新されないままだった。

## 影響範囲

- **D08025**: 自分の partner.colors に '青' が含まれていなくても effect が queue される
- **D11020**: 影響なし (condition なし)
- **将来カード**: `eventRemoveByAP({ additionalCondition: ... })` 系全般で同症状
- **declared / triggered ability 一般**: triggered ability の condition (CLAUDE.md rules/17 §条件付き能力) が全て無視される可能性

### 不確実性

- resolve 段で再評価される設計の可能性あり (Plan agent 調査では `resolve.stack.ts runOne()` で未発見、要追加検証)
- もし resolve 段で評価されていれば listener 段の missing は **重大度=低** (queue 数増加のオーバーヘッドのみ)、resolve 段でも未評価なら **重大度=高** (誤発動)
