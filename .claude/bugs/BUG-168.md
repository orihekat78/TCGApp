# BUG-168: 突撃[キャラ]/[事件] 変種のみ持ちの名乗りキャラが actor 列挙から消える

## 期待動作
rules/13: 突撃[キャラ] は「名乗り状態でもアクション[キャラ]できる」。名乗りターン中、AI 手列挙
(move-enumerator) と UI actor 列挙 (enumActionSourceCandidates) に actor として現れ、
アクション[キャラ] の合法手が列挙される。

## 実動作 (修正前)
`canAction` (targetKind 'any') が exact-string 判定 (`突撃`/`迅速` のみ) で false →
両呼出元が `if (!canAction) continue` で actor ごと skip → 突撃[キャラ] のみ持ちの合法手が
一切列挙されない (エンジン直呼び canActionAgainstChar は正しく true = UI/AI 層でのみ死ぬ)。

## RCA
namedExceptionAllowed の 'any' 分岐欠落。既存 pin test (tests/engine/flow/main/action.test.ts:108)
が誤挙動を「仕様」として固定していた ("any キーワード判定")。

## 修正
W4 r62 bundled fix: 'any' で 突撃[キャラ]/[事件] 変種を許可 (対象種別の絞りは
canActionAgainstChar/Case が担う)。pin test を新裁定に更新 (case 側 false pin は維持)。
分離実測: 本分岐のみで smoke winsA 498→472 (他 W4 変更は挙動不変 = 分岐無効時 498 復元)。
smoke-baseline re-baseline 済。

## 水平展開
- filtered-突撃 (W4 r62 新設 grantFilteredAssault) は同関数に同時実装 — 同 gap なし。
- canActionAgainstCase 側は 'case' 判定既存で正 (誤列挙なし)。

## 防止策
actor 列挙 gate (canAction) と per-target gate (canActionAgainstChar/Case) の責務分離を
action.ts コメントに明記。新キーワード変種追加時は 'any' 分岐への追加を checklist 化。
