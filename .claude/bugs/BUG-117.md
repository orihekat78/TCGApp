## 概要

`src/engine/effect/atom-handlers.ts` の `targetFilterToPredicate`
(`deckRevealUntil` 専用の TargetFilter→predicate 変換ヘルパ) は

- 対応: `cardId` / `color` / `trait` / `levelMin/Max` / `kind`
- **未実装で黙って drop**: `apMin` / `apMax` / `lpMin` / `lpMax` / `hasSetCards` / `custom`

`TargetFilter` 型には `apMin/apMax/lpMin/lpMax` が **存在する** ため typecheck は通り、
これらを使うカードは **コンパイルエラーにならないまま LP/AP 条件が無視** されていた。

正路 (target pick) の `src/engine/target/candidates.ts` `matchOneFilter` は
ap/lp/level すべて実装済 → **経路で実装が乖離** していた (deckRevealUntil だけ縮小版)。

## 影響カード (3 枚)

| card | テキスト | 誤動作 (修正前) |
|------|---------|----------------|
| B01013 / B01013P 妃英理 | 上から2枚見て **LP0** の【青】キャラを1枚 | LP 無視で最初の【青】を拾う |
| B01053 工藤有希子 | 上から2枚見て **LP2以上** の【白】キャラを1枚 | LP 無視で最初の【白】を拾う |

他の deckRevealUntil カード (D01013 一族 / B01016/34/55/72/90 一族 / B01048 / D11019) は
color / level / trait / kind filter のみ使用 → **影響なし** (水平展開で全 22 枚確認済)。

## 再現 (Playwright 実機)

`tests/e2e/bug-117-deckreveal-lp-filter.spec.ts`:

```
B01053: deck top2 = [D03009(白 LP1), D03002(白 LP2)]
  → 期待: D03002 (LP2以上) を手札に
  → 修正前実機: Received array ["D03009"] (LP1 を拾う = WRONG)
```

修正前 2 件 fail / 修正後 2 件 pass。

## 修正

`targetFilterToPredicate` に ap/lp 判定を追加。deck 内カードは scene candidate
(turnEffects / override) を持たないため printed 値 (`d.ap ?? 0` / `d.lp ?? 0`) で判定 —
`matchOneFilter` の非現場ケース (`base?.ap ?? 0`) と同式。additive (color/level 系の既存挙動は不変)。

## 水平展開調査

- `targetFilterToPredicate` 以外に TargetFilter を **手動で縮小実装** している箇所が無いか:
  `grep "filter\.(color|trait|levelMax|kind)"` を engine 全体に実施 →
  candidates.ts (正路・全 field 実装) と本ヘルパ **のみ**。同種バグ他に無し。
- `deckRevealUntil` 使用カード全 22 枚 (live) の official text vs DSL を突合 →
  ap/lp 使用は上記 3 枚のみ。残りは text-faithful 確認済。

## なぜ E2E をすり抜けたか / 防止策

- 既存 deck-look-N e2e (engine-extensions spec の D01013 同型 5 色) は **color filter のみ** 検証。
  LP/AP filter の検証 case が無かった。
- 防止策: BUG-117 spec で LP filter の「decoy(条件外)を拾わない」assertion を追加。
  今後 ap/lp/level/trait/kind の各 filter 種別を持つカード追加時は、
  **「条件を満たさない decoy を deck 上位に置いて拾わせない」** 形の e2e を必須とする。
- 教訓: 型 (TargetFilter) に field が在ることは「engine が解釈する」ことを保証しない。
  declarative filter を新 verb で受ける際は **どの field を実際に評価するか** を実機で確認せよ
  (card-impl-engine-gates.md の「code path が在るだけでは不十分」教訓と同型)。
