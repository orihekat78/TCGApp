## 概要

`src/engine/target/candidates.ts` の `matchOneFilter` (target pick 候補列挙の正準経路) は
`filter.keyword` を **`CardDef.keywords[]` のみ**で判定していた。

しかし アイコン能力 (**カットイン / 変装 / ヒラメキ / ミスリード**) は 2026-05-27 Option C 移行で
`keywords[]` に入らず **AbilityDef の type/scope/trigger 構造** で表現される:

| アイコン | 表現 |
|---------|------|
| カットイン | `type:'triggered' + scope:'on-hand' + trigger:{hook:'effect:declared', optional:true}` |
| ヒラメキ | `type:'triggered' + trigger:{hook:'evidence:remove-by-action', optional:true}` |
| 変装 | `type:'icon-disguise'` |
| ミスリード | `type:'icon-misread'` |

そのため `filter.keyword:'カットイン'` は **どのカードにも一致しない** (全カードの
`keywords[]` に 'カットイン' は 0 件)。BUG-117/118 と同型の「型に field が在るが engine が
正しく評価しない」field-drop バグ。

## 影響カード (1 枚)

| card | テキスト | 誤動作 (修正前) |
|------|---------|----------------|
| B05112 バーボン a1 | 【宣言】【スリープ】手札から**【カットイン】を持つ**レベル5以下の【黒】のキャラを1枚まで登場 | `keyword:'カットイン'` が候補0 → 宣言能力が常に no-op (キャラを登場できない) |

`filter.keyword` を使うカードは B05112 a1 の **1 枚のみ** (全 src/cards grep で確認)。
他のカットイン/変装/ヒラメキ持ちカードは「自身がカットインする」実装 (`effect:declared` hook +
`charModifyAP $contact.byUid`) であり、`filter.keyword` で他カードを絞る用途は B05112 のみ。

additive。`filter.keyword` 不使用カードは候補列挙が完全不変。

## 教訓 (LESSONS-LEARNED-3 教訓 23 の追補)

「型に field が在る≠engine が評価する」は **値の表現方法** にも及ぶ。`filter.keyword` は型上
任意文字列を受けるが、アイコン能力は keywords[] という想定の格納先に無い。新しい filter 述語を
書くときは「その値がどこに格納されているか」を実データで確認せよ。判定述語は 1 箇所に集約し、
複数経路が同じ判定を別実装しない (ドリフト = BUG-117/118 の温床)。
