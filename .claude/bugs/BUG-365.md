# B02030 Cut-In negation

## Expected

- 相手のCut-In使用だけを観測し、変装では発動しない。
- 自分の現場のset-cardを正確に2枚リムーブした場合だけ、そのCut-In効果を無効にする。
- set-cardは異なるhostから1枚ずつ選べる。
- 使用Cut-Inカードはremoveに残り、contactの行動済み順序は巻き戻さない。

## Actual

- `B02030`は宣言能力`a2`だけを持ち、Cut-In反応`a1`が明示DEFERされていた。
- `Effect.kind='negate'`は型だけ存在し、resolverで常に例外になった。
- 通常`cutin:used` observerはCut-In自効果の後に解決するため、無効化に間に合わなかった。

## Root cause and fix

- 人間のoptional/exact-two選択を挟む即時無効化用のstack provenanceが無かった。
- negateを含むCut-In reactionだけを`immediateDeclaredReaction`として自効果より優先した。
- 既存`charRemoveSetCard n:2 minimumPolicy:exact`で物理set occurrenceを選ぶ。
- 2枚除去後、同じdeclared batchの未解決Cut-In自効果だけをcancelする限定negateを実装した。
- 使用カードのremove移動と`cutInUsed`は既存flowのまま維持した。

## Horizontal investigation

- 通常Cut-In observer、B10087の自効果先行、owner orderingを回帰確認した。
- 1 host/複数hostのexact-two set removalと不足時no-opを確認した。
- both owners、disguise negative、save round-trip、次プレイヤー行動を公開dispatchで確認した。

## Prevention

- 即時反応は通常observerと別のstack priorityとして明示する。
- 無効化はcard IDだけでなくdeclared batch・player・resolution kindで特定する。
- optional cost不足、decline、保存復元、contact行動順をT3 gateに含める。
