## 仕様 (rules/15)
D11014 a2 step3「〚カード名[萩原千速]〛を登場させた場合、カードを1枚引く」は、step2 sceneEnter で書かれた
`$entered` bind を step3 conditional (boundMatchesFilter) が読んで判定すべき。

## 実動作 (バグ)
BUG-105 で sequence は pick-pause するようになったが、human 経路の `useEngineDispatch.effectPickResolve` は
(1) pick 解決した sceneEnter atom と (2) continuation remainder (conditional) を **別々の `event.queue`** で
**別 ctx** 実行していた。`entryToCtx` は entry.bindings から ctx.bindings を復元するが、両 queue とも
bindings 未指定 + Immer draft 取込で proxy 化するため、sceneEnter が書いた `$entered` が step3 の ctx に
届かず → 1 ドロー不発。

## 修正
`useEngineDispatch.effectPickResolve` の continuation 分岐を **保存 ctx を直接使う runEffect** に変更:
- 中断中の sequence/chain は continuation に「中断時の ctx」(plain bindings、globalThis 側) を保持している。
- continuation がある場合、resolved atom と remainder を **同一の保存 ctx (chainCont.ctx)** で `runEffect` 実行。
  → sceneEnter の `$entered` 書込が plain な保存 ctx.bindings に残り、step3 conditional が同 object を読む。
- continuation 無し (単発 pick) は従来通り `event.queue`。
- `effect:resolve:start/end` hook は listener 不在のため runEffect 化で skip しても影響なし (確認済)。

## 効果範囲 / 水平展開
- continuation 機構を使う全カード (D11007 a3 / D08013 / D08024 / D11020 / D08003) に影響 → 全 test PASS で回帰なし。
- 保存 ctx 使用で D11007 a3 の uid drop も解消 (source.uid 込みで実行)。
- AI 経路は walk で同期解決 (BUG-106) のため continuation を経ず、本修正は human 経路専用。
