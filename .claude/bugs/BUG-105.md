## 仕様 (rules/15)
効果は記載順に解決。pick を含む step の後段 step は、その pick の結果が反映された盤面で評価されるべき。

## 実動作 (バグ)
`resolver.ts` の `sequence` は素の for ループで、step が pick を side-channel に積んで return しても
継続実行する (`chain` のような pick-await pause/continuation が無い)。結果、pick を含む step の後段が
**pick 解決前の盤面**で評価される:
- **D08024 a1**: step2 charModifyAP の対象列挙が step1 sceneEnter (登場) 前 → 登場キャラを選べない。
- **D11020 a1**: step2 conditional (removeTraitAtLeast) が step1 sceneRemove 前に評価。
- **D11014 a2**: step3 conditional (boundMatchesFilter $entered) が step2 sceneEnter の bind 前に評価。

## 修正
`resolver.ts` の `sequence` に `chain` 同型の **pick-await pause + continuation** を追加 (ただし
no-apply-break はしない=各 step は独立)。pick を含まない sequence は queue 長が増えず従来通り一括実行 (動作不変)。
- pick を含む step で pause → 残り step を `__pendingChainContinuation` に退避 → pick 解決後に
  continuation で残り step が **post-pick 盤面**で実行される。

## 効果範囲
- **D08024 (state 依存)**: ✅ 修正。step2 が continuation で post-step1 scene を見て登場キャラを選択可能。
- **D11020 (state 依存)**: ✅ 修正。step2 condition が post-step1 remove を見る。
- **D11014 (bind 依存)**: ⚠ 部分。sceneEnter は正しい順序で実行されるが、step2 pick 解決時に書かれる
  `$entered` bind が step3 の continuation ctx (pause 時 capture) に伝播しない → step3 draw は別途
  bind-propagation 対応が必要 (継続課題、本修正の範囲外)。
- **D08013 (BUG-078)**: 保護。step2 evidenceToHand が post-step1 evidence を pick (Phase E 不変)、
  step3 discard は continuation で resolve (bug-077 Phase F を新機構に更新、15/15 PASS)。
