## 期待動作

継続 AP/LP 修飾 (continuousModifier.apDelta/lpDelta) の condition が他キャラの有効 AP/LP を参照しても、
read は有限ステップで終端する (循環は base 値で打ち切り)。

## 実動作

`read.char.ap/lp/level` は `continuousDelta(s,uid,which)` を **guard 無し** で直接呼ぶ
(_inContinuousDelta フラグを立てるのは `candidates.ts` の `continuousDeltaSafe` のみ)。
`cond/eval.ts` の `apAtLeast`/`lpAtLeast` は `charRead.ap`/`charRead.lp` を直接呼ぶ (これも無 guard)。

→ キャラAが「apDelta gated by lpAtLeast」、キャラBが「lpDelta gated by apAtLeast」を持つと、
A.ap → contDelta(apDelta) → evalCond(lpAtLeast) → B.lp → contDelta(lpDelta) → evalCond(apAtLeast)
→ A.ap → … と **無限相互再帰 → stack overflow**。実機再現済 (lvlDelta 不在でも発生 = 本 wave 起因ではない)。

## 本 wave (lvlDelta) との関係

lvlDelta は **新たな再帰面を作らない**: level は effective-read される唯一の経路が
`candidates.matchOneFilter` (= continuousDeltaSafe guard 配下) で、`$self.level` の effective dyn も
`levelAtLeast` condition も engine に不在。level 軸は依存グラフの **sink** (ap/lp に gate されるが
level を読み返すものが無い) ゆえ cycle の edge になれない。本 wave は安全 (review verdict PASS)。

## RCA

`continuousDelta` 系の再入 guard が `candidates.ts` 入口にしか無く、`read.char.*` 入口 + `cond/eval.ts`
の AtLeast 系が **guard を経由しない** entry point になっている (BUG-113 cycle 注記の射程外)。

## 修正方針 (別 commit)

`read.char.ap/lp/level` の continuousDelta 呼び出しにも `continuousDeltaSafe` 相当の再入 guard を
かける (depth guard or 共有フラグ)。ap/lp/level の3軸対称に適用。挙動不変 (既存カードは循環 condition
非該当 → guard 不発火) を smoke + 全 vitest で確認の上、additive に投入できる。

## 防止策

- 効果値 read の循環は **単一の再入 guard** に集約 (read entry も含める)。
- continuous condition が他キャラの有効値を参照しうる新カード追加時は再帰面を review。
