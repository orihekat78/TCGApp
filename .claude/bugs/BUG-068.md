## 発見契機

2026-05-23 全 BUG audit (audit agent 3) で発見。BUG-052 「D11019 bind ref 未解決」の 残課題セクションに以下が記述されていたが、follow-up BUG が起票されていなかった:

> 他 atom (`charModifyAP` / `discard` / `effect:declared` payload 等) で `$<key>.<field>` 参照する場合は同 pattern で resolveBindRef 追加。resolveEffectPicks への bind ref 統合は別 refactor で

## 期待動作

`$matched.uid` / `$entered.cardId` 等の bind ref を、`charModifyAP` / `charModifyLP` / `discard` / `effect:declared` payload など **全 atom** で解決できる。

## 実動作

`src/engine/effect/atom-handlers.ts:111-124` の `resolveBindRef` helper は以下 3 atom のみ呼び出される:

- L223: `sceneEnter` (`cardId`)
- L304: `charGrantKeyword` (`uid`)
- L310: `charRevokeKeyword` (`uid`)

L278-285 の `charModifyAP` は `a.uid` をそのまま渡し、`$matched.uid` のような bind ref が含まれていても解決されない → atom 内部で uid が存在せず silent fail。

現状は D11019 (15 の受難) のみが bind ref を使うが、将来カードで `$matched.uid` を charModifyAP に渡すと **latent landmine** として顕在化する。

## 関連ファイル

- `src/engine/effect/atom-handlers.ts:111-124` (resolveBindRef helper)
- `src/engine/effect/atom-handlers.ts:278-285` (charModifyAP、未配線)
- `src/engine/effect/atom-handlers.ts:286-293` (charModifyLP、推定、未配線)
- `src/engine/effect/atom-handlers.ts:134-151` (discard、未配線)
- `src/engine/effect/resolve-picks.ts` (resolveEffectPicks への統合は別 refactor の余地)

## 想定修正

1. `resolveBindRef` を全 atom (uid / target 受け取り箇所) で呼び出すよう拡張
2. unit test 追加: 各 atom が `$matched.uid` を bind context から解決できることを assert
3. resolveEffectPicks への bind ref 統合 (大きな refactor、別 BUG 候補)
