## 概要

`engine/cond/eval.ts` の `caseTrait` condition が事件カードの特徴を **`CardDef.traits`** (キャラ特徴用) から
読んでいた。事件カードの特徴は専用フィールド **`CardDef.caseTraits`** (`caseTraits?: string[]`、
例 D08026=`caseTraits:['古城']` / `traits:[]`) に格納されるため、caseTraits のみに特徴を持つ事件で
【事件古城】等の条件が **永久に false** になる field-drop バグ (BUG-117/118/122/123 と同族)。

> 検出契機: disguise-hook の【事件YAIBA】変装 (B06017) ゲートを調べる過程で、caseTrait 評価経路が
> caseTraits を見ていないことが判明。

## 期待動作 vs 実動作

| 事件カード | traits | caseTraits | `caseTrait('古城')` 修正前 | 修正後 |
|------|-------|-----------|---------|-------|
| D08026 (青の古城探索事件) | `[]` | `['古城']` | **false (バグ)** | true |
| D11021 (婚活パーティー) | `['婚活']` | `['婚活']` | true (婚活が traits にも在り偶然動作) | true |

D11021 が 婚活 を **両フィールド** に冗長保持していたため 婚活 gating (D11003/D11005) は偶然成立しており、
バグが顕在化していなかった。古城 を gating するカードは現状 0 件のため active な機能不全はなし (latent)。
ただし D11021 のデータ冗長を「caseTraits のみ」に正すと 婚活 gating が静かに壊れる脆さがあった。

## 修正

`caseTrait` branch を `caseTraits` + `traits` の **union** で評価:

```ts
const traits = [...(d?.caseTraits ?? []), ...(d?.traits ?? [])];
return traits.includes(cond.trait);
```

union のため strictly more permissive → 既存挙動 (D11021 婚活 / 非該当 false) を保持しつつ
caseTraits のみの古城系を解禁。`caseColor` が `caseInfo.colors` fallback を持つのと対称だが、
runtime state に caseTraits フィールドは無いため CardDef のみ参照で十分。

## 水平展開調査 (全 case カード + 全 caseTrait 利用)

- 全 36 case カードの traits/caseTraits を突合: 非空 caseTraits は **D08026(古城) / D11021(婚活)** のみ。
  他 34 枚は両方空。古城 は caseTraits のみ・婚活 は両方。→ union 修正は D11021 を保持し古城を解禁、
  他は無影響。
- caseTrait 利用箇所: `caseTraitConditioned` wrapper (D11003/D11005, 婚活) + B09101 (`犯人`, 該当 case 0 件で
  fix 無関係)。古城 gating カードは 0 件。
- caseColor / caseStatus 等 他の case-field 評価は正しいフィールド (colors/status) 参照で健全。

## 検証

- `tests/engine/cond/eval.test.ts` に caseTrait describe 追加 (caseTraits のみの古城→true / 非該当→false /
  両フィールド婚活→true / 空→false)。
- 回帰: caseTraitConditioned.test / D11003 / D11005 unit + case-trait-conditioned e2e (4) すべて pass
  (D11021 婚活 true / D08026 で婚活照会 false の negative も保持)。typecheck clean。

## 教訓 (BUG-122 の続き)

「値の格納先を確認」(BUG-122) の case-field 版。事件カードは **色=colors / 特徴=caseTraits / 状態=status**
と専用フィールドを持つ。condition 評価は必ず正しいフィールドを参照すること
(キャラ用 `traits` と事件用 `caseTraits` は別物)。冗長データ (D11021 の二重保持) はバグを隠蔽する。
