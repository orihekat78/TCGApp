## ユーザー指摘

> ネクストヒントはそもそも挙動がおかしいので修正してほしい。

## 期待動作 (rules/12)

1. **step1**: FILE 最上部 (アシスト中パートナー除く) を手札に加える
2. **step2 (任意)**: FILE 枚数以下のレベルのキャラ/イベントを 1 枚使用可
   - step1 で得たカードも使える
   - step1 カードは step2 の FILE 枚数判定に **数えない** (engine は popTop 後の file.length で判定)
   - 使用カードは事件の色制限 (rules/20)
   - キャラ → アクティブ + 名乗り状態で登場 / イベント → 効果発動 + リムーブ

## 実動作 (修正前)

- [src/ui/hooks/useActionsPanelFlow.ts](../../src/ui/hooks/useActionsPanelFlow.ts) `runNextHintFlow`
  が confirm modal 後 `dispatchEngineAction({ type:'nextHint', player })` を **`optionalCardId`
  無し** で呼ぶ
- engine `runNextHint(state, p, undefined)` は step1 (FILE→手札) のみ実行し step2 をスキップ
- confirm modal は「続けて1枚使用できます」と表示するが実際には使えない
- step2 用の picker UI は **未実装** (コードに「次段で実装予定」コメント残存)

## 関連ファイル

- [src/engine/flow/main/next-hint.ts](../../src/engine/flow/main/next-hint.ts) — engine 側 `runNextHint(state, p, optionalCardId?)` は step1+step2 atomic で正しく実装済 (バグ無し)
- [src/ui/hooks/useActionsPanelFlow.ts](../../src/ui/hooks/useActionsPanelFlow.ts) — runNextHintFlow が optionalCardId を渡さなかった
- [src/ui/components/ActionsPanel.tsx](../../src/ui/components/ActionsPanel.tsx) — NH button 経由で flow 起動
- [src/ui/hooks/useNextHintPicker.ts](../../src/ui/hooks/useNextHintPicker.ts) — **本 fix で新規作成** (Zustand store + Promise hook、useConfirmation 同型)
- [src/ui/components/Playmat.tsx](../../src/ui/components/Playmat.tsx) — picker UI mount

## RCA

engine 側 `runNextHint(state, p, optionalCardId?)` は最初から step1+step2 atomic 設計
で実装されていた (UI から optionalCardId を渡せば step2 まで動く)。一方 UI 側は
「confirm modal で発動可否を確認するだけ」の MVP 実装で終わっており、step2 用 picker が
未実装だった。「engine が step2 をスキップしている」と誤認されやすい構造 (UI コメントの
「次段で実装予定」が放置されていた)。

## 修正

### Option A 採択 (atomic, engine 不変)

骨格凍結原則 (CLAUDE.md) 準拠。engine の atomic 設計を尊重し UI 側で「FILE-top + 使用可能
手札」を picker で事前提示、選択結果を 1 dispatch で渡す。

### 実装 (commit 9380314)

- **新規** [src/ui/hooks/useNextHintPicker.ts](../../src/ui/hooks/useNextHintPicker.ts):
  `useConfirmation` 同型の Zustand store + Promise hook。
  `ask({ fileTopCardId, fileTopName, candidates })` → `Promise<NextHintChoice>`
  (`{kind:'use';cardId} | {kind:'skip'} | {kind:'cancel'}`)
- **書換** `runNextHintFlow`:
  1. `canStartNextHint` check
  2. FILE-top cardId 算出 ([mutate/file.ts popTop](../../src/engine/mutate/file.ts#L37) と同ロジック)
  3. `postPopCount = (非アシスト FILE 枚数 - 1)`。候補 = `[fileTopCardId, ...hand]` を
     `readDef.card(id)` で `level ≤ postPopCount` かつ 色 ⊆ 事件色 で filter
  4. `await useNextHintPicker().ask({...})`
  5. use → `dispatchEngineAction({ type:'nextHint', player, optionalCardId })` /
     skip → `dispatchEngineAction({ type:'nextHint', player })` (optionalCardId 無し) /
     cancel → `{ ok:false, reason:'cancelled' }`

### UX 改善 (commit db08c74)

picker UI を専用 modal (NextHintPickerModal) から **HandZone pick-mode に統合**。
ユーザ要望「手札拡大 UI で出せるカードを黄色枠でピックアップ選択したい」反映。
HandZone を汎用化 (pickBannerText/pickableCardIds/pickSkipLabel/onPickCancel)、Playmat で
FILE-top を合成カードとして手札末尾に追加表示、候補のみ pickable 化。

## 水平展開

- 「engine API は完全だが UI が部分実装」パターンは他に類似なし (typescript / vitest で
  cover される flow は完全実装、cover 漏れだったのは NH のみ)
- HandZone pick-mode 汎用化は既存 discard-pick (`effectPickResolve`) と互換: pickableCardIds
  未指定で全カード pickable の従来動作を維持、回帰なし
