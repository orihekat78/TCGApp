## 期待動作

Pattern B pick (target=pick query、cardIds/cardId マーカー無しの generic 経路) で n:{min:2,max:2} 等の
複数枚 pick が解決されたとき、選択された **全枚数** が atom の `target` 配列に載る。
B04005/B07002 a1「手札を2枚リムーブする」= 2枚とも remove へ。

## 実動作 (修正前)

全 3 経路で先頭 1枚に collapse:

1. **human**: `applyPickAndContinuation` generic 分岐が `target:[resolvedCardId]` (単数) — UI Playmat
   multi-select が渡す `pickedUids` を握り潰す
2. **AI drain**: `drainAiEffectPicks` → 同上 (chooseAiPick は pickedUids を正しく構築していた)
3. **AI 同期 walk**: `resolveEffectPicks` generic Pattern B が `target:[pickValue]` (heuristic 単一選好)

shipped 影響: **B04005 江戸川コナン a1** (discard n:2、catalog-reuse バッチ、behavioral test 無し) が
全経路で 1枚しかリムーブされず。handReveal (B09061) は zone 不変 + atom レベル exact-N gate で機能的
無害だが bind が 1枚しか入らない (core.ts ★未対応(3) として既知文書化)。

## 修正 (engine + UI の 2 層)

- [apply-pick.ts](../../src/engine/effect/apply-pick.ts) generic 分岐: `target: allCardIds`
  (= pickedUids ?? [pickedUid] の解決済全件)。n:1 は `[resolvedCardId]` と byte 同一。
- [resolve-picks.ts](../../src/engine/effect/resolve-picks.ts) AI 同期 generic 分岐: nMax>1 は
  cardIds contract (BUG-103) と同流儀の greedy nMax 枚。nMax<=1 は旧 path 不変。
- **UI 側** (playwright 実機検証で発見 — engine fix だけでは human 経路が直らない):
  [HandZone.tsx](../../src/ui/components/HandZone.tsx) に multi-select (pickNMin/pickNMax/onPickMulti、
  CardListModal と同 contract: toggle + 「完了 (N/M枚)」ボタン) を追加し、
  [Playmat.tsx](../../src/ui/components/Playmat.tsx) の discard pick が nMax>1 のとき pickedUids を
  収集して dispatch。banner 文言も「手札から{N}枚選んで〜」に (旧: 常に「1枚」)。nMax<=1 は
  単発 click 経路 byte 不変。
- core.ts handReveal ★未対応(3) → 解消済に更新。

## 防止策

- 新 atom が「N枚 pick」(n≥2) を使う場合は 3 経路 (human apply / AI drain / AI 同期 walk) の実機 probe を
  authoring 前に必ず走らせる ([[feedback-carrier-reuse-human-path-empirical]] と同じ教訓の pick 版)。
- catalog-reuse バッチ出荷カードは descriptor test のみのものが多い — n≥2 pick を含む shipped カードを
  見つけたら behavioral test を追加する。
