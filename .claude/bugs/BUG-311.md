# 強制公開サーチの不要な順序選択

## 期待動作

同じ印字を持つ32定義は、一致カードを強制的に処理し、残りをデッキ下へ移した後、
デッキ全体をシャッフルする。印字にない順序選択を要求しない。

## 実動作（修正前）

`deckToBottomBound`の既定`arbitrary`により、人間所有者かつ残り2枚以上で
`pendingDeckReorder`が発生した。直後に全デッキをシャッフルするため、選択は不要かつ無意味だった。

## RCAと修正

`deckToBottomBound`の既定値に、公式上の選択権がない定義も依存していた。
公式rawとTSVを照合した32定義へ`order:'preserve'`を明示した。

## 横断調査と予防

同じ`deckRevealUntil -> deckToBottomBound -> deckShuffle`形を横断確認した。
静的回帰で32定義、直後のshuffle、alias parity、除外カードを固定する。
代表public human経路では`pendingDeckReorder === null`を検証する。
