# BUG-175: pick 解決後の再実行 ctx が chooser 座標系 (BUG-174 family 第3経路)

## 期待動作
B04058「そうした場合、相手は手札を1枚リムーブする」= discard{n:1, player:'opp'} (owner=self 相対)。
chooser は手札所有者 (opp)。pick 解決後の atom 再実行でも owner (self) 座標系で
resolvePlayer('opp') → opp の手札から discard される。

## 実動作 (修正前)
`applyPickAndContinuation` の continuation 無し経路 (最終 step の pick) が
`event.queue(..., { player: pending.player })` — **chooser (opp)** を source.player に渡すため、
再実行 ctx で resolvePlayer('opp') が opp の相手 = **self** に反転。self 手札 (空) を対象に
no-op → 相手手札が減らない silent miss。decline 経路 (applyPickSkipAndContinuation) も同形。

## 関連ファイル
- src/engine/effect/pending-state.ts — `PendingEffectPickSide.ownerPlayer?` 追加
- src/engine/effect/resolve-picks.ts:415 — push 時に `ownerPlayer: ctx.source.player` 同梱
- src/engine/effect/atom-handlers/picks.ts:127 — 同 (chooser==owner site、挙動不変)
- src/engine/effect/apply-pick.ts — event.queue 2 site を `pending.ownerPlayer ?? pending.player` に

## RCA
BUG-174 (short-form side 二重相対化) と同根: pick 境界を跨ぐと座標系 (owner 相対) の基準が
失われる。BUG-174 修正は **候補列挙側** (buildShortFormPick side) のみで、**解決後再実行側**
(event.queue source) は未修正だった。既出荷カードは全て chooser==owner (「相手が選ぶ」pick は
owner-pick 化する dead 配線ゆえ存在せず) — W3 review が「cross-side 短縮形 pick latent、
出荷実態は discardRandom のみ」と記録していた latent が B04058 (初の chooser=opp consumer) で顕在化。
