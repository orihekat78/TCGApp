## ユーザー指摘

> #5: 事件カードの能力を発動しない。

## 期待動作

D08026 (青の古城探索事件) / D11021 (千速と重悟の婚活パーティー) の事件カード
は 2 種の能力を持つ:

- **a1 caseResolvedHandRemove** (triggered, hook=`case:to-resolved`): 解決編に
  なったとき自分手札 1 枚リムーブ
- **a2 caseDeclaredEvidenceFlip** (declared, condition=`caseStatus '解決編'`):
  ユーザー宣言で表向き証拠コストにより対象 AP 修正

両能力ともユーザー操作下で正しく発動できなければならない。

## 実動作 (修正前) — 3 層複合バグ

### 層 1: shared class の scope 設定ミス (engine 側 + UI 列挙側両方を block)

`src/cards/_shared/caseResolvedHandRemove.ts:22` および
`src/cards/_shared/caseDeclaredEvidenceFlip.ts:30` で
`scope: 'on-scene'` ハードコード。`AbilityScope = 'on-scene'` は
「現場 area のみ」の意味で、`src/engine/listeners/triggered.ts:scopeAllowsArea`
で `area === 'scene'` のみ true を返す。事件カードは `area: 'case'` で配置
されるため:
- triggered (caseResolvedHandRemove): listener が scope 不一致で skip → a1 発動せず
- declared (caseDeclaredEvidenceFlip): 同 scope 検査が cost/condition 評価前に
  fail し UI 列挙から除外

### 層 2: engine 側 `findSceneChar` (declared-ability.ts) が scene 限定

`src/engine/flow/main/declared-ability.ts:22` の `findSceneChar(state, uid)` が
`state.players[p].scene` のみ走査。uid='case:self'/'case:opp' を渡しても null
返却 → `canDeclaredAbility` が false → UI から能力使用不可

### 層 3: UI 列挙 (`enumDeclaredAbilitySources` / `enumDeclaredAbilityIdsFor`) が scene 限定

`src/ui/hooks/useActionsPanelFlow.ts:282` / `:314` で
`state.players[player].scene` のみ iterate。事件カードを source 候補に
含まない → ActionsPanel の宣言能力選択画面に事件カード非表示。
`makeAbilityCtx` の area type も `'scene' | 'partner-area'` のみで
`'case'` 不受理。

## RCA (Root Cause Analysis)

`AbilityScope` enum に `'on-case'` が存在せず (`'on-scene'` / `'on-partner-area'`
/ `'on-hand'` / `'on-evidence'` / `'always'`)、case 専用 scope の設計が抜けて
いた。`_shared/caseXXX` helper を作成した際に「事件カードも scene と同様に
'on-scene' でよかろう」と誤判断したのが起点。

加えて declared ability infrastructure (engine + UI) が当初 SceneCharacter のみ
対象として設計されており、事件 / パートナーの宣言能力経路が後付けで部分的に
しか配線されていなかった。

## 修正

### Fix 1: shared class scope を 'always' に変更

```ts
// _shared/caseResolvedHandRemove.ts
type: 'triggered',
scope: 'always',  // ← 'on-scene' から変更
//... condition (case:to-resolved hook + caseStatus) で十分 gate

// _shared/caseDeclaredEvidenceFlip.ts
type: 'declared',
scope: 'always',  // ← 'on-scene' から変更
condition: caseStatus '解決編' で適切 gate
```

### Fix 2: engine 側 `findSceneChar` を `findCardOnBoard` に拡張

`src/engine/flow/main/declared-ability.ts`:
- uid prefix `case:` / `partner:` 認識し scene / case / partner-area から検索
- return type に `area` 追加
- `useDeclaredAbility` の error message も更新 (`not in scene` → `not on board
  (scene/case/partner-area)`)

### Fix 3: UI 列挙関数を case card 包含

`src/ui/hooks/useActionsPanelFlow.ts`:
- `enumDeclaredAbilitySources`: scene iterate 後 case card も check して
  uid=`case:${player}` を sources に追加
- `enumDeclaredAbilityIdsFor`: `case:` prefix を検出して case area へ
- `makeAbilityCtx` の area type に `'case'` 追加
- `runDeclaredAbilityFlow` の cost/ctx 構築でも area 推定ロジック追加

## 水平展開

- partner ability は別経路 (`runPartnerAbilityFlow`) で `area: 'partner-area'`
  既に正しく扱っているため影響なし
- triggered listener (`triggered.ts`) の `collectCardsInPlay` は case を含む
  ので scope='always' に変更すれば listener 側修正不要
- 既存 vitest 1547 PASS / smoke 1000 戦 0 exception 維持

## 残課題 (separate BUG 候補)

- 事件カード declared ability の `limit: { kind: 'turn', n: 1 }` 制約が
  `incrDeclaredUseCount` (scene 限定) で enforce されない。case には
  declaredUseCount field がない。turn 上限管理の case 対応は別 BUG で扱う

## 防止策

- `AbilityScope` に `'on-case'` を将来追加検討 (今回は 'always' で代替)
- shared class の scope 既定値を「area から推定」する factory pattern
  検討 (`caseXXX` → scope=any 等)
- declared ability infrastructure の対応 area 一覧を docs 化
