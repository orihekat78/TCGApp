## Expected

B03023の登場観測時、相手デッキ上1枚を公開し、そのカードを元の位置へ戻す。
複数の B03023 は全て発動するが、各解決で公開するのは同じ上から1枚だけ。

## Actual

`log` atom は文言だけを記録し、カードIDを UI 公開チャネルへ渡さなかった。公開内容を確認できない。

## RCA

「元に戻す」を state no-op と誤認し、公開情報そのものを effect state/log に表現しなかった。

## Fix

既存 `deckRevealUntil{player:'opp',maxN:1}` を使う。deck は非移動のまま、
`__pendingDeckRevealSide` と詳細 log へ公開情報を残す。

## Horizontal investigation

B04079 など既存の「上から1枚見る」も同 primitive で、deck 不変と UI 表示を実現済み。
新 engine/UI primitive は不要。

## Prevention

公開して元に戻す効果は state差分だけでなく、UI side-channel と card ID 付き log を public flow で検証する。

## Implementation update

`deckRevealUntil` now receives `presentation:'reveal-return'` for B03023. Its overlay shows return-to-deck semantics, and the pending reveal channel is FIFO with source identity so B03023/B04012 cannot overwrite one another.

Public reveal and private look are now separate payload semantics. B03023 declares `visibility:'public', viewer:'all'`; ordinary look effects default to `visibility:'private'` and the ability owner. A CPU private look is redacted from the human log and never enters the human DOM/image side-channel. Public reveal pauses CPU progression until its overlay completes.

The horizontal audit classifies all 190 executable `deckRevealUntil` callers: 59 confirmed public, 130 confirmed private looks, and 1 unresolved. Confirmed public callers now declare `public/all`; only B03020 retains the fail-closed default pending authoritative visibility evidence. `捜査3` on B08074 is public by rules/13 (`捜査X` explicitly says to reveal X cards). Real CPU B01093, B03023, and B08074 flows verify public cards and CPU pause on desktop and 851x393 landscape.
