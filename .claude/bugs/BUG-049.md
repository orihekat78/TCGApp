## ユーザー指摘

> #8: こちらが事件カードにアクションした際に、相手がガードしました。この時、
> 相手の証拠・自分の証拠は変わらないはずなのに相手の証拠ー１、自分の証拠＋１
> が行われていた。

## 期待動作

rules/07 + rules/10:
- アクション[事件] が **ガードされなかった場合のみ** → 相手証拠 -1 + 自分証拠 +1
- アクション[事件] が **ガードされた場合** → コンタクト発生 (攻撃キャラ vs
  ガードキャラ)、AP 判定で敗者リムーブ、**証拠変動なし**

## 実動作 (修正前)

`src/ui/hooks/useEngineDispatch.ts:275-287` の `actionJudge` ハンドラが
`ax.target.kind === 'case'` で常に証拠操作を実行していた:

```ts
case 'actionJudge': {
  const ax = flow.action._getContext(action.actionId);
  if (!ax) return;
  if (ax.target.kind === 'case') {
    // ← ax.guardUid が set されているかチェックせず常に実行
    flow.actionCase.removeOpponentEvidenceTop(draft, ax);
    flow.actionCase.gainSelfEvidence(draft, ax);
  } else {
    flow.action.snapshotAP(draft, ax);
    flow.contact.judge(draft, ax);
  }
  return;
}
```

flow:
1. action[case] declare → guard-window
2. opp guard 成立 → `tryGuard` で `ax.guardUid = guarderUid` set、phase =
   'leave-resolution'
3. advance → contact-pending → action-1/2 → judge
4. judge phase で **証拠変動誤実行** (本 BUG)

## RCA (Root Cause Analysis)

Phase 8 per-step action dispatch 設計時:
- char target: judge = AP 判定 (snapshotAP + contact.judge)
- case target: judge = 証拠変動 (removeOpponentEvidenceTop + gainSelfEvidence)

の 2 分岐を作ったが、「case target が guard された場合」の third branch を
失念。rules/07 + rules/10 では明確に「ガードされなかった場合のみ証拠操作」と
規定されているのを engine 側で表現していなかった。

## 修正

`src/ui/hooks/useEngineDispatch.ts`:

```ts
case 'actionJudge': {
  const ax = flow.action._getContext(action.actionId);
  if (!ax) return;
  // user_request 20260522_01 #8 fix: case target でも guard 成立した場合は
  // 証拠変動なし — contact AP 判定で攻撃キャラ or ガードキャラのリムーブのみ
  if (ax.target.kind === 'case' && !ax.guardUid) {
    // rules/10: 相手証拠リムーブ + 自証拠獲得 (unguarded のみ)
    flow.actionCase.removeOpponentEvidenceTop(draft, ax);
    flow.actionCase.gainSelfEvidence(draft, ax);
  } else {
    // char target OR case target + guard 成立 → contact AP 判定
    flow.action.snapshotAP(draft, ax);
    flow.contact.judge(draft, ax);
  }
  return;
}
```

## 水平展開

- AI 経路 (`resolveActionAgainstCase` in `src/ai/action-resolution.ts:155`):
  常に `passGuard` を呼ぶ実装で `guardUid` set されない → 既存挙動と互換
- char target に guard 経路は元から `snapshotAP + contact.judge` で正しい
- 影響: 既存 vitest 1530+ PASS / smoke 1000 戦 0 exception

## 防止策

- 「ガードされなかった場合のみ X」のような rules 条件は、engine 側で
  guardUid 存在チェックを統一的に行うヘルパ (`isGuarded(ax)`) 化を検討
- 新規 action 系修正時は rules/07 + rules/10 + rules/08 を必須参照リストに
- per-step action dispatch のテストは「全 phase × char/case × guard/unguard」
  matrix で網羅 (本 BUG fix で 1 case 追加、残 matrix は別 BUG で拡充)
