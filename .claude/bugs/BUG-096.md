## 仕様 (rules/17)

【ターン①/②】= 各ターンに1回/2回だけ発動。triggered ability でもこの回数制限が適用される。

## 期待動作

triggered ability の `limit:{kind:'turn',n}` が、1ターンに n 回まで発火するよう enforcement される。

## 実動作 (バグ)

- `ability.limit` は declared フロー ([declared-ability.ts:82-84](../../src/engine/flow/main/declared-ability.ts)) でしか読まれない。
- triggered 発火経路 ([triggered.ts handleHook](../../src/engine/listeners/triggered.ts)) は selfOnly/matcher/matcherCondition/condition/effect のみ gate し `event.queue` する。`limit` も fire-count も見ず、`event.queue` も (uid,abilityId) dedup しない。
- 影響: **D11016 a1** (action:guarded)・**D11007 a3** (contact:start) の【ターン1】が1ターンに**複数回発火可能**。`limit` は死にメタデータ。
- ※ declared の limit (D08005 a2 / D08026 a2 / D11021 a2) は BUG-067 で enforcement 済み＝正常。

## RCA

BUG-067 (2026-05-28) は declared フローにのみ limit enforcement を入れた。triggered フローは
別経路 (listeners/triggered.ts) で、同じ `declaredUseCount` 機構を流用していなかった。
旧 memory note (obs 7686) の「limit 未 enforcement」の triggered 分の積み残し。

## 修正

[triggered.ts handleHook](../../src/engine/listeners/triggered.ts): effect-exists チェック直後に
`ability.limit?.kind==='turn'` なら `declaredUseCount >= n` で skip、queue 後に `incrDeclaredUseCount`。
declared と同じ `SceneCharacter.declaredUseCount` + `resetTurnFlags` (ターン境界 reset) を流用。

## 水平展開

- triggered limit を持つ MVP カード: D11016 a1 / D11007 a3 のみ。非MVP partner は abilities:[] で影響なし。
- limit を持たない triggered (大多数) は `ability.limit?.kind==='turn'` false で従来通り (no-op、不変)。
- hirameki 経路 (handleEvidenceRemovedHook) の listen カードに limit 持ちは無し (D08013/19/24, D11003/09/12)。

## 防止策

behavioral test ([triggered-limit-guard.test.ts](../../tests/engine/listeners/triggered-limit-guard.test.ts)):
同ターン2回ガード→1回のみ発火 / counter reset 後に再発火。
