## 概要

`useEngineDispatch.ts` の `declaredAbility` ケースは:

```ts
case 'declaredAbility':
  if (action.cost && action.ctx) {
    engineCost.pay(draft, action.cost, action.ctx);
  }
  flow.useDeclaredAbility(draft, action.uid, action.abilId, action.ctx);
  return;
```

`action.cost && action.ctx` が **どちらも揃って渡されたとき限り** cost を支払う。
渡されない場合は **silent skip** され、effect だけが queue される。

`flow.useDeclaredAbility` のコメントには「cost 支払いは呼出元の responsibility」と明記されているが、
caller が忘れた場合の **safeguard / 警告は無い**。能力 def に `cost` が定義されていても、
ability.cost を読まずに dispatch すれば cost フリーで能力が走る。

## 再現

`B06069 a2` (declared + cost: sleepSelf):

```ts
await dispatchAction(page, { type: 'declaredAbility', uid: 'sno#1', abilId: 'a2' });
// → 効果 (sceneToHand) は queue + resolve、cost (sleepSelf) は **未払い**
// → B06069 は state: 'active' のまま (sleep 化されない)
```

これは engine-extensions-2026-06-05.spec.ts の B06069 e2e で観測され、当該 expect 行は
「sleepSelf コストの確認は declared-ability cost system の責務 — sceneToHand verb の検証範囲外」
とコメントして skip 済。

## 影響

- **本番 UI 経路では問題なし**: ActionsPanel 等は card def から cost を取得し action.cost に渡す
  (推定 — 未検証)
- **AI 経路では問題なし**: `src/ai/policy.ts:241-256` で ability.cost を engine.cards.get 経由で取得し
  `engine.cost.pay` を確実に呼ぶ
- **e2e / 直接 dispatch では cost が silent skip**: テスト書く側が cost+ctx を明示しないと
  cost フリーで効果が発火 → 「engine がカードルールを正しく実装している」検証の信頼性が下がる

## 解消 (2026-06-12 リファクタ Phase 2c)

2026-06-05 に Option A (warning log) を暫定導入後、Phase 2c で **Option B を構造化して採用**:

- 新設 `src/engine/flow/main/ability-activate.ts` (activateDeclaredAbility / activatePartnerAbility)
  が uid から ctx を構築し、def に cost があれば **必ず** engine.cost.pay → flow.useXxx を実行
- 呼出元 (UI / AI / e2e) の契約は `{type, uid, abilId, costParams?}` に縮小 —
  cost+ctx の caller 構築自体が廃止され、渡し忘れによる silent skip は構造的に不可能
- B06069 e2e に sleepSelf cost 支払いの実 assert を追加して green (解消の実証)
- 残課題: warning log `declaredAbility:cost-not-paid` は pay が costPaid を積む cost kind が
  flipFaceUpEvidence のみのため false-positive 化 (log 列は従来と不変)。後続フェーズで
  costPaid 全 kind マーク化 or 警告廃止を検討 (review-records.md §2c MINOR-2)

## 水平展開調査

- 同様の cost-bypass 可能性は他に無いか確認:
  - `useDeclaredAbility` 以外で `engine.cost.pay` を呼ぶ場所: AI policy のみ
  - `useEngineDispatch.ts` 内で cost が必要だが action 引数任意の他箇所:
    - `actionGuard` / `actionContact` (cost なし、確認不要)
    - `handUseCard` (event card 効果は内蔵、cost なし)
- → `declaredAbility` 固有問題

## 防止策

- e2e で declared ability を dispatch する際は ability.cost を読み込んで action に渡す
  ヘルパ `dispatchDeclaredWithCost(page, uid, abilId)` を導入し、cost 漏れの再発を防止
- engine 側に caller 責務違反検知 (Option A) を入れる
