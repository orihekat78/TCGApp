## 期待動作 (rules/03, rules/15)

「このキャラをスリープさせてもよい。そうした場合、〜」型カードで self が **スタン状態**の場合:
- rules/03: スタン状態のキャラが「スリープさせる」効果を受けても状態は **スタンのまま** (sleep 化しない)。
- よって「スリープさせた」= 成立せず → 「そうした場合」の後続効果は **発動しない** べき。

## 実動作

`optional{ chain[ sceneSetState{uid:'$self', state:'sleep'}, <後続> ] }` idiom で:
- self がスタン → `sceneSetState` は no-op (`mutate/scene.ts` がスタンを尊重、sleep 化しない)。
- だが `atom-handlers/scene.ts` の direct-uid 経路は **`chainStepNoApply` を立てない** → chain が break せず
  **後続効果 (B04092 なら AP+2000) が誤適用**される (「そうした場合」が実際にはスリープしていないのに成立)。
- カード側 `condition: not(charStateIs self sleep)` は **sleep のみ** gate し stun を通す。

## 関連ファイル

- `src/engine/effect/atom-handlers/scene.ts` (atomSceneSetState direct-uid 経路、chainStepNoApply 未設定)
- `src/engine/mutate/scene.ts` (setState がスタン尊重で no-op)
- `src/cards/ct-p04/B04092.ts` (wave-18 exemplar) / `src/cards/ct-p07/B07019.ts` (先行 shipped、同 idiom)

## RCA

self-sleep を「cost」ではなく「effect atom」で表現する idiom (triggered ability は宣言 cost を持てない) で、
sceneSetState の no-op が chain の front-step 失敗として伝播しない。cost 版 (`sleepSelf`) は canPay で
スタン/スリープを弾く (rules/21) が、effect 版にはその gate がない。

## 水平展開

`optional{chain[sceneSetState $self sleep, …]}` idiom の全カードが対象。要 grep:
`git grep -l "state: 'sleep'.*\$self\|uid: '\$self', state: 'sleep'" src/cards`。
B07019 / B04092 が既知。carrier は shipped B07019 で既に latent (本 wave で新規化せず)。

## 防止策 / 修正案

- **engine (推奨)**: atomSceneSetState の direct-uid 経路で、対象がスタンで sleep 化 no-op のとき
  `ctx.dyn.chainStepNoApply = true` を立てる (chain break → 「そうした場合」不成立)。family 横断で一括解消。
- **カード側 (暫定)**: `condition: charStateIs self active` (sleep/stun 両除外) に変更。ただし engine 修正が正道。

B07019 = 自ターン登場時)。bug budget 容認、engine touch-up wave で family 一括修正候補。
