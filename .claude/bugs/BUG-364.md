# B06068 keyword-loss temporal boundary

## Expected

- 解決時点で有効な`突撃[キャラ]`を由来に関係なくすべて失う。
- generic `突撃`は別キーワードとして維持する。
- 解決後に新しく得た`突撃`または`突撃[キャラ]`は有効になる。
- ターン終了時に境界情報を清掃し、継続付与を復元する。

## Actual

- `revokedKeywords`は印字と自身continuousだけを減算した。
- permanent/turn grantとface-up set riderは常に残った。
- effective keyword filterも印字キーワードを無条件で復活させた。
- 同値再付与や再revokeのmarker-only変化をcausal logが記録しなかった。

## Root cause and fix

- 「失う」を時間境界でなく由来別の除外として実装していた。
- revoke時に既存grantをpre-boundary化し、active set sourceのinstance IDを保存。
- 後発grant markerと新しいset instanceだけを許可し、再revokeで境界を更新。
- keyword reader、effective filter、causal projectionを同じ有効値へ統一。
- markerless旧saveは時系列復元不能のため現ターンfail-closed。

## Horizontal investigation

- production `charRevokeKeyword` callerはB06068のみ。
- readerの全keyword source、target filter、condition、UI/AI actionを確認。
- legacy set occurrenceは既存instance-ID正規化後にsnapshotする。
- generic token、both owners、base/P、decline、turn cleanupを回帰化。

## Prevention

- keyword lossはsource categoryでなくresolution boundaryとしてtestする。
- 新source追加時はpre/post boundaryとeffective-filter parityを確認する。
