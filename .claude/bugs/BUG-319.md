# choose-intercept複数コピー欠落

## 期待動作

同じCardDefの物理コピーが同時に条件を満たす場合、各コピーが独立して発火し、
所有者が解決順を選び、一件ずつ解決する。

## 実動作

`choose-intercept`は最初の一致だけを返す。B04003を2枚配置しても一件だけがpendingになり、
最初の支払い後は元のchooseを再開するため、二枚目の能力が現れない。

## RCA

`consult-choose-intercept`が単一matchを返し、再開時の`skipChooseIntercept`が残り候補を抑止する。
通常trigger batchと異なり、コピー別の候補・所有者順・継続状態を表現できない。

## 対応方針

専用のbatch continuationと公開順序schemaを設計する。B04003のQA判定は未適合のまま維持し、
B08081系とB02067系のcopy identityも横断検証する。

## 必須回帰

- B04003二枚で両UIDが同一batchへ入るRED test
- 所有者が逆順を選び、各支払い後に元のchooseへ一度だけ戻るpublic test
- B08081系とB02067系の既存単一コピー動作
