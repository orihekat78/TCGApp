# B02039 set-card proxy interception

## Expected

- B02039がset-cardを選ぶ処理では、hostキャラを選んだ扱いにしない。
- 選んだset-cardがB02067でも、そのhostの無効化能力は発動しない。
- 実際に相手キャラを選ぶ通常の`bindPick`ではB02067が発動する。
- human、CPU、save復元で同じ判定を行う。

## Actual

- B02039はset-card選択をhostの`bindPick`と後続のoccurrence選択で表現していた。
- 共通pick処理がhost proxyを通常のcharacter選択と誤認した。
- B02067のTurn1を消費してB02039のcontinuationをcancelし、set-card選択へ進まなかった。

## Root cause and fix

- pickには印字上のselection subjectを区別するauthorityがなかった。
- B02039のcanonical `bindPick`へ`selectionSubject:'set-card'`を付与した。
- marker単体は保存データから改ざん可能なため信用しない。
- live source、printed origin/index、登録済みCardDef、ability ID、canonical targetを毎回照合する。
- human `applyPickAndContinuation`とautonomous `resolveEffectPicks`が同じpredicateを使う。

## Horizontal investigation

- `setCardToEvidence`のhost proxyはB02039だけだった。
- unmarked character `bindPick`は従来どおりB02067を発動する。
- base/P、両owner、multi-target、continuation、Turn1、CPUを確認した。
- genuine cold restoreとforged/missing/unknown markerをfail-closedで確認した。

## Prevention

- persisted atom argsをrule authorityとして直接信用しない。
- humanとautonomousのpick interception判定を単一predicateに保つ。
- proxy選択には印字上のsubjectとcanonical descriptor照合を同梱する。
