## 概要

複数 option の `kind:'choice'` 効果は、**宣言能力** では `useActionsPanelFlow.ts:606` が
dispatch 前に choice modal を出し `ctx.dyn.choiceIndex` を供給する → engine が選択 option へ unwrap する。

しかし **enter トリガ** (handUseCard 経由) の choice は:
- `runHandUseFlow` (useActionsPanelFlow.ts:762) は確認モーダル後 `handUseCard` を dispatch するだけで
  enter 効果の choice を **surface しない**。
- engine は choice で **pause せず** `resolver.ts` / `resolve-picks.ts:434` が
  `choiceIndex` 未指定時に **option 0 に既定化** する。

→ 結果、enter トリガの複数択 choice は **常に option 0 が自動実行** され、human は選べない。

## 影響カード (2 枚)

- **B06007 / B06007P 灰原哀**: 【パートナー青】【登場時】3 択
  (① 突撃付与 / ② 相手 lv≤7 を bounce / ③ 2 ドロー)。
  実機では常に ① 突撃付与 が適用され、②③ を選べない (audit-suspects-coverage spec で確認)。

## 修正 (案B engine pause、user 承認で実装、additive)

pick (pendingEffectPick) と完全同型の `pendingEffectChoice` 機構を新設し、engine が human の複数 option
choice で pause → UI modal → `choiceResolve` dispatch で解決する汎用機構を追加した。

- **engine pause** (`resolve-picks.ts` choice case): `opts.humanChooser===true && options.length>1 &&
  chooser!=='opp'` のとき pushPendingEffectChoiceSide + 空 effect (no-op parallel) を return し
  option 0 既定化を防ぐ。choiceIndex 指定済 (declared) / humanChooser=false (AI) / 単一 option は無傷。
- **side-channel** (`resolve-picks.ts`): `__pendingEffectChoiceSide` + `PendingEffectChoiceSide`
  ({player, source:{cardId,abilityId,uid}, options:[{index,verb,args}]}) を pick と 1:1 で新設。
- **再開** (`apply-pick.ts applyChoiceAndContinuation`): readDef から元 effect 復元 → choiceIndex 付き
  再 walk → unwrap → event.queue。選択 option 内の $pick (option② sceneToHand) は既存 pick queue に
  再 push され effectPickResolve で連鎖消化。
- **UI**: store.pendingEffectChoice + `choiceResolve` action (useEngineDispatch) +
  `EffectChoiceModalHost` (ChoicePickerModal 再利用) + useEffectPickFlowDriver の AI fallback。
