## 概要

複数 option の `kind:'choice'` 効果は、**宣言能力** では `useActionsPanelFlow.ts:606` が
dispatch 前に choice modal を出し `ctx.dyn.choiceIndex` を供給する → engine が選択 option へ unwrap する。

しかし **enter トリガ** (handUseCard 経由) の choice は:
- `runHandUseFlow` (useActionsPanelFlow.ts:762) は確認モーダル後 `handUseCard` を dispatch するだけで
  enter 効果の choice を **surface しない**。
- engine は choice で **pause せず** `resolver.ts` / `resolve-picks.ts:434` が
  `choiceIndex` 未指定時に **option 0 に既定化** する。

→ 結果、enter トリガの複数択 choice は **常に option 0 が自動実行** され、human は選べない。

## 影響カード (2 枚)

- **B06007 / B06007P 灰原哀**: 【パートナー青】【登場時】3 択
  (① 突撃付与 / ② 相手 lv≤7 を bounce / ③ 2 ドロー)。
  実機では常に ① 突撃付与 が適用され、②③ を選べない (audit-suspects-coverage spec で確認)。

### 影響しないもの (誤検出回避のため明記)
- 単一 option の choice (B02046 / B04071 等) — sequence/atom を包む構造的用途。option 0 自動解決が **正**。
- declared 能力の choice (D11014 a2 / B02040 a2 / B04005 a2 等) — useActionsPanelFlow:606 で surface 済。
- 【ヒラメキ】(evidence:remove-by-action, optional) の choice (D08019 / D11009 / B06070 等) — 別 driver。
- MVP デッキ (CT-D08/D11) の choice カードは全て上記いずれかで **未影響**。

## 修正方針 (未着手・要方針確認)

enter (および将来の action 等) トリガの複数択 choice を human に選ばせるには、宣言能力と同等に
choice modal を surface する必要がある。候補:

- **案A (UI 先行解決)**: `runHandUseFlow` がキャラ登場前にカードの enter 能力を walk し、
  複数 option choice があれば `useChoicePicker().ask()` → `handUseCard` の dispatch に
  `ctx.dyn.choiceIndex` を渡す。`handUseCard` action / dispatch contract に ctx を追加する必要あり。
- **案B (engine pause)**: engine が human の複数 option choice で pause し `pendingEffectChoice` を
  surface、UI driver (useEffectPickFlowDriver 類似) + `choiceResolve` dispatch で解決。
  汎用的だが engine flow + state + UI に跨る大きめの変更。

影響が B06007/P の 2 枚と狭く、dispatch contract / engine flow に触れるため、着手前に方針を確定する。

## 防止策

triggered (非 declared) の複数 option choice カードを追加する際は、UI surface 経路の有無を必ず実機確認する。
card-addition-checklist に「複数択 choice は宣言/enter/その他トリガ別に surface 経路を確認」を追記候補。
