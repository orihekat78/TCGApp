(必要証拠数 - 1) で自分が劣勢のとき、相手の証拠を削る case attack が

## RCA

Phase 6 Group B での heuristic 設計時、reasoning が「常に LP > 0 で安全な手」
という前提でハードコーディングされていた。実際は局面によっては case attack
の方が証拠差分が高い (+1 自 / -1 相手 = 差分 +2)。設計時にこの観点での
スコア比較ロジックが入っていなかった。

## 試行錯誤の記録

実装中、複数の threshold を試して smoke で turn 数と timeout を測定:

| threshold | turn avg | timeouts | 理由 |
|-----------|----------|----------|------|
| 常に case attack 優先 (score=2 vs LP) | 135.5 | 641 | 双方 AI が攻防戦に陥り stall |
| oppEvidence ≥ ⌈req/2⌉ | 94.8 | 424 | 中盤から発動して同じく stall |
| oppEvidence ≥ req-1 | 53.4 | 208 | 後期発動だが catch-up しきれず stall |
| **oppEvidence ≥ req-1 ∧ selfEvidence < oppEvidence** | **11.19** | **0** | ✅ **採用** |

最終 threshold は「相手があと 1 で勝つ ∧ 自分が劣勢」という劣勢時のみの
disruption play。優勢時はレースで勝ち切る方が効率的。

## 修正

```diff
+ // reasoning vs actionAgainstCase スコア比較

+ // case attack を候補に。それ以外は reasoning 優先。
+ const bestReasoning = ...;
+ const bestCaseAttack = oppCriticalWin && selfBehind ? scoreCaseAttack() : null;
+ if (bestReasoning && bestCaseAttack) {
+   return bestReasoning.lp >= bestCaseAttack.score ? bestReasoning.m : bestCaseAttack.m;
+ }
+ if (bestReasoning) return bestReasoning.m;
+ if (bestCaseAttack) return bestCaseAttack.m;
```
