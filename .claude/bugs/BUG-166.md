## 期待動作

通常イベント/ヒラメキの効果解決中、そのカードは refresh のシャッフル対象に含まない。
カットインはリムーブエリア上で解決するため対象に含む。

## 実動作

engine は通常イベント/ヒラメキを効果完了前に `remove` へ移す。
そのまま refresh を行うと解決中の自身も deck へ混入する。B07060 deck 0 draw が実到達例。

## RCA

簡略ライフサイクルと rules/26 の乖離。初回修正 `46d7b73d` は
`CardDef.kind === 'event'` を「解決中」と推測したため、カットインと無関係な event source も除外する過修正になった。
同 ID 複数時の `indexOf` も解決中でない既存枚を残し得た。

## 修正方針

- source に `resolutionKind: normal-event | hirameki | cutin` を明示。
- refresh 除外は `normal-event` / `hirameki` のみ。
- writer → event normalize → stack entry → `EffectCtx` → human decision resume へ伝播。
- 同 ID は後積みの解決中枚を保持。

## 水平調査

- hand-use / Next Hint / B07060、ヒラメキ UI resolve、contact cut-in。
- 第三者誘発は使用カードの marker を継承させない。
- pick / choice / optional / continuation の全中断境界。

## 再発防止

- normal event / hirameki / cutin / unrelated source の四分類を実経路と単体の両方で固定。
- deck 0、remove 1、同 ID 複数、human pause/resume 後の refresh を必須回帰とする。
