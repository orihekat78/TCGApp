## 期待動作 (rules/26)

イベント / ヒラメキの効果を解決している間、そのカードは **まだリムーブエリアに置かれていない** 扱い
(リフレッシュのシャッフル対象に **含まれない**)。B07060 (deck 0 で使用) の場合:
step1 draw → refresh (remove のみ shuffle、B07060 自身は対象外) → … → 末尾 toPartnerArea で **PA に到達**。

## 実動作 (engine 簡略化)

engine は event を使用時に即 `mutate.remove.add` (hand-use-card.ts / next-hint.ts)、証拠も
`evidence.removeTop` で hook emit 前に remove へ push する。そのため解決中に refresh が起きると
**解決中の自身も shuffle で deck に混入** → 末尾 toPartnerArea が lastIndexOf=-1 で graceful no-op →
カードは PA でなく deck (場合により draw で手札) に残る。crash / 不正状態は無し。

- 到達可能例: **B07060** a1 = draw が先行し deck0 で refresh を誘発 → 自身巻き込み。
  B07059 / PR195 の a1 は refresh 誘発 atom を含まず非到達。selfToEvidence (PR085 系) も同モデルの潜在。
- 現状挙動は `tests/cards/engine-wave12-partner-area-cards.test.ts` §F2 で **pin 済** (挙動変化検知用)。

## RCA

「使用済/リムーブ済カードを即 remove へ置き、self 系 verb が後から splice で拾う」モデル
(selfToEvidence 由来、toPartnerArea も踏襲) と rules/26 の「解決中は remove に無い」の恒常的乖離。
今回 G39 で「解決中に refresh を誘発しつつ末尾で自身を参照する」カード (B07060) が初めて出荷され
到達可能になった。

## 修正方針 (未着手)

resolving-card の隔離 (解決中カードを remove と別の transient slot に置く or refresh shuffle から除外
する marker) = **engine-wide 骨格変更 (T3)**。影響面が広い (refresh / selfToEvidence / hirameki 全経路)
ため専用 wave で設計から。優先度 低 (デッキ 0 で当該イベントを使う極端エッジのみ・graceful)。

## 水平展開

- selfToEvidence (PR085/PR091): 同モデルだが a1/a2 に refresh 誘発 atom が無く現状非到達。
- ヒラメキ解決中の refresh (rules/26 §シャッフル対象): 同乖離が既存。ヒラメキ effect に
  draw/mill を含む出荷カードが将来増えると到達面が広がる — 新規ヒラメキ카드 certify 時に確認。

## 防止策

- wave-12 で F2 pinning test 追加済 (挙動が変わったら検知)。
- → enforcement: 新規「self 系 verb + refresh 誘発 atom 同居」カードの certify で本 BUG を必ず参照。
