## 期待動作

rules/07 + rules/11:
- 推理 / アクション 実行で actor (scene キャラ / partner) が **スリープ状態** になる
- UI: scene card が縦 → 横 (rotate -90deg) に回転表示

## 実動作

- engine 層: `mutate.scene.setState(state, uid, 'sleep')` で state が正しく 'sleep' に変わる
- DOM 層: `<div class="card color-yellow sleep">` で `.sleep` class が付与される
- **しかし computed style: `transform: matrix(1, 0, 0, 1, 0, 0)` (identity matrix、回転無し)**

→ CSS rotate(-90deg) が **全く適用されていない**ように見える。

## 関連ファイル

- `src/ui/components/SceneArea.css:128` (修正対象)
- `src/ui/components/SceneArea.css:247-258` (.card.sleep / .card.stun rule)
- `src/ui/components/SceneArea.css:367-371` (`@keyframes scene-card-enter`)

## RCA (Root Cause Analysis)

`src/ui/components/SceneArea.css:128`:

```css
.scene-area .card {
  animation: scene-card-enter 280ms ease-out both;  /* ← `both` が原因 */
  ...
}
```

`@keyframes scene-card-enter` の **100% (final) フレームに `transform: translateY(0) scale(1)`** が定義されている。

`animation-fill-mode: both` は `backwards + forwards` を意味し、特に `forwards` が
animation 終了後も 100% フレームの style を保持する。CSS 仕様では
**animation の computed value は元の base style より優先される**ため、
後から付与される `.card.sleep { transform: rotate(-90deg) }` が **animation 100% に上書きされて無効化**。

確認 (Playwright + chromium dev tools 経由):
- `getAnimations()` で `name: scene-card-enter`, `playState: finished`, `currentTime: 280` を確認
- 完了済 animation がまだ transform を lock していた

## 水平展開

- **PartnerArea.css**: `.card.sleep { transform: rotate(-90deg) }` あり、ただし `animation: scene-card-enter` 系の lock 無し (candidate-pulse は box-shadow のみ) → 影響なし
- **FileArea / HandZone / RemoveArea / LogPanel 等**: `animation: ... both` 使用するが `.sleep` 状態の対象でないため影響なし
- **CaseArea (case-stamp-flip)**: `transform: rotate(...)` を 100% で設定するが、対象は事件カードのみで状態遷移なし → 影響なし

→ SceneArea のみが影響

## 修正

`src/ui/components/SceneArea.css:128`:

```css
animation: scene-card-enter 280ms ease-out backwards;
```

`both` → `backwards` に変更。これで:
- 0% フレームの style は animation 開始前 (delay 中) のみ適用 (delay 無しなので実質影響なし)
- **100% フレームの style は animation 終了後保持しない** → base style (.card.sleep 等) が transform を制御

mount 直後の enter 効果はそのまま、終了後の state 遷移は正しく反映。

## 検証

Playwright dev サーバで実機確認 (修正後):

- opp-2 (元から sleep): `transform: matrix(0, -1, 1, 0, 0, 0)` = `rotate(-90deg)` ✅
- opp-3 (stun): `transform: matrix(-1, 0, 0, -1, 0, 0)` = `rotate(180deg)` ✅
- self-3 (reasoning 後): engineState='sleep', domClass='card color-yellow sleep', transform=`rotate(-90deg)` ✅

unit / E2E / smoke 全緑 (既存 BUG-029 regression test は dispatch chain のみで computed style 検証なし、本 BUG は補完)。

## 防止策

- CSS animation で transform を扱う場合、`animation-fill-mode: both` は **状態遷移系 class
  (.sleep / .stun 等) の transform を上書きするリスク**があるため避ける
- `backwards` (delay 中のみ) または明示的に fill-mode 無し (default `none`) を選ぶ
- 新規 scene card 系 CSS では同じ pattern にしない (LinterRule 候補)
