## 概要

`resolveActionAgainstCase` (`src/ai/action-resolution.ts`) はアクション[事件] で常に `passGuard` を呼ぶ。
公式: rules/07-08 ではアクション[事件] も **ガード可能** (相手が現場のアクティブキャラ1枚でガード)。
human 経路 (useEngineDispatch の per-step) は guard 窓に対応済だが、CPU 攻撃側 driver の経路は passGuard 固定。

結果、AI-vs-AI / human が CPU にアクション[事件] される場面で、CPU 防御側がガードを選べない。
ブレット付与 (B01068/B02068) の「ガード不能化」が AI-vs-AI では観測上無意味になる副作用もある。

## 影響範囲

- AI 防御側のアクション[事件] ガード判断全般。smoke は両者 AI のため勝率に影響し得るが、
  cluster3 では本件を **修正せず** (BUG-141 の declare-drain のみ case 経路に追加) → smoke baseline byte 一致。
- cluster3 のブレット系 (B01068/B02068) は human 戦では正しく機能する (human 防御側はガード可)。

## 期待動作 / 実動作

- 期待: アクション[事件] 宣言 → 防御側 chooseGuard (候補があれば) → ガード or 証拠処理
- 実動作: 常に passGuard → 必ず証拠処理へ

## 修正内容 (2026-06-15 修正済)

- `src/ai/action-resolution.ts resolveActionAgainstCase` に `defenderPolicy?` 引数を追加し
  `defenderPolicy.chooseGuard` 委譲を実装 (char 経路 `resolveActionAgainstChar` と同型)。
  ガード成立時は `snapshotAP → judge` (攻撃 vs ガード、証拠変動なし)、不成立時のみ rules/10 の
  `removeOpponentEvidenceTop + gainSelfEvidence`。これは human 経路 `useEngineDispatch` の actionJudge 分岐
  (`case && !guardUid` → 証拠操作 / else → AP判定、user_request 20260522_01 #8 で確定済) と同型。
  宣言時 trigger の drain は `attackerPolicy` で従来挙動を維持 (drift を guard 窓に限定)。
- 呼出元: `src/ai/policy.ts` (applyMove) のみ `new HeuristicPolicy()` を渡す (= AI-vs-AI gameplay / smoke の
  guard 窓。baseline drift の出所はここ)。
- **follow-up 修正 (同セッション、playwright 回帰で発見)**: `useEngineDispatch.ts` の bundled `actionAgainstCase`
  にも当初 `HeuristicPolicy` を渡したが、この bundled 経路は **hirameki demo** (App.tsx: opp→self の case で
  evidence 除去→相手の【ヒラメキ】発火) と e2e 専用で、防御側を auto-guard すると evidence が除去されず
  demo / e2e (8 hirameki spec) が壊れた → **passGuard 固定に revert**。実ゲームの防御ガード窓は別経路で対応済:
  人間/CPU の case アクションは per-step (`useActionsPanelFlow`→`actionDeclareCase`) + `useContactFlowDriver`
  (opp 防御=HeuristicPolicy / self=GuardPickerModal) が解決 (BUG-144 前から)。よって BUG-144 本体の修正範囲は
  `resolveActionAgainstCase` + `policy.applyMove` のみで十分だった。
- 注: FSM contact-pending は case のため cutin フェーズを省略し judge へ直行する (既存挙動、parity 維持。
  guarded case-action の cutin 対応は別 scope)。
- 検証: `tests/ai/policy.action-guard.test.ts` に case-guard / case-passGuard テスト追加 (red→green)。
  full vitest 2109 pass、smoke:1000 で期待 drift (avg 10.86→11.00、winsA 469→498、timeouts/exceptions=0)
  を確認し `smoke-baseline.json` を re-baseline。
