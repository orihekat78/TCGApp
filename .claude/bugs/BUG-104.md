## 仕様 (D11013 公式テキスト、rules/09)
D11013 a1 カットイン: コンタクト中のこのカット元キャラを AP+1000。コンタクト相手が[警察]なら1ドロー。
D11013 は【自分ターン中】制限が無いため防御側 (相手ターン) でもカットイン可能。

## 実動作 (バグ)
1. **ctx.contact 未設定**: D11013 a1 の custom check は `ctx.contact?.targetUid` を読むが、entryToCtx
   (resolve/stack.ts) が ctx.contact を設定しないため常に false → **警察1ドローが永久不発**。
2. **byUid 攻撃者固定**: cutin binding (flow/contact.ts) が `byUid: ax.byUid` (常に攻撃者) を詰めるため、
   防御側カットインで AP+1000 が**自分(防御)でなく相手(攻撃)キャラ**に乗る。

## 修正
- **flow/contact.ts cutIn binding**: `byUid: contactCharUidOf(ax, p)` (カットイン側 p のコンタクト中キャラ)、
  `targetUid: contactCharUidOf(ax, opp(p))` (相手)、`attackerSide: ax.byPlayer` を追加。
  攻撃側カットイン (p===byPlayer) では byUid=ax.byUid で不変 (回帰なし)。
- **resolve/stack.ts entryToCtx**: bindings.contact[0] から `ctx.contact` を展開 (byUid/targetUid/guardUid/attackerSide)。
  D11013 custom check が ctx.contact.targetUid で警察判定可能に。

## 水平展開
- $contact.byUid を使う他カットイン (D08007/15/17/23, D11017/18/19) は攻撃側カットインで byUid 不変
  (contactCharUidOf(ax, byPlayer)=ax.byUid)。cutin e2e 8件 PASS で確認。targetUid を使うのは D11013 のみ。
- ctx.contact 読取は dyn/eval.ts ($contact dyn) と D11013 custom のみ。cutin の $contact.byUid は
  resolveBindRef (ctx.bindings) 経由なので ctx.contact 追加の影響なし。

## 検証
tsc / vitest 1675 (behavioral: 防御側カットインで防御キャラ AP+1000 + 警察攻撃者で deck-1 ドロー、
攻撃キャラ不変) / smoke 1000 例外0 (500/500) / cutin e2e 8件 PASS (攻撃側不変) / empirical 確認
(AP 1000→2000 on 防御, draw 発火, 攻撃 8000 不変)。
