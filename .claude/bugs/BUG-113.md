## 仕様
ターゲット/条件の数値フィルタ (`apMin/apMax/lpMin/lpMax`) は「効果解決時点の有効値」を参照すべき
(rules/15,19,22)。有効値 = `(override?printed) + turnEffects±修正 + continuousDelta(継続効果 dyn)`。

## 実動作
Task 2 で `matchOneFilter` (target/candidates.ts) を turnEffects ±修正込みの有効値判定に修正したが、
`continuousDelta` (read/char.ts の dyn 集計、`continuousModifier.apDelta/lpDelta`) は **import cycle 回避**
のため inline 集計から **除外**。read.char.ap/lp (display 等) は continuousDelta を含むため、継続効果を持つ
キャラでは **filter と display で AP/LP がずれる**残差がある。

### 現状の影響: 軽微
- `continuousModifier.apDelta` を engine 配線で持つカードは **D08005 (灰原哀, evidence-per-AP)** のみ (BUG-095)。
- 灰原哀が「APX以下」リムーブ等の対象になり、かつ証拠数で AP がしきい値をまたぐ場合のみ不整合。稀。

## 恒久対応案 (DEFERRED)
- `read/char.ts` の AP/LP セレクタを cycle 無しに切り出し (continuousDelta も含む純粋関数)、
  candidates.ts から共有する。または candidates.ts に continuousDelta 相当を cycle-safe に inline 化。
- cond/eval ↔ candidates ↔ read.char の依存関係を整理してから行う (cycle に注意)。

## 検証
effective-value-filter.test.ts は turnEffects ±修正分を検証済。continuousDelta 分は本 BUG で別管理。
