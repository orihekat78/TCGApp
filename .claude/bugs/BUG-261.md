## Expected

An invalid Hirameki can still be activated but has no text effect. A character's
printed conditional keyword is recognised outside the scene only while its icon
condition is met.

## Actual

The optional Hirameki listener dropped a failed ability condition before the
player could activate it. Off-scene target filtering used only static keywords,
so it omitted printed conditional keyword abilities.

## Evidence

- Official rule manual Ver.2.5 pp.21 and 25.
- Regression: `tests/engine/rule-manual-ver2.5.test.ts`.

## RCA

The shared triggered listener treated every condition failure as a trigger
failure. The candidate filter had no state-aware fallback when no scene UID was
available.

## Fix

`PendingHirameki.effectValid?` preserves the legal activation surface and
suppresses only its text resolution. The effective-keyword reader now evaluates
explicitly marked printed icon-condition keywords with the candidate owner and
area; text and external grants remain excluded off-scene.

## Horizontal investigation

Verified shared optional-icon handling in `triggered.ts`, resolution in
`useEngineDispatch.ts`, scene/hand filtering in `candidates.ts`, deck reveal
predicates, bound conditions, and PA-MR printed ability suppression.

## Prevention

Keep a real dispatch-path test for invalid optional icons and a valid/invalid
off-scene keyword target pair whenever a manual revision changes validity rules.
