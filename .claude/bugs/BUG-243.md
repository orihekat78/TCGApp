## Expected behavior

Repeated public cards have distinct selection and detail accessible names, without exposing instance IDs. Unique cards stay free of ordinal noise.

## Actual behavior

`SelectableCardTile` and public `CardListModal` entries named buttons from the card display name only, so duplicate physical occurrences were indistinguishable.

## RCA

Internal occurrence identity was preserved in keys/test IDs and callbacks, but never mapped to a user-facing assistive-technology occurrence label.

## Horizontal investigation

All `SelectableCardTile` consumers were checked: hand discard, guard, deck reorder/place, set-card replacement, and Souza reorder can render public duplicates. Hidden set-card choices already receive safe visible ordinals. `CardListModal` public face-up cards, including revealed evidence details, require the same distinction.

## Prevention

Use public card occurrence order such as `1枚目`/`2枚目` only when a rendered public card ID repeats. Pass that label to both primary and detail names; never derive it from or expose an internal instance ID.
