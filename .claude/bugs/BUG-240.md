## User report

At the formal mobile landscape viewport (Pixel 5, 851x393), the visible
CardListModal close button cannot be clicked while SpectatorHUD is displayed.

## Expected behavior

Modal close controls and backdrops receive pointer input above non-modal HUD
surfaces. Actual HUD buttons remain usable.

## Actual behavior

The HUD's empty section is the hit-test target over the CardListModal close
button. Playwright reports `.spectator-hud-section` intercepting the click.

## Related files

- `src/ui/components/SpectatorHUD.css`
- `src/ui/components/CardListModal.css`
- `tests/e2e/user-bug-wave-ui.spec.ts`

## RCA (Root Cause Analysis)

SpectatorHUD is fixed at z-index 9100, while CardListModal is z-index 1500.
Its click-through rule was limited to `@media (max-width: 640px)`. Landscape
Pixel 5 is 851px wide, so the desktop `pointer-events: auto` HUD section won
the hit test over the modal close.

## Fix

Apply the existing control-only pointer-event pattern at the base HUD rules:
the HUD, sections, and button rail pass through, and only actual buttons opt
back in. This also prevents the rail's 2px flex gaps and scrollbar box from
capturing modal input.

## Horizontal investigation

Checked other non-modal overlays: RecentActionToast, OppTurnOverlay,
RefreshOverlay, TutorialOverlay, and EffectStackPanel. Their non-interactive
surfaces already use pointer pass-through with interactive children opting in.
CardExpandModal already outranks the HUD; this bug was specific to the older
CardListModal z-index.

## Verification

- RED: focused Pixel 5 landscape `elementFromPoint` assertion returned false.
- GREEN: actual close click (no force), HUD pause control, a real close moved
  to a measured HUD button-gap coordinate, and console-zero assertion pass at
  851x393.
- Existing desktop and mobile browsing regression pass after the fix.

## Prevention

For every fixed HUD or notification surface above ordinary modal layers, set
the container and every layout-only wrapper to pointer pass-through. Re-enable
pointer input only on named interactive controls, and test the real viewport
coordinate plus flex gaps when layers overlap.
