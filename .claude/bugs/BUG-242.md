## ユーザー報告

伏せられたセットカードを選ぶ modal が文字だけを表示する。重複した物理カードは同じ accessible name になり、裏面として認識できない。

## 期待する状態

各非公開候補は実際に読み込まれた汎用カード裏面を表示する。カード ID・名前・画像 URL を漏らさず、ordinal を含む個別の button 名で keyboard 選択でき、`instanceId` をそのまま解決 payload に渡す。

## 実際の状態（修正前）

`SelectableCardTile` の hidden 分岐は `hiddenLabel` の text だけを描画し、ARIA は全候補で `伏せられたカードを選択` だった。

## RCA

セットカード host は identity 漏えい防止のため hidden tile を正しく渡していたが、tile の hidden renderer が公開カード用の `CardArt` パターンから外れていた。さらに generic ARIA 文言を ordinal で派生させなかったため、同一カードの物理 occurrence を assistive technology で区別できなかった。

## 対応

hidden tile でも `CardArt(null)` を使い、既存の data URI fallback を汎用カード裏面として描画する。画像は `aria-hidden`、`alt=""` とし、`hiddenLabel` を `aria-label` に含める。selection callback は既存どおり `instanceId` のみ渡す。

## 水平調査

- `EffectPickerModal` の伏せた evidence は既に `CardArt(null)` と detail 非表示を使う。
- `FileArea` / `EvidenceArea` は CSS の裏面スタックであり、選択 button や private card payload を持たないため対象外。
- face-up の decision tile は名前・ID・detail を出す既存仕様を保持する。

## 再発防止

hidden selectable tile の unit test で loaded back source、private metadata 非漏えい、ordinal ARIA、instanceId 選択を固定する。851x393 Playwright で keyboard 選択、画像 load、console 0 を確認する。

## 検証

- RED: hidden image 不在と duplicate ARIA の focused unit 3 failure を確認。
- GREEN: focused unit 13 pass、desktop/mobile Playwright 2 pass。
- E2E は実際の B02039 解決で、現場の character `B02040`（黒羽盗一）による絆を満たす。同一 `D08003` の beta を表向き evidence に移し、alpha だけを伏せた set card として残す。mobile は実 touch context の tap を使う。
