## 完了項目

### 1. 新規 listener: `src/engine/listeners/triggered.ts`

- 7 hook (`enter` / `effect:declared` / `action:declare` / `action:guarded` / `contact:start` / `case:to-resolved` / `phase:end:start`) 用の汎用 listener
- `collectCardsInPlay()` で scene + partner-area + case + hand の全カードを scan
- 各カードの ability で `type === 'triggered'` かつ `trigger.hook === hookName` をフィルタ
- `scope` (on-scene / on-partner-area / on-hand / on-evidence / always) で発火可否判定
- `trigger.selfOnly` で「自分のキャラに対する発火のみ」絞り込み
  - scene/partner/case: source.uid === card.uid
  - hand: payload.cardId === card.cardId (event card 自身の使用検知)
- `trigger.matcher` で カード側の custom 条件チェック
- 合格分を `event.queue` で pendingEffects へ push

### 3. emit payload kind 分離 (`hand-use-card.ts` / `next-hint.ts`)

`eventRemoveByAP` (cards/_shared) 等の matcher が `kind === 'event-use'` を期待する契約に従い:

| 旧 emit | 新 emit |
|---------|---------|
| `{ kind: 'handUseCard', cardId }` | `{ kind: 'event-use' \| 'character-use', cardId }` |
| `{ kind: 'nextHintCardUse', cardId }` | 同上 |

カード kind に応じて自動分離。

## 設計上の判断

1. **汎用 listener 1 つで 7 hook を扱う**: 各 hook ごとに専用 listener を作るより保守容易。scope/selfOnly/matcher の共通ロジック流用可。
2. **hand area も scan 対象に含めた**: event card は使用時にまだ hand にあり、`scope: 'on-hand'` の triggered ability (eventRemoveByAP) を発火させるため。selfOnly のチェックは payload.cardId 一致で判定。
3. **hirameki / misread は touch しない**: icon-flash / icon-misread は別系統 (UI 側 dispatch resolve)、本 listener は `type === 'triggered'` (条件発動) のみ扱う。

## 水平展開で発見した波及問題と対応

- **emit payload kind**: 旧 `'handUseCard'` / `'nextHintCardUse'` は generic で eventRemoveByAP matcher と整合しなかった → kind 別に分離
- **既存テスト**: 旧 kind 期待を新 kind に更新 (2 test 件)
- **AI move enumerator の `kind: 'handUseCard'`**: これは Move type の kind であり emit payload kind とは別物、変更不要
