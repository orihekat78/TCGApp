## メタ判断: createPortal 採用の発見と修正

### 発見

初期実装で `TutorialHighlight` を `TutorialOverlay` の子として render したところ、Playwright 実機検証で **highlight が target から 1090px ズレて** 表示されることが判明 (target top=64 / highlight top=1154 / 同一座標系想定だが食い違い)。

### 原因

`TutorialOverlay.css` に `animation: tutorial-slide-up 280ms ease-out both` があり、`@keyframes` の `to { transform: translateY(0) }` で `both` 指定により animation 終了後も `transform` 効果が維持される。CSS spec により **transformed ancestor を持つ position: fixed 子要素は、その ancestor を containing block とする** (viewport ではなく)。

### 解決

`React.createPortal(<>...</>, document.body)` で `TutorialHighlight` を `document.body` 直下に portal render。親 (TutorialOverlay) の transform 影響を受けず、viewport 基準の fixed positioning が正しく機能。

Playwright 再検証で target rect と highlight rect が完全一致 (top=64 / left=1712 / w=200 / h=1008 で actionsPanelRect と同一)。

### 水平展開メモ

他の overlay (CardListModal, GameSetupModal 等) は内側に `position: fixed` 子要素を持たないため、同じ問題には到達していない。今後 transform ancestor 配下に fixed 子要素を置く場合は portal を検討する。

## エッジケース対応 (CLAUDE.md §設計レビュー §エッジケース)

| ケース | 動作 |
|--------|------|
