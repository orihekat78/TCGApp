# 2026-05-18-8 — Round 4c BUG-006 修正 + Playwright E2E 導入

## 概要

ユーザ実プレイで報告されていた重大バグ **BUG-006「アクション[事件] で証拠が変動しない」** の根本原因を実機で再現・特定し、最小修正で解決。同時に React reactivity 系バグを今後 CI で検出するための **`@playwright/test` 実機 E2E 基盤** を導入。

## 達成

### BUG-006 解決

- 根本原因 (確定): `src/ui/state/store.ts:78-82` の `dispatch` で、`state-machine.advance()` が `contact-pending → judge` (case shortcut) で GameState を一切 mutate しないケースがあり、Immer `produce` が同一参照を返す → Zustand `setState` で subscribers 起動せず → `useContactFlowDriver` の useEffect が再 run しない → `judge` phase で永遠に停止 → `actionJudge` 発火せず evidence 不変動。
- 修正: `dispatch` で `Object.is(next, current)` なら `{ ...current }` で shallow copy を強制し、常に新参照を保証。
- 影響範囲: `src/ui/state/store.ts` のみ (UI dispatch wrapper、骨格凍結原則は engine 対象なので非抵触)。

## 教訓

- **dispatch chain が単体テストで pass しても React reactivity が動くとは限らない** — driver 系 hook は Zustand subscriber に依存し、Zustand は `Object.is` 比較で fire 判定する。Immer produce は draft 未変更で同一参照を返すため、module-level state (ax.phase) のみ変える dispatch は subscriber を起こさない。
- **実機 E2E (real browser) は React fiber 込みのテストとして単体テストでは捉えられないバグを検出する** — Vitest jsdom は概ね十分だが、`useEffect` のタイミング・依存配列の挙動は実機の方が厳密。
- **「dispatch 配線は存在する」と「dispatch が driver から発火する」は別レイヤーの保証** — 統合テストと E2E は責務が異なる。
