## メタ原因 (なぜ Round 2 で 18 件発見されたか)

1. **smoke 偏重テスト戦略**: CPU-vs-CPU smoke (1000 戦) は engine 健全性を担保するが、
   Human-vs-CPU の UI 経路を一度も触らない。ユーザが実機でプレイして初めて発覚。
2. **段階開発の前提変更**: Phase 4 で追加した `decideFirstPlayer` 概念を Phase 7 の
   TopBar 実装が反映していなかった (静的 mapping)。同様に Phase 5 で追加した
   `canMulligan`/`mulligan` API が Phase 8 で UI 化されないまま放置された。
3. **memory.md ✅ 誤判定**: 「Phase 9a-1 L0 実装済」と memory に記録されていた
   チュートリアルは scaffold UI のみで、`useStore.getState()` の hook 非配線により
   「次へ」が機能していなかった。状態管理の挙動を実機で触らないと検出不能なバグ。
4. **共通パターンの分散**: UID 表示は 5 箇所、エリア onClick は 3 箇所など、
   類似コードが分散しており 1 箇所の修正で水平展開が必要だった。
