## Phase 2: spec ts 作成 → BUG-034 検出

初版は 7 test 構成 (各カード shape/fire/skip + negative) で 289 LOC 作成。実装後 dispatch path で `pendingHirameki` が null のまま (4 件 fail)。

### 詳細デバッグ (発見)

E2E 用 debug spec で:
1. `__game.event.emit('evidence:remove-by-action', payload)` 直接呼び出し → listener fire + side-channel populate **成功** (DRAINED で値取得)
2. `__game.dispatch({type:'actionAgainstCase', ...})` → 証拠リムーブは成功するが side-channel に値が来ない (POST-DISPATCH DRAIN: null)

→ `_pendingHiramekiSideChannel` の **module instance 分離疑い**:
- `engine/index.ts`: `'./listeners/hirameki.js'` → Module C で listener 登録
- `useEngineDispatch.ts`: `'@/engine/listeners/hirameki.js'` → Module D で drain
- vite dev mode の `.js` + alias resolve 差で **別 instance** 生成、side-channel が共有されない

`useEngineDispatch.ts` の import path を `'../../engine/listeners/hirameki.js'` に変更しても同症状 → dev server 再起動なしの HMR では効果不明 (kill PID 5756 は sandbox で denied)。

### 対応方針

production code 変更を **すべて revert**、spec を **shape verification のみ** (3 tests) に縮小。BUG-034 として登録、Round 4j-fix で:
1. global state 使用または engine namespace re-export で module-instance 問題回避
2. spec を 7 test 構成 (fire/skip 含む) に拡張
