## 設計

- `src/ai/policies/mcts.ts` 新規 — `MCTSPolicy implements AIPolicy`
- choose() で各 candidate に対し:
  1. produce で move を state に apply
  2. `runMatch({ self/opp = HeuristicPolicy })` で gameResult まで rollout
  3. score: byPlayer 勝利=+1 / 敗北=-1 / draw=0、N 回平均最大の candidate を返却
- optional method (chooseGuard / chooseHiramekiTrigger 等) は内部 HeuristicPolicy へ delegate
- default: rollouts=10, rolloutMaxTurns=30

## 重要な観測: MVP MCTS は HeuristicPolicy より弱い

100 戦結果で MCTS が劣勢になった原因分析:

1. **rollout の variance dominates signal**: 5 rollouts × N candidates の統計ノイズが
   HeuristicPolicy の hand-crafted 判断品質を凌駕できない
2. **1-ply の構造的限界**: MCTS は move 単位で評価するため、turn 内 move 列の sequencing が
   HeuristicPolicy 全体の判断より浅い
3. **rollout policy 自体が HeuristicPolicy**: 評価対象と評価器の同質性が signal を弱める

**結論**: MVP は MCTSPolicy class / rollout 基盤 / delegate pattern を投入したが、
**AI 強度自体は HeuristicPolicy 未満**。strength tuning は Phase 9-F.2 で別途扱う。
