1. **Immer `produce` で wrap** — engine actions は in-place mutator (void 戻り) のため
   Zustand の change detection を効かせるべく Immer の `produce` で新参照を作る。
   AI orchestrator (`src/ai/policy.ts`) と同じパターン。
2. **`runAllUntilEmpty` を produce 内で呼ぶ** — Phase 5 listener が
   `reasoning:before-add` 等で pendingEffects に積んだ effect を即時解決する。
   AI 側と運用を統一。
3. **`isAllowed` 前段ガード** — engine の throw を待たずに hook 層で
   canX 判定し、UI フレンドリーな `{ ok:false, reason:'not-allowed' }` を返す。
4. **import スタイル**: `import * as flow` を採用 — `vi.spyOn(flow, 'doReasoning')`
   が同じ namespace 経由でなければ機能しないため、test と実装で揃える必要があった。
5. **endTurn canX**: engine 側 predicate なし → manual check
   (`turn.player === player && turn.phase === 'main'`) で同等のガード。

## Task 8.2 `useTargetPicker` (同セッション続き)

Q8 クリック+確認 UX の基盤 hook を land。target picker は推理 / アクション宣言 /
宣言能力 / アシスト等で共通利用する基盤。

### 成果物 (8.2)

- `src/ui/hooks/useTargetPicker.ts` (138 行)
  - `PickerPhase` 3-state ステートマシン: idle / picking / confirming
  - 別 Zustand store `useTargetPickerStore` (engine state とは分離、複数 component が
    subscribe するため global)
  - imperative API: start / pick / confirm / cancel / isCandidate
  - Promise + state ハイブリッド: start() は Promise<string|null> 返却、UI 側は
    `useTargetPickerStore((s) => s.phase)` で再描画 subscribe
- `tests/ui/hooks/useTargetPicker.test.ts` (190 行、17 tests)
  - 初期 idle / start→picking / 0 候補スキップ / pick→confirming /
    pick 非候補 no-op / confirm resolve / cancel from picking|confirming /
    idle中 no-op×3 / 再 start 旧 Promise 破棄 / isCandidate 各 phase

### 設計判断 (8.2)

1. **subscribe-free 関数群**: `useTargetPicker()` 自体は `useTargetPickerStore((s)=>...)`
   を呼ばず `getState()` のみ使用。これにより React レンダラ無しテストから直接呼べる。
   Component で再描画 subscribe したい場合は `useTargetPickerStore` を別途 import。
2. **0 候補 → 即 null resolve**: rules/17 §「〜まで」の「0枚を選択可能」を反映。
3. **再 start() で旧 Promise を null resolve**: UI で picking 中に別アクションを
   選び直した場合の自然な挙動。テストで明示的に検証。
4. **pick(uid) で非候補 → no-op**: UI 側に明示エラーは出さない (誤クリック耐性)。
