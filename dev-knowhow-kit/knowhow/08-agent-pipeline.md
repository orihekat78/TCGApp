# 08. マルチエージェント・バッチパイプライン

大量の均質バックログ（conan では カード 2049 枚）を、エージェント判断と決定的スクリプトの
分業で安全に量産するパイプライン。全体は一方向ファネル:

```
①survey/粗分類 → ②certify（精査） → ③adversarial verify → ④決定的 validate
→ ⑤決定的 codegen + register → ⑥バッチ回帰ゲート → ⑦wave 統計記録
```

## 代表クラスタリング + クローン展開（1 回認証 → N 件適用）

- バックログ全件を **テキスト完全一致** でグループ化。distinct 1 件だけ精査し、
  残りメンバーは ID 差し替えで複製（2049 件 → 661 distinct に圧縮）
- ⚠ 実敗例: 抽象化シグネチャ（色/枚数を捨象）でクローンしかけて誤実装未遂。
  **クローン適用は「実テキスト完全一致」のグループに限る**。メンバー個別の原文を必ず再取得
- 完了判定は「出力ファイルの存在」のみ（進捗 DB を作らない）→ 中断・部分失敗・再実行が
  追加の状態管理なしで成立（実際に rate-limit で全滅した日も翌日同じコマンドで再開できた）

## certify → adversarial verify の 2 段審査

- **certify**: 仕様の全 clause を能力にマッピングし、JSON Schema 強制で
  `verdict(green|yellow) / clauseMap[{clause, mapsTo, grounding}] / blocker` を返す。
  **grounding（実際に開いた実例ファイル or コア実装の引用）を required にする** のが肝
- **verify**: green のみ第二エージェントが「この green を反証せよ」の逆インセンティブで検証。
  fatal 1 件で不採用
- **判定原則の非対称性を明文化**: false green（誤採用）は false yellow（見落とし）より
  はるかに有害。疑わしければ yellow がデフォルト
- verify プロンプトには過去バグから抽出した「狩りどころカタログ」（filter 値取り違え・
  フック取り違え等）を与える

## 決定的バリデータ（語彙のホワイトリスト照合）

- エージェント出力 JSON を、コアと同期したホワイトリスト（許可 verb / 禁止 verb / フック /
  条件 / フィールド）に対し再帰 walk で照合。未知キー・closure 混入を codegen 前に exit 1
- **動機**: LLM は「もっともらしいが存在しない引数キー」を生成し、コアはそれを黙って無視する
  （silent no-op）。Schema 強制は形しか守れない。語彙の正しさはこの層で守る
- ホワイトリストには同期元をコメント明記（`// src/.../effect.ts AtomVerb と同期`）。
  同期ずれ自体を月次 audit の点検対象に

## 決定的 codegen + 冪等 register

- エージェントに任せるのは **判断が要る部分（マッピング）だけ**。メタデータ転記・ファイル形式・
  import 配線は決定的スクリプトに任せる → 転記 typo が構造的に消える
- 手書き規約の「原型ファイル」を先に 1 枚確定させ、codegen はそれを忠実に再現
- 生成ヘッダに原文 + マッピング + 根拠を埋める（レビューがファイル単体で完結）
- register は「無ければ挿入、有ればスキップ」の冪等設計 + dry-run デフォルト（--write 明示）

## brief.md — エージェント共通教科書（知識をプロンプトから分離）

- プロンプトは短く（項目データ + 出力契約 +「まずこの 2 ファイルを読め」）、
  ドメイン知識は単一 brief ファイルに集約: 一次情報源の優先順位 / 出力スキーマ /
  検証済みレシピ集（実証元ファイル名つき）/ ⛔ゲート一覧 / 判定原則
- wave 完了ごとに settled したパターン・新発見ゲートを brief に追記 → 全エージェントが賢くなる
- 人間が手動実装する時も同じ brief を読めばよい（dual-use）。git で知識の変遷が追える

## 運用ノウハウ

- ステージ間は **ファイル渡しのみ**（メモリ渡し禁止）→ どこからでも再開可能
- 並列度は実測で制御（16 並列で throttle 発生 → サブバッチ 8 件直列に）
- 1 件の失敗は null で続行、集計に returned/total を出して取りこぼし可視化
- バッチ回帰ゲート: 個別 green でも組合せで落ちる → typecheck / lint / full test /
  長時間ランダム実行 / E2E を「全 green でなければ commit しない」
- 進捗は単一カウンタ（ALL_CARDS 等）で表現 → ユーザーとの「今回 +N 件」合意が明確

## 移植のしかた

1. バックログを 1 つの機械可読カタログ（TSV/JSON）にする
2. 粗分類は可能な限り決定的スクリプトで行い、エージェントは曖昧域だけに使う
3. SCHEMA（verdict / clauseMap / grounding を required）と brief.md を用意
4. validate → codegen → register を npm script 化し、回帰ゲートを規約化
