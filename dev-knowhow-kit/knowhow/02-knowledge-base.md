# 02. 外部一次資料のナレッジベース化（rules/ パターン）

権威ある外部資料（公式ルール / API 仕様 / 法規制 / RFC / 社内規程）を
LLM が決定的に参照できるローカル抜粋に変換するパターン。

## 構成

```
.claude/rules/
├── INDEX.md          # 原典の章立て順の目次 + 参照原則 + 取得日 + 残課題
├── sources.md        # 出典台帳（URL・バージョン・取得日・再フェッチポリシー）
├── 01-<topic>.md     # トピック別抜粋（各 ≤100 行）
├── ...
├── 2X-qa-<topic>.md  # 二次情報源（公式 Q&A 裁定等）は番号帯を分離
└── errata.md         # 原典側の訂正・改版差分の記録
```

## トピック別抜粋ファイルの書き方

- **1 ファイル = 1 トピック、≤100 行**（LLM が該当トピックだけコンテキストに乗せられるサイズ）
- 冒頭に出典ページ/セクション番号、末尾に `## 関連` で相互リンク
- 表を多用し散文を避ける。`⚠` で実装者が踏みやすい罠を強調
- 原文の丸写しはせず **要約のみ** 保存（著作権配慮。sources.md に明記）
- **初回抜粋後に必ず原文と突合する再検証パスを 1 回入れる**
  - 実績: 再検証で漏れ 3 件発見（LP≤0 の挙動・一方通行遷移・下限なし）。漏れは必ずある前提

## INDEX.md の要点

- ファイル番号順ではなく **原典の章立て順** に目次を再配列（読み順を誤らせない）
- 「参照原則」: 情報源の優先順位を明記（一次 = 公式 docs、二次 = 公式フォーラム回答、三次 = 補助のみ）
- 「残課題」: まだ抜粋していない領域を列挙 → 「知らないことを知っている」状態を維持（推測補完の防止）

## sources.md の要点

- 表形式: 名称 / バージョン / URL / ローカル抽出パス（一次）、名称 / URL / 信頼度（二次・三次）
- 「取得・更新履歴」を日付 + 箇条書きで追記式に（監査結果も残す）
- 矛盾時の正本宣言を 1 行書く（例: エラッタ後を正とする / テキスト > 画像）
- 冒頭に再フェッチ指示: 「新規領域追加時はここから再取得して更新すること」

## 信頼度階層と Q&A 裁定の分離

- 基本ルール（一次資料準拠）とエッジケース裁定（公式 Q&A 等の二次）をファイル番号帯で分離
- 二次ファイルは冒頭 blockquote に出典 URL + 回答者の身元（公式メンテナか否か）
- 「Q: / A: 太字で結論 / 根拠引用」形式。不明点は削除せず **「仕様明示なし（要追加調査）」** と書き残す
- 一次と二次が矛盾したら機械的に一次優先

## 参照義務 + コード内引用コメント（3 層トレーサビリティ）

1. CLAUDE.md に規約化: 「ドメイン判断時は必ず INDEX.md から該当トピックを開く /
   推測で補完しない / 記述がなければ不明として扱いユーザー確認 or 原文再フェッチ」
2. 実装ファイル冒頭に参照コメント必須: `// rules: 11-reasoning.md §LP≤0`
   （API なら `// api-doc: stripe-webhooks.md §retry` 等に読み替え）
3. このコメントを正規表現抽出して逆引き索引（by-rule）を自動生成できる（→ knowhow/05 mapping）

コード行 ↔ 抜粋ファイル ↔ 原典ページの 3 層が往復可能になり、
「このルール解釈は正しいか」をレビューで機械的に検証できる。

## research/ — 調査と規約の分離

- 設計判断のための調査は `.claude/research/<topic>/` に番号付きファイル
  （01-overview → 02-分析 → 03-先例 → 04-recommendation★）
- 同名ハブ `<topic>.md` に目次 + 結論 1 行 + 「結論の運用への反映」リンク表
- 確定結論は CLAUDE.md に **結論 + research へのリンク 1 行だけ** 昇格
  （規約だけだと「なぜこの制約があるか」が失われ、後続セッションが制約を緩めてしまう）

## 移植手順

1. `.claude/rules/` を作成、一次資料をテキスト抽出（`.tmp/` に置く）
2. トピック単位に `NN-topic.md`（2 桁番号 + slug、各 ≤100 行）で分割
3. INDEX.md / sources.md を作成、CLAUDE.md に参照義務 3 点セットを書く
4. 再検証パス（原文と 1 章ずつ突合）を 1 回実施してから運用開始
